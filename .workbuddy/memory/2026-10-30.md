### 对 v1 的审核结论（7 事实 / 6 推导 / 7 矛盾 / 7 漏审）
- **移动单位**：v1 把"天"改"格"是方向错误。三11 是「预算点 + 地形按点消耗」，项目现状本身就是该模型，只需把"天"改名"移动力（MP）"。"格"会产生"林地 2 格/格"病句。
- **城距实测**（脚本算 `CITY_COORDS` 投影到 576×432）：119 条 `MAP_EDGES` 几何**中位 43.4 / 均值 54.6**，59 城**最近邻中位 22.2 / 均值 27.3**。v1 把均值当中位，据"55 格"断言行军偏慢。
- **最大漏审**：`MapEdge.cost` 注释"cost = 行军天数"，中位值 2，与网格 43 格差 19–21 倍；`council.ts` 用它算邻城威胁与战机 → AI 与玩家两套时钟。
- **图边连错城**：晋阳–襄平 249 格、邺–襄平 207、建宁–零陵 177、江州–长沙 148、襄平–北海 128（隔渤海）。
- **攻城**：许昌开局耐久 = (1200+80×6)=1680 上限 × 0.8 = **1344**（v1 用 1940 是建成城墙后的上限）；0.12 时 4.0 天破城；v1 的 0.04 打不出 2–3 旬（1680÷112=15 天）；正确值 **0.025**（→19.2 天 = 1.9 旬），配兵器 ×4 → 4.8 天。
- **v1 的假问题**：副将已实现（`SQUAD_DEPUTIES_MAX=2`）；两套格已在总表 §02 sec-note 声明；小路总表本就是 4–7。
- **数据三处不一致**：总表 §07 写 338 人（110/221/7），`generals.ts` 注释写 160，代码实测 **175（110/58/7）**，兵力 80,410（登场 51,560）。
- **水军不能走水路**：`marchCost.ts` 对所有兵种 `river/lake/sea = Infinity`，14 水城 / 16 渡口 / 水兵兵种空转。
- **无委任/军团**：59 城一旬一令，后期每旬约 40–60 次点击；三11 靠都督制压到 5–10 次。
- **诸葛亮 0 兵不是 bug**：应为「参军位」（三11 军师不单独出阵），不该塞兵。

### v2 给出的方案
- 单位：MP（每旬 10，地形 1/2/3 MP/格），兵种分档 10/14/14/8，`speed` 只留烽燧。
- 先修图再谈速度；新增 `scripts/check-map-edges.ts` 检测几何异常边（比值 >2.0 报警）。
- 攻城磨损 0.12 → 0.025；回血不动（432 万场沙盒已验证 1%）。
- 新增 §4 操作体验：委任/目标式行军/一括/情报前置/旬报，硬指标「中期 20 城每旬点击 ≤15，出征 ≤4」。
- 优先级：P0 = 修图 + 磨损 + MP 改名 + 委任；P1 = 兵器/水路/气力/适性/特技。
