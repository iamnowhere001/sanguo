## 地图引擎与工具选型评估（产出 docs/地图引擎与工具选型评估-v1.md）

- 基线实测：`src` 38,654 行 / 113 文件；`render` 7,357 行；`ui` 7,228 行；`tests` 7,770 行 / 45 文件。地图 576×432 = 248,832 格。
- 关键发现（都已写入文档，后续别重复挖）：
  - 地形分块 = 384 世界单位（32 格）× 1.5 px/单位 = **18 px/格**，LRU 32 块 ≈ 42 MB；720% 时放大 2.2×。
  - `MapCanvas` **无 rAF**；`BattleCanvas` 已有 fx 层 rAF 范式（`BattleCanvas.tsx:1669,1716`，30fps 节流 + reduced-motion）→ 地图层照搬即可。
  - `imageSmoothingEnabled = true` 与「新国风像素」冲突；缩放手感是连续 1.12 倍且锚定选中城池/屏幕中心，非光标；移动端无双指捏合。
  - **无任何版图/每格归属数据**（`territory|influence|tileOwner` 零命中），势力色只有城池径向光晕。
  - `perf:check` 明文不测浏览器 FPS（只测建局/AI月结/存档序列化）→ 无渲染基准。
- 选型结论：**不换引擎**。P0 补地基（渲染基准 / tileOwner 多源 Dijkstra 场 + d3-contour 边界 / 分层+rAF / 相机数学 / Tiled 资产管线）；P1 才考虑 PixiJS 8 只换 render 内核（@pixi/react 8.0.5 停更 2025-12、pixi-viewport 6.0.3 停更 2024-11，手写挂载）；P2 Phaser 4 `TilemapGPULayer` 仅在 P1 证伪后；Godot/Unity/Cocos/LayaAir/three/MapLibre 全部否决。
- 核对过的版本（2026-10-29）：pixi 8.22.0、phaser 4.2.1、three 0.186.1、@babylonjs/core 9.33.0、excalibur 0.32.0(BSD-2)、Godot 4.7.2、Unity 6000.6、Cocos 3.8.8、Tiled 1.12.x(GPL-2.0+ 编辑器 / TMX 规范 BSD)、LDtk 1.5.x(MIT)。

## 大地图左右栏改浮层（22:45）

需求：左右侧边栏改为悬浮在地图之上的浮层，覆盖地图而非占独立列；收起时地图不变。

实现（只动 3 个文件）：
- `src/styles/global.css`：`.game-grid` 从三列 grid 改成 `position: relative` 的单块舞台，`.map-main` 改为 `position:absolute; inset:0`（画布恒等于整块工作区）；`.game-grid > .side-panel` 绝对定位成悬浮卡片（12px 内缩、12px 圆角、双层投影、93% 半透明渐变）。收起用 `transform: translateX(±(100%+gap))` + `visibility` 延迟，不触发任何重排，`ResizeObserver` 不重算。
- 派生 CSS 变量 `--hud-inset-l/r`（浮层遮住的横向区间）与 `--hud-shift`：图例、缩放条、底部提示条、出征条、部队 HUD 按它让位并保持视觉居中。
- 浮层拉手 `.rail-toggle` 骑在卡片内缘（展开时 `gap + rail-l - 10px`，收起贴边 0），跟随卡片滑动。
- 战斗界面复用 `.side-panel`，所以绝对定位限定在 `.game-grid > .side-panel`，战斗栏不受影响。
- `MapCanvas.tsx`：图例改成 `.map-legends` 竖排容器（势力图例 + 地形图例），把左下角让给提示条——浮层挤压后地形图例与提示条原本会压字。
- `MapScreen.tsx`：`readRailCollapsed()` 在窄屏（≤900）无历史偏好时默认收起两侧浮层；≤720 展开一张自动收起另一张。

校验：`tsc` / `build` 通过，测试 439 例全通过；画布缓冲在展开/收起三态下恒为 3200×1682（1600×960@2x），地图构图不动。

## 出征派遣改造 · 规格（未实施）

需求：把「出征」从「指定攻击目标（敌城）」改为「派遣部队到指定格」，参照三国志11 大地图交互（点/拖选目的地、显示路线与可达范围、可途经点、可中途改令、确认前给目的地信息与行军预览）；兵种（步/骑/弓等）用不同图标。

诊断结论：**系统层已具备大半**，缺的是入口语义与 UI。
- 已有：`moveArmyTo`（逐格+行军令）、`advanceAlongPath`（跨旬续走）、`armyReach`/`armyPreviewPath`、`marchField`（地形/关门/城墙/占位阻挡）、`siegeTargetOf`+`assaultCity`（到达即围城、攻城另令）、`playArmyTurn` 旬推进。
- 缺：`sortieArmy` 强制 `targetCityId` 且必须是敌城；`routeForArmy` 对空地返回 null；`MapCanvas` 的 `attackSet` 只认城池命中，格子点不动；单击即 `SORTIE` 无确认；`drawArmyToken` 不分兵种。

方案（docs/出征派遣-v1.md）：
- 目标语义从「城」下沉为「格」：新增 `planDispatch(fromCity, dest)`、`resolveDispatchDest`（敌城 3×3 吸附到最近可用门外格）、`dispatchField`/`dispatchReachOf`（两档可达：本旬实色 / 后续虚线）、`sortieArmy` 加 `dest?` 重载。
- `Army.targetCityId` 变可选，新增 `dest`/`waypoints`，SAVE_VERSION 5→6。
- 交互：点「出征」→ 预览可达 → 单击锁定目的地 → 底部 `DispatchBar` 确认条（门/点将/行程/旬数/关防）→ 确认出征。双击同格跳过确认。
- 兵种徽记三档 LOD：r<6 色点、6–12 单字（步/骑/弓/水/极/玄）、≥12 矢量图徽；取主将兵种，混编在徽记下加小点。
- 两个必须点明的后果：① 堵门成本骤降（以往要出征到该城才能堵门）；② **当前没有行军遭遇战**，两军相邻不交战，只有同格互斥，所以"半路截击"实际只是挡路。
- 取舍：点敌城仍有效（吸附语义），AI 一行不改，抵达≠开战/四门封锁/每将月一调动全部保留。
- 改动量估算 ≈ +750 行 / 8 改 1 新 / 2–3 天。
- 未决：① 敌城是否可点 ② V1 是否做拖拽画路径（与 pan 手势冲突，建议不做）③ 堵门是否 V1 就限流。
