**一句话主线**：三11 的「守」不是数值堆出来的，是**三层冗余** ——
守将铺满让每座城都有人，兵力归城让城本身成为资源容器，耐久让城能「被打穿」而不是一击易主。
而「弃」是配套的：打不过要有体面的退路，否则玩家只会读档。

机制与数值不变，但看到「61」时要知道那是旧口径 —— 当前值一律查 [项目基线](../00-基线/项目基线.md) §2。

## 篇一 · 后勤与城池耐久：守将铺满、兵力归城、城能被打穿

> 起因是四条实机反馈：守将太少、兵力绑死在将领身上、城池没有「被打穿」的概念、调将可以一城接一城瞬间投送。

---

> 起因：四条来自实机的反馈 —— 城池守将太少、兵力绑死在将领身上、城池没有「被打穿」的概念、调将可以一城接一城瞬间投送。
> 本文记录这四项的设计裁决与落地位置，数值真值源仍在 `src/data/tables/balance.ts`。
> 计数口径：本文写作时为 61 城；阳平关 / 濡须口 转为关防后为 59 城，机制与数值不变。

### 1 · 守将铺满：338 名武将

**问题**：主表 174 人分摊到 59 城，平均不到 2 人；208 赤壁的曹操二十多座城，名将集中在几个大城，边缘小城常年 0 将 —— 内政、征兵、守城全部停摆。

**裁决**：人物表分两层。

| 层 | 文件 | 内容 |
| --- | --- | --- |
| 名将主表 | `data/tables/generals.ts` | 174 人，剧情锚点与主力，208 默认驻城 |
| 补位表 | `data/tables/generalsExtra.ts` | 164 人，按势力分组，默认 `inactive` |

建局时 `createGame` 调 `fillGarrisons`：按「缺将数从多到少」把本势力的补位将领摊进各城，直到每城达到 `BALANCE.GARRISON.MIN_GENERALS_PER_CITY`（=2）。

实测（四个剧本，59 座有主城池）：

| 剧本 | 登场武将 | 均 | 不足 2 将的城 |
| --- | --- | --- | --- |
| 189 董卓弄权 | 132 | 2.2 | 0 |
| 200 曹操崛起 | 134 | 2.2 | 0 |
| 208 赤壁 | 148 | 2.4 | 0 |
| 220 三国鼎立 | 124 | 2.0 | 0 |

**防呆**：`EXTRA_GENERALS` 与主表 id 冲突会被对象展开静默吞掉（主表条目直接消失），
因此在建表时就抛错；补位表内部的重复 id 同样在模块加载时抛错。

### 2 · 兵力属于城池

**问题**：`General.troops` 既是「驻军」又是「出征部队」，兵力无法集中、无法运输，征兵也被单将带兵上限卡死。

**裁决**：新增 `City.troops` = **未分配兵力池**。

```
城池总驻军 = City.troops（池） + Σ 在城武将 troops（已分配）
```

| 场景 | 行为 |
| --- | --- |
| 征兵 | 先补给执行武将，超出其带兵上限的部分进池；受城池驻军上限约束 |
| 批量征兵 | 按带兵缺口分给全城，余量进池 |
| 分配 | `ASSIGN_TROOPS`（单将，正数领兵 / 负数交回）、`ASSIGN_TROOPS_ALL`（全城） |
| 出征 | `createBattle` 先按武力从高到低从池里补满参战武将，再判「无兵可战」 |
| 守城 | 同上：目标城的池兵会由守将带上城墙 |
| 月粮 | 池兵同样吃粮，断粮时同样逃亡（堵住「把钱粮换成池兵」绕过后勤） |
| 无将城池 | 池兵随城溃散 —— 兵无将则散，不给「有兵无将」的城当刷兵容器 |

唯一真值源：`src/systems/troops.ts`（`troopCapOf` / `poolOf` / `topUpFromPool` / `projectedTroops` / `withdrawTroops`）。
`projectedTroops` 是「若现在分配，各将会带多少兵」的纯计算版，AI 评估与出征预览共用，保证**预览 = 实战**。

### 3 · 城际运输

`TRANSPORT { fromCityId, toCityId, gold, food, troops }`

| 约束 | 值 |
| --- | --- |
| 范围 | 相邻己方城池（与调将同一套邻接约束，不允许中转站） |
| 政令 | 现代模式 1 点（出发城），经典模式 0 |
| 单次兵力上限 | `BALANCE.GARRISON.transportMaxTroops` = 6000 |
| 目标驻军 | 不得使目标城超过规模上限 |
| 兵力来源 | 先扣池，不足部分由守将按兵力从小到大分兵 |

到达后兵力先进目标城池，再按带兵余量自动分给守将，剩余留在池里。

### 4 · 城池耐久

**问题**：原本只有「守军全灭」一条陷城路径，城墙只是个减伤数字，守方缩在城里硬顶时缺少明确出口。

**裁决**：`City.durability`，上限由纯函数给出：

```
上限 = base[规模] + 城防 × 6 + 城墙工程 260
      capital 1200 / large 900 / medium 650 / small 450
```

| 规则 | 值 / 位置 |
| --- | --- |
| 攻城磨损 | 攻方部队**站在城池格上**，每日 `troops × 0.12 × (1 + 武力/200)`（`battle/siege.ts`） |
| 城破判定 | `battleOutcome`：`cityDurability <= 0` → 攻方胜；与「驻守兵力为 0」并列 |
| 月结修复 | 有主城池每月回补上限的 12%（`logistics.runCityRepair`） |
| 城池易主 | 耐久回落到上限的 30% |
| 展示 | 城池面板「城墙耐久」进度条 + 属性条；战棋 HUD 城墙条 + 攻城提示 |

**为什么不是「攻方入城即胜」**：守方 8 个出生位里只有 4 个在城池格上，清掉城内守军后攻方才能站住，
此时城外残兵仍可反扑 —— 攻城变成一个「占住城内、顶着反扑磨墙」的独立阶段，而不是瞬间结算。

### 5 · 每月行军一次

**问题**：`doMoveGeneral` 只校验「相邻」，玩家可以 A→B→C→D 在同一回合内连续调将，
等于绕过整条补给线把部队瞬间投送到地图另一端。

**裁决**：`General.marchTurn` 记录最近一次行军回合，`marchTurn >= turn` 即本月不能再动。

- 调将、出征都计入（`createBattle` 成功后写 `marchTurn`）；
- AI 的 `applyStrategicMove` 走同一条约束；
- UI 在武将行显示「本月已行军」并隐藏调往下拉。

`BALANCE.GARRISON.movesPerTurn = 1` 保留为可调项。

## 篇二 · 外交与弃城：三态关系、战前弃城、守方撤退

> 本篇给「打不过」提供了三条出路：谈（外交）、弃（战前撤走）、逃（战棋内撤退）。三条都按攻方胜利结算，但保住了人和兵。

---

> 状态：**已实施**（2026-10-23）。
> 范围：`src/systems/factionDiplomacy.ts`、`src/systems/abandon.ts`、`src/systems/battle/setup.ts` / `resolve.ts`、`src/core/reducer.ts`、地图与战棋 UI。
> 回归：`tests/factionDiplomacy.spec.ts`（10）、`tests/abandon.spec.ts`（4）、`tests/battle.retreat.spec.ts`（7）、`tests/ui.smoke.spec.tsx`（新增 3 条）。

---

### 0. 结论

- **外交**：势力之间现在有战争 / 停战 / 同盟三种状态与 −100~100 的关系分。玩家可以送礼、停战、结盟、宣战；AI 会互相停战、被压制时向玩家求和；停战 / 同盟期内双方不能出兵，攻击候选与 `createBattle` 都会拦截。
- **战前弃城**：守不住的城可以整建制撤往相邻友城，城池交给最强的邻敌，粮草金钱各损失一半。玩家在城池面板操作，AI 在月度阶段自动判断。
- **守方撤退**：战棋内守方也能弃城撤退，按攻方胜利结算，但未溃散守军撤往友城保留 70%；主将需保住 25% 兵力才能突围。无守军城池被占领时，零兵守将也会撤走，不再留在敌城里。

### 1. 外交关系

#### 1.1 数据模型

```ts
type RelationState = 'war' | 'truce' | 'alliance';
interface FactionRelation {
  state: RelationState;
  score: number;          // -100..100
  untilTurn?: number;     // 停战 / 同盟到期（含）
  offeredAtTurn?: number; // 上次求和，避免每月骚扰
}
GameState.diplomacy = { relations: Record<'a|b', FactionRelation> }
GameState.pendingDiplomacy = { fromFactionId, kind, turn } | undefined
```

- 关系键按两个 faction id 排序后拼接，保证 `a|b` 与 `b|a` 同一条。
- 新开局 / 旧存档：`ensureDiplomacy` 补齐全员战争。
- 到期未续：`effectiveRelation` 按战争处理，`tickDiplomacy` 在每月 AI 阶段把状态改回 war 并 −5 关系。

#### 1.2 玩家行动

| 行动 | 费用 | 效果 | 条件 |
|---|---|---|---|
| 送礼 | 200 金 | 关系 +10 | 任意状态 |
| 停战 | 300 金 | 停战 12 回合，关系 +10 | 当前战争；AI 接受才生效 |
| 结盟 | 500 金 | 同盟 24 回合，关系 +20 | 需先停战、关系 ≥55；AI 接受才生效 |
| 宣战 | 0 | 立即战争，关系 −40；其它势力各 −5 | 当前停战 / 同盟 |

停战被接受的三条任一：

1. 关系 ≥15（两次送礼即可）；
2. AI 总兵力 < 玩家 75%（打不过）；
3. AI 实际接壤的敌对势力 ≥2，且兵力不超过玩家的 1.1 倍（多线压力，但碾压局不谈）。

结盟额外要求双方有共同敌人，或 AI 比玩家弱。被拒绝仍扣使者费用，并 −5 关系。

UI：地图顶栏「外交」打开势力列表，显示关系、剩余回合、态度分、兵力与四个行动。原城池面板的「外交」改名为「敌将」，只处理离间 / 招揽 / 策反，避免两个入口混淆。

#### 1.3 AI 外交

- **AI 互相停战**：当双方都不是最强势力、且主动方明显弱于对方时，主动方花 300 金签 12 回合停战。效果是弱国抱团，把压力转向最强势力（通常是玩家或曹操）。
- **向玩家求和**：AI 总兵力 < 玩家 55% 时，每隔 6 回合发一次停战请求，进入 `pendingDiplomacy`。玩家在地图上看到「停战请求」弹窗；接受即停战 12 回合，拒绝 −10 关系。
- **求和月不进攻玩家**：已经递出求和信的势力，本月攻击候选会跳过玩家目标，避免「一边求和一边捅刀」。
- **未回应的求和信 3 个月后作废**，防止 AI 永久等待。
- **攻击过滤**：`planAttackCandidates` 与 `planMassingMove` 跳过停战 / 同盟目标；`createBattle` 再做一次兜底，玩家手动出征也会被拒绝。
- **威胁判断**：`adjacentThreat` 只统计敌对邻国；盟友 / 停战邻居不再触发增援或弃城。
- **侧翼窗口**：`windowBonusFor` 的「多线受敌」只统计与守方敌对的第三方，盟友不算牵制。

#### 1.4 关系变化

| 事件 | 变化 |
|---|---|
| 送礼 | +10 |
| 停战达成 | +10 |
| 同盟达成 | +20 |
| 宣战 / 毁约 | −40（其它势力 −5） |
| 停战 / 同盟到期 | −5 |

| 求和被拒 | −10 |

### 2. 战前弃城

#### 2.1 规则

`canAbandonCity` 的前置条件：

1. 大地图阶段、己方城池；
2. 不是最后一城（弃最后一城 = 亡国）；
3. 相邻有敌对势力（没有威胁就不需要弃城）；
4. 城里有可撤退的守将（含 0 兵守将）；
5. 相邻友城的空位装得下全部守军（整建制撤退，不做分批）。

执行 `abandonCity`：

- 所有 active 守将移到相邻友城（优先空位最多的）；
- 城池交给**最强的相邻敌对势力**（按该城驻军排序）；没有敌对邻国时才会变成无主（前置条件通常已排除）；
- 城中粮草、金钱各损失 `BALANCE.ABANDON_SCORCH_RATE = 50%`；
- 玩家弃城会记录 `recordCityLost`，并检查游戏结束与章节进度；
- 日志：「X 弃守 Y，N 将退往 Z，W 进驻」。

#### 2.2 玩家入口

城池面板底栏新增「弃城撤退」：

- 不满足条件时禁用，tooltip 说明原因（最后一城 / 无相邻敌军 / 友城容不下 / 非己方城池）；
- 满足时弹出确认框，写明撤退目的地、接手的势力、辎重损失比例；
- 确认后立即执行，不发生战斗。

#### 2.3 AI 判断

`planAbandonment` 每月评估一次：

```
threat = 最强相邻敌军的驻军
ratio  = easy 3.0 / normal 2.5 / hard 2.2
若 threat > defense × ratio（或 defense = 0），且能找到目的地 → 弃城
```

- 每月最多弃一城；
- 君主在城内也会一起撤走，保存势力核心；
- 弃城发生在增援 / 出兵之前：先保人，再谈反击；
- 如果 AI 刚和威胁方签了停战，`adjacentThreat` 不再计入，自然就不会弃城——外交可以救城。

### 3. 战棋内守方撤退

- 战棋顶栏的「撤退」按钮现在对攻守双方都显示；守方文案为「弃城撤退」。
- 守方点击后，reducer 走 `resolveBattle(s, b, 'victory')`：按攻方胜利结算，城池归攻方，但未溃散守军撤往相邻友城，保留 70%。
- 确认框会显示撤退目的地；没有相邻友城时明确警告「守军将被俘」。
- 主将只有兵力 ≥ 出战兵力 25% 才能突围；残兵主将仍会被俘。
- 已经溃散的守军不撤退。
- 无守军城池被 `captureUndefended` 占领时，城里的零兵守将也会撤往友城；无路才 inactive，不再出现「0 兵守将留在敌城」的脏状态。

- **同盟不自动参战**：目前同盟只保证互不攻击，盟友不会在你被进攻时自动对敌宣战，也不会派兵支援。
- **AI 不主动结盟**：AI 之间只签停战，不签同盟；玩家可以主动与 AI 结盟。
- **没有战争疲劳 / 关系自然漂移**：关系只随事件变化，不会因长期和平自然回暖。
- **弃城不能选接手指向**：城池固定交给最强邻敌，玩家不能选择「交给盟友」或「留空城」。
- **守方撤退没有断后战**：撤退即弃城，不能打一场掩护战再走。
