# 项目基线 v1 · 数据与需求台账

> **状态：当前有效。** 这是**台账**，不是规格。规格讲「为什么这样设计」，本文只钉「现在是什么」。
>
> - 数据基线由 `npm run baseline:doc` 从代码生成，**不要手改标记区**。
> - 校验：`npm run baseline:check`（已并入 `npm run verify`）——代码改了没重生成、文档写了过期数字，都会红。
> - 机器可读副本：[项目基线-v1.json](项目基线-v1.json)。

## 0. 三条使用规则

1. **引用数字先查本文 §2。** 任何文档要写「59 城」「47 关防」「SAVE_VERSION 6」，从本文抄；查不到就补进来，不许另开一份。
2. **改了代码就重生成。** 配表 / 版本号 / 缩放档位一变，同一次提交里跑 `npm run baseline:doc`，否则 `verify` 会挡住。
3. **新文档要登记。** 没有在 §1 登记「管什么、不管什么」的文档，不算真值源，只能当讨论稿。

## 3. 需求基线（关键契约）

只列「改了就算破坏兼容」的条目。每条都能在代码里指到唯一位置。

| # | 契约 | 真值源 | 钉住它的测试 |
| --- | --- | --- | --- |
| R1 | 一回合 = **一旬**，3 旬 = 1 月；跨月才做月度结算 | `systems/economy.ts` `advanceTime` | `economy` / `report` |
| R2 | 每支部队每旬 **1 个动作**（移动不占动作），判据 `actedXun === xunTurn` | `systems/combat/action.ts` | `siege.map.spec` |
| R3 | 行军预算按兵种：步 / 弓 / 水 10 MP，骑 / 极 14，玄 8 | `systems/army.ts` `MARCH_MP_BY_CLASS` | `army` |

| R5 | 关防通行线 **1 格宽、4 邻接**；线外山水不可通行 | `render/gateGrid.ts` | `gates` |

## 6. 维护流程

```bash
npm run baseline:doc     # 代码 → 本文 §2 + 项目基线-v1.json
npm run baseline:check   # 校验：代码 vs 基线 vs 文档断言
npm run verify           # 完整门禁（含 baseline:check）
```

`baseline:check` 做三件事：

1. **代码 → JSON**：`collectFacts()` 与 `docs/项目基线-v1.json` 必须一致（改了配表没重生成 = 红）。
2. **JSON → 本文 §2**：生成块必须与 JSON 一致（手改了生成块 = 红）。
3. **文档断言**：README / 规格 / 迭代计划里的关键数字必须命中当前值，且不得残留已废止的旧值。
