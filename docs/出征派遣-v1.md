# 出征派遣 v1 · 从「指定攻击目标」改为「行军到目的地」

> **状态：已实施（2026-10-29）。** 上游：[全地图规格 v3](全地图规格-v3.md)。
> 本文只改**出征入口的目标语义**，不改战斗、不改 AI、不改围城规则。
> 实施结果与偏差见 §10。

## 0. 结论先行

| 诉求 | 落地方式 | 落点 |

**一句话取舍**：把「目标」从**城**换成**格**，城只是格的一种吸附语义。旧操作（点敌城 = 去围它）仍然成立，只是不再叫"选择目标"，叫"目的地吸附"。

## 2. 交互规格

### 2.1 模式与状态

```
[城池面板] 点「出征」
        ↓
┌─ 派遣模式 dispatch: { fromCityId, dest: GridPoint|null, plan: DispatchPlan|null } ─┐
│  ① 选点：鼠标移动 → 实时可达高亮 + 目的地浮标                              │
│  ② 预览：hover 格 → 金色虚线路径 + 箭头 + 行程浮标                          │
│  ③ 锁定：单击某格 → dest 锁定，底部 DispatchBar 展开详情                    │
│  ④ 确认：点「确认出征」或双击同格 → SORTIE(dest) → 退出派遣模式            │
└───────────────────────────────────────────────────────────────────────────┘
Esc / 右键 / 「取消」 → 退出派遣模式，不消耗任何资源
```

### 2.2 可达范围的**两档**语义（关键设计）

三国志 11 的目的地**不受本旬移动力限制**：可以下令去 10 旬外的城，部队每旬走 10 天。现有 `moveArmyTo` 已经是这个行为，UI 必须诚实地画出两档：

| 档位 | 判定 | 视觉 | 含义 |
| --- | --- | --- | --- |
| 本旬可达 | `dist ≤ armyMp` | 淡琥珀填充 `rgba(255,248,226,.30)` + 琥珀边界实线 | 下令当旬就能站到 |
| 后续可达 | `dist > armyMp` 且 `Number.isFinite(dist)` | 无填充，仅 `rgba(184,134,48,.45)` 虚线边界 | 成立行军令，每旬续走 |
| 不可达 | `dist === Infinity` | 无标记；hover 显示 ✕ 与原因 | 山岭水域 / 敌关封锁 / 城墙壁垒 / 敌方占位 |

> 复用 `MapCanvas` 现有的边界描边算法（`MapCanvas.tsx:1682`），只需把它从「只吃 `selectedArmy`」改为「吃一个 `reach` 集合 + 一种样式」。

### 2.3 目的地吸附规则

| 点到的东西 | 解析结果 | 信息条文案 |
| --- | --- | --- |
| 敌城 3×3 城郭 / 城心 | 吸附到该城**最近的可用门外格**，`siegeCityId` 置位 | 「襄阳 城下（东门）· 抵达后可围城，攻城需另下令」 |
| 己方城 3×3 | 吸附到最近可用门外格（= 回防/换防） | 「新野 城下（南门）· 抵达后自动入城」 |
| 关门 / 渡口所在格 | 保留该格为目的地 | 「潼关 · 过关 +2 日」 |
| 普通可通行格 | 该格 | 「平原 · 距此 12 日」 |
| 山岭 / 水域 / 城墙角 | 非法，禁止落点 | 「山岭不可通行」「城墙壁垒，须走城门」 |
| 已被他军占据 | 非法 | 「该格已有部队」 |
| 己方兵所在格 | 非法 | 同上 |

**这就是与旧逻辑的接缝**：点敌城仍然"点得动"，但语义从"指定攻击目标"变成"目的地吸附到城下"。玩家不用重新学，系统内部却统一成"到点"。

### 2.4 确认条（`DispatchBar`）

底部中央，覆盖 `.march-banner` 的位置（派遣模式下隐藏原 `.map-hint`，避免叠字）：

```
┌──────────────────────────────────────────────────────────────────────────┐
│ 出征 · 新野                                                              │
│ 自 东门 出城 · 张飞、关羽、赵云 率 4,820 兵（步 2 · 骑 1）      [取消] [确认出征] │
│ 目的地 襄阳城下（东门） · 平原 · 全程 18 日 · 约 2 旬 · 本旬走 10 日，余 8 日续行 │
│ 经 汉阳渡（渡水口，接战为水战）                                          │
└──────────────────────────────────────────────────────────────────────────┘
```

字段来源：
- 门 / 兵种构成 / 兵力：`planDispatch` + `pickSortieGenerals`
- 全程日数：`plan.days`（除以 `speed` 后取整，与现有 `log` 一致）
- 旬数：`Math.ceil(days / (MARCH_DAYS_PER_XUN * speed))`
- 关防：`gateSummaryOf(path)` 的 `waterCrossing`

### 2.5 中途改令

选中在途部队 → 点任意格 → 走 `MOVE_ARMY`（**已实现，不改**）。补两条 UI：

1. 选中部队的 HUD 增加「改令」状态标；点到新格时提示「改令 · 本旬余 X 日」。
2. 野地待命的部队 HUD 显示「待命（野外）· 无围城目标」。

### 2.6 途经点（V1.5，非 V1）

- `Shift + 点击` 追加途经点，路径按段拼接：`A→W1`、`W1→W2`、`W2→Dest`，各段独立寻路。
- `Ctrl+Z` / 右键撤销最后一个途经点。
- 数据：`Army.waypoints?: GridPoint[]`（仅供绘制拐点与「途经 N 处」文案；真实路径已烘焙进 `path`）。
- 被阻挡时部队停在当前格，途经点作废，需重新下令（与现状一致）。

### 2.7 拖拽选点（V1.5，**建议 V1 不做**）

拖拽与现有地图平移手势冲突：`onPointerDown` 已经用于 pan + 双指捏合 + 惯性甩动（`MapCanvas.tsx:2279`）。若在派遣模式把左键拖拽改为"画路径"，玩家最容易犯的错就是**想拖地图结果画了一条线**。V1 先做「单击选点 + 双击确认」，等点击手感稳定后再评估。

## 3. 与原有目标选择逻辑的取舍

| 维度 | 旧：指定攻击目标 | 新：派遣到目的地 | 取舍判断 |
| --- | --- | --- | --- |
| 心智模型 | "打谁" | "去哪" | ✅ 新模型**兼容**旧操作（点城=吸附城下） |
| 操作步数 | 2 步 | 3 步（点格→确认） | ⚠️ +1 步；用「双击同格直接出征」补偿 |
| 可表达意图 | 只能攻城 | 攻城 / 堵门 / 守关 / 佯动 / 半路占位 | ✅ 这是主要收益 |
| 部队字段 | `targetCityId` 必填 | `dest` 必填，`targetCityId` 可空 | ⚠️ 存档迁移 |
| 到达敌城门外 | 围城，不自动开战 | **完全一致** | ✅ 不动 |
| 攻城 | 显式 `ASSAULT` | **完全一致** | ✅ 不动 |
| 四门被堵不能出城 | 有 | **完全一致** | ✅ 不动 |
| AI | `sortieArmy(from, targetCity)` | **一行不改**（内部走同一函数） | ✅ 零回归 |
| 自动点将 | `pickSortieGenerals` | **不变**，确认条里可见名单 | ✅ 不动 |
| 「可出征 N 城」计数 | CityPanel 按钮 + 顶栏 | 改为「可派遣」，计数逻辑保留但不作为 disabled 唯一条件 | ⚠️ 需改 disabled 判定 |

### 明确保留（不因"派遣化"而变）

1. **抵达 ≠ 开战**：站在敌城门外是围城，攻城是独立下令。
2. **城墙不可穿越**：只有城主能进城，敌军只能停门外。
3. **敌对关防封锁整条线**：须先攻关，不可绕行。
4. **一格一军**：敌我同格互斥。
5. **每将每月一次调动**（`g.marchTurn`）。
6. **编队 `squads`**：出征即编队，主将+最多 2 副将。

### 明确删除

1. 「出征 · 选择目标（55）」的目标计数作为**唯一入口条件** → 改为「有可达格即可出征」。
2. `attackSet` 作为"唯一可点集合" → 改为"吸附目标集合"，格子本身也可点。

## 5. 部队行动状态机

```
        出征(dest)
 驻城 ──────────────→ 行军令(path≠[], mp>0)
  │                      │  本旬移动力耗尽 / 结束回合
  │                      ↓
  │                    续行(path≠[], mp=0) ──下旬──→ 行军令
  │                      │  走完全程
  │                      ↓
  │              ┌───────┴────────┐
  │              ↓                ↓
  │        围城(敌城门外)      待命(任意格)
  │              │ 攻城            │ 改令 / 入城(己方城心)
  │              ↓                ↓
  │           战棋           行军令 / 驻城
  └──────────────────────────────┘
```

### 新增 / 变化的点

| 点 | 变化 | 影响 |
| --- | --- | --- |
| `待命` 可以在地图任意格 | **新能力** | 堵门、守关、半路占位成为可行战术 |
| 野地待命不吃月结 | `runSiegeAttrition` 只看四门 `blockedBy`，不看野地 | ✅ 无副作用 |
| 入城 | 只有站到己方**城心**才 `mergeArmy` | ✅ 不变 |
| 战败撤退 | `retreatCityFor(fromCityId)`，`fromCityId` = 最近经过的己方城 | ✅ 不变，野地部队也有落脚点 |
| `armyEtaXun` | 读 `path`，与目的地语义无关 | ✅ 不变 |

### 两个必须点明的后果

1. **堵门成本骤降。** 以前要"出征到某城"才能堵它门，现在可以随便派一队去堵任何城门。四门全堵月结掉 5% 兵 + 民忠 −2（`SIEGE_DESERTION`）会变得容易被利用。建议 V1 先观察，若过强再加限制（例如堵门需 ≥1000 兵，或守军可"突围"造成双方损伤）。
2. **没有行军遭遇战。** 两军相邻不交战，只有"同格互斥"阻挡。所以"半路截击"目前只是**挡路**，不是**交战**。加遭遇战属于 V2 议题，本次不做——但文案不要写成"截击"，写"阻路"。

## 6. 兵种图标规格

### 6.1 兵种来源

`General.unitClass`（`infantry | cavalry | archer | navy | elite | mystic`）已存在，`UNIT_CLASS_LABEL` 已有中文名。部队是多将编队，取：

- **主将兵种** = `squads` 的第一个 key 对应武将的 `unitClass`（无 `squads` 时取 `generalIds[0]`）。
- **混编提示** = 其余武将中不同兵种，最多取 2 个，在徽记下方画 3px 小点。

### 6.2 徽记设计（墨线，跟随纸/墨/琥珀调）

| 兵种 | 图徽（r ≥ 12） | 低缩放汉字 |
| --- | --- | --- |
| 步兵 | 圆角盾面 + 中脊竖线 | 步 |
| 骑兵 | 马首侧影（鬃毛 + 双耳） | 骑 |
| 弓兵 | 弓弧 + 弦 + 一支箭 | 弓 |
| 水兵 | 帆 + 桨 | 水 |
| 极兵 | 双戟交叉 | 极 |
| 玄兵 | 三爻卦线 | 玄 |

描线色统一 `rgba(58,48,30,0.85)`（与现有枪旗一致），**不用高饱和兵种色**——势力色已占用描边，再加一套彩色会破坏纸墨调性。

### 6.3 三档 LOD

| 棋子半径 | 绘制 | 理由 |
| --- | --- | --- |
| `r < 6`（≈ 缩放 < 40%） | 棋子内部染成兵种色（势力色环保留） | 此尺寸任何字形都糊，只能靠色相 |
| `6 ≤ r < 12`（40%–150%） | 单汉字，`700 ${r}px` | 汉字在中间缩放最易读，也符合系列传统 |
| `r ≥ 12`（> 150%） | 矢量图徽，`lineWidth ≈ r * 0.09` | 近景要质感 |

低饱和兵种色（`r<6` 的芯色）：步 `#6b7a8f`、骑 `#a8563c`、弓 `#4e7f5b`、水 `#3f6f8f`、极 `#8a6a2f`、玄 `#6b4a7a`。

### 6.4 与现有元素的不冲突检查

| 元素 | 位置 | 冲突？ |
| --- | --- | --- |
| 兵力小牌 | 棋子下方 `py + r*1.05` | 徽记在圆心，不冲突 |
| 名称牌 | 棋子上方 `py - r*1.9` | 不冲突 |
| 移动力圆点 | 选中时左上 `px - r*1.1` | 与兵种色点**同位置** → 色点移到右上 `px + r*1.1` |
| 选中虚线圈 | `r*1.55` | 不冲突 |

### 10.2 三处与规格不同

1. **目的地文案改用地理参照。** 规格里写的是「(x,y) 野地」，实测像调试输出；
   改为 `plainDestLabel()`：取最近城池 + 方位 + 格数，例如「江夏东南 16 格」「襄阳 城下」。
   日志、确认条、「在途部队」列表共用同一函数。
2. **删掉了旧的「出征路线」绘制。** 原来地图上会画 8 条通往敌城的红色虚线（`marchFrom` 时转金色）。
   目的地不再是城之后，这些线既不代表可选目标、又容易被误读成作战计划，连同城池的「可出征」描边一起移除；
   可达范围改由派遣模式的两档高亮表达。
3. **可达高亮加了「浅晕 + 深琥珀」双描边。** 单层 `rgba(184,134,48,.85)` 1.2px 在羊皮纸底色的平原上几乎看不见，
   实测后改为 3.4px 暖白晕 + 1.7px 深琥珀，两档各自成套。

### 10.3 性能

`armyFieldOf` 让选中部队的可达范围与悬停预览共用一次全图 Dijkstra；
派遣模式同理（`dispatchField` 只在进入模式时算一次）。
修掉了原先「每次 pointermove 重跑一遍 24.8 万格 Dijkstra」的隐患。

`beyond` 圈只铺 3 旬（`DISPATCH_HINT_XUN`）：更远的格仍然可点，但不再点亮——
整块大陆全亮既不可读，也要在每次重绘时描几万条边。
