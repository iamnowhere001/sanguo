## 0. 结论先行

| 用户诉求 | 落地方式 | 关键位置 |
| --- | --- | --- |
| 大地图全面优化，参考三国志 11 | 城郭 3×3 砖石城墙 + 四门 + 角楼 + 官署；部队为圆形棋子；移动力范围用琥珀边界线 | `render/MapCanvas.tsx` |
| 部队一个一个地移动，像战棋小地图 | 每旬 10 天移动力，点一格走一格；点远处则留下"行军令"逐旬续走 | `systems/army.ts` `moveArmyTo` |
| 城池占 9 格、4 门、堵门不能出城 | 3×3 = 9 格城墙，四边中点各一门；门外格被敌军占据 = 该门被封 | `render/terrainGrid.ts` `systems/cityGrid.ts` |
| 城池被攻占前，敌方不能进城 | 城墙 9 格只对城主开放；敌军只能停在门外 | `cityGrid.tilePassableFor` |

**战斗形态没变**：仍是切 12×8 战棋。评估文档的判断（裁切战场性价比最高）继续沿用，
本档不碰 `systems/battle/*`，只在 `createBattle` 上加了一个 `skipAdjacency` 开关。

## 1. 城池占地：3×3 + 四门

```
        ┌───┬───┬───┐
        │   │ ▲ │   │   ▲ = 北门（门楼在墙外）
        ├───┼───┼───┤
        │ ◀ │ 官 │ ▶ │   ◀ ▶ = 东西门
        ├───┼───┼───┤
        │   │ ▼ │   │   ▼ = 南门
        └───┴───┴───┘
   门外格在四边再外一格：出城列阵 / 围城落位
```

| 概念 | 含义 | 代码 |
| --- | --- | --- |
| 城心 | 3×3 的中心，`cityAnchors()` 返回的格 | `CityBlock.col/row` |
| 城墙 | 9 格，含四座门 | `CityBlock.tiles` |
| 城门 | 四边中点的城墙格（渲染为门洞 + 门楼） | `CityBlock.gateTiles` |
| 门外格 | 门再外一格，任何势力都能站 | `CityBlock.approaches` |
| 封死门 | 门外格压着邻城城墙，开不出去 | `CityBlock.sealed` |

### 落位冲突怎么解决

61 座城在 96×72 的地图上按真实经纬度落点，中原 / 江东有几处挤到放不下 3×3。
`cityBlocks()` 的解法是**打分选位**：

```
候选得分 = 与地理落点的距离 + 封死门数 × 3
```

- 优先"原地封一门"，而不是"外推五格"——濡须口若被推到建业以东，地理上完全错了；
- 结果：51 城偏移 ≤1 格，9 城偏移 2–3 格，1 城（濡须口）5 格；**封死门 0 座**；
- 每城至少 1 座可走陆门（30 城四门全通，2 城只剩 1 门——都是长江沿岸的水城）。

### 门为什么可能不可用

| 情况 | 判定 | 结果 |
| --- | --- | --- |
| 门外是水域（江陵南门对着长江） | `marchDaysOfTile(approach) === Infinity` | 陆军出不去，画作「－」 |
| 门外压着邻城城墙 | `sealed` | 同上 |
| 门外站着敌军 | `armyAtTile(approach).factionId !== 城主` | 画作「✕」，此门被封 |

## 2. 通行规则：三层，缺一不可

1. **城墙只认城主** —— 这是「城池被攻占前，敌方部队不能进入城池」的落点。
   注意城门格也算城墙：敌军不能"站在门洞里"。
2. **四角是实心墙体** —— 谁都走不了。少了这一条，寻路会从墙角"翻墙"出去，城门形同虚设
   （实现时踩过：第一版路径直接从 (20,38) 的角格穿出，四门完全没起作用）。
3. **一格只站一支部队** —— 占位即阻挡，这也是"堵门"能成立的前提。

出城路径因此必然是「城心 → 某座门 → 门外格」。`routeForArmy()` 把这条路径裁掉城内段，
部队直接出生在门外格上：**城内不摆棋子**，城墙只画势力旗。

## 3. 逐格调度：移动力而不是"每旬自动走完"

| 项 | 取值 |
| --- | --- |
| 每旬移动力 | `MARCH_DAYS_PER_XUN = 10` 天（地形按天计费：平原 1 / 林地丘陵 2 / 沼泽 3） |
| 手动移动 | `MOVE_ARMY` → `moveArmyTo()`，扣掉实际天数 |
| 走不到怎么办 | 保留 `path` 作为"行军令"，`END_TURN` 时按剩余移动力续走 |
| 移动力刷新 | `playArmyTurn()` 收尾时把所有部队补满 |
| 走到己方城心 | 自动解散入城（武将回城，纵队移除） |

界面上：点部队 → 高亮本旬可达范围（琥珀边界线）→ 点格子行军；悬停显示路径预览。
范围用**边界线**而不是整片填色，因为 10 天移动力在平原上能覆盖 150+ 格，整片填色会糊住地形。

## 4. 围城：站着不打，打要下令

这是与 M 档最大的手感差异。M 档是"抵达即开战"，本档拆成两步：

1. **抵达敌城门外 = 围城**（`siegeTargetOf`）。不开战、不弹窗，只在地图上挂一面「围」旗；
2. **下令攻城 = 开战**（`ASSAULT` → `assaultCity()`）。部队必须正站在目标城门外。

为什么必须拆开：如果抵达即战，围城方永远没机会"堵着门不打"，
「堵门让守军出不来」这条规则就永远不会被触发。

### 围城的收益

只堵门没有收益，玩家就不会去做。所以月结加了一条（`runSiegeAttrition`）：

> 四面陆门全被敌军堵死 → 守军逃散 5%，民忠 −2。

## 5. 战略 AI：从"凭空开战"改成"派兵上路"

M 档的 AI 是 `createBattle()` 直接开打，玩家看不到任何过程。本档改成：

- **AI 打玩家** → `sortieArmy(factionId)` 派一支纵队上路，走到城下才自动攻城；
- **AI 打 AI** → 仍是 `autoResolveBattle()` 瞬时结算（61 城规模下不值得为旁观战争付性能）。

代价与收益：

| | 变化 |
| --- | --- |
| 收益 | 玩家看得见威胁、来得及堵门 / 增援；"全地图"终于有了空间感 |
| 代价 | AI 月结不再因玩家防守战中断（`runAiFaction` 常返 `done`），
  防守战改在玩家 `END_TURN` 的 `playArmyTurn` 里触发 |
| 兜底 | `sortieArmy` 失败（四门被堵 / 无路线）时退回旧的瞬时开战 |

`tests/ai.spec.ts` 与 `tests/difficulty.spec.ts` 相应改为"先有纵队、再推到城下开战"。

## 6. 渲染：三国志 11 式的城郭

| 层 | 做法 |
| --- | --- |
| 城墙 | 亮米色墙面 + 墨线勾边 + 下沿深色"厚度"；女墙垛口沿上沿一排小方块 |
| 四角 | 敌楼（塔基 + 四坡顶 + 势力旗） |
| 四门 | 门洞（圆拱）+ 门楼（歇山檐）；门楼朝**外**——西门的檐指 −x，东门指 +x（旋转方向踩过坑） |
| 城内 | 地坪按势力色淡染 + 官署（歇山顶）+ 两间厢房 |
| 部队 | 圆形棋子（纸底 + 势力色描边 + 枪旗符号），下方兵力牌，选中显示移动力 |
| 封门 | 门上打朱砂斜杠 |

**分级绘制**：屏幕上一格 < 5.5px 不画门、< 8px 不画垛口、< 9px 不画角楼、< 10px 不画官署。
全图 100% 缩放时城郭约 20px，只剩"城墙轮廓 + 势力色"，靠描边与落影保证可辨认。

| 项 | 归属 |
| --- | --- |
| 战场从大地图裁切 | 仍是 12×8 固定战场（评估文档 §5 难点 5 的 M 档方案未实施） |

## 9. 已知取舍

1. **濡须口被推到建业以东 5 格**。这是 3×3 占地与真实地理的直接冲突，
   在 96×72 的格网下无解；若要修正，只能手工微调 `CITY_COORDS` 里那一带的经纬度。
2. **河流仍不可通行**。长江沿岸城市之间只能走陆路绕行，江陵 / 公安一线尤其明显。
   水战与渡口通行属于 L 档后续（`GATES` 里已经有渡口数据，只是没接进寻路）。
3. **AI 只有"打玩家"才派兵**。AI 互攻仍是瞬时结算，所以地图上的纵队基本只朝玩家来。
   要让全图都"看得见部队"，得把 AI 互攻也改成行军——那是战略 AI 重写（评估文档难点 7）。
4. **没有野战**。两支部队只能互相挡路，不能开打。这是本档最大的一块缺口：
   它让"半路截击"只能靠堵地形实现。
5. **AI 到城下就攻城，不停下来围**。所以"城门被堵"对玩家的实际压力只有一瞬
   （AI 抵达当旬即开战）。规则本身是双向对称的：玩家围 AI 的城，AI 守军确实出不来，
   月结也确实逃散——只是 AI 本来就不出城迎战，这一条对它的可感度低于对玩家。
   要让围城成为真正的攻防拉锯，得先有野战（部队 vs 部队），否则"解围"无从谈起。
