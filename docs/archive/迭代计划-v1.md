## 0. 结论先行

1. 报告里的 M0（垂直切片）已经完成，M1 / M2 / M4 主体也已提前落地；不需要从 M0 重跑。
2. 真正阻塞后续工作的只剩两类**地基问题**：战斗真值表（E04）与确定性工程（E14）。它们决定数据结构，必须先于内容与打磨。
3. 因此把剩余工作重排为 **I1–I5**：先补 A 层真值 → 再做 B 层校准与信息层 → 最后接 C 层开关与验收。每个迭代有独立准出，不达标不进入下一个。

- 森林隐蔽落地：弓兵在森林被远程攻击时伤害 ×0.8；贴脸近战不触发，目标预览标注“森林隐蔽 −20%”。

## 8. 贯穿轨道与工程纪律

以下四件事从 I1 起每个迭代都做，不单独排期：

1. **数值沙盒与回归**：每次调参后跑 `sim:battle` / `sim:economy`，对比 CSV，不靠手感。
2. **事件日志与回放**：结算关键分支必须写 log；固定种子可回放。
3. **月报与可归因 UI**：新增结算规则时同步补月报解释，避免“有结果没原因”。
4. **存档迁移测试**：任何状态字段变更都带迁移函数与夹具。

**工程纪律**（沿用现有约定）：

- 先 `balance.ts` 常量 → 再 `formulas.ts` 纯函数 → 再写断言 → 最后接 UI。
- 模拟器只能复用规则纯函数，禁止复制一份实现。
- 平衡参数带 `【GDD】/【优化】/【推导】` 标注，新增值必须标注来源。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 切换相性 / 地形表打破现有样例与手感 | 战斗结果整体漂移 | 先写新表断言，再重算旧样例；保留旧值快照做前后对比 |
| 随机数分流改动存档结构 | 旧档不可读 | 升版本 + 迁移链 + 旧档夹具；迁移失败给明确提示 |
| 税率 3.0 与报告 1.2 冲突 | 经济手感走偏 | 以 `sim:economy` 三路线差距为准裁决，回写 `balance.ts` 与文档 |
| 模拟器与实机两套实现 | 调参失效 | 共用纯函数，代码评审把“复制公式”列为阻塞项 |
| 搜索随机化削弱记忆点 | 情怀流失 | 保留“经典点位”开关；随机化只作用于新开局 |
| 月报信息过载 | 玩家点跳过 | 三层折叠，默认只显示结论 |
| 极兵削弱过度 | 转职失去吸引力 | 用“突破”定位补偿：对城防与阵型有额外破防值 |
| 范围蔓延 | 迭代无法收口 | C 层默认关闭；非目标见 §11 |
