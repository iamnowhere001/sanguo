# 大地图布局迭代优化计划 · v1

> 上游：[全地图规格 v3](../02-系统/地图.md)（地图真值源）、[关隘有效性体检 v1](../02-系统/地图.md)（问题诊断）。
> 本文是**施工计划**：先把问题量化清楚，再定目标、拆阶段、写验收，最后才动代码。

## 0. 决策摘要

采用**混合方案**，不押注单一路径：

| 层面 | 做法 | 为什么不能只做这一层 |
| --- | --- | --- |
| 地理数据 | 校准 `CITY_COORDS` / `GATES.anchor`，补全缺失锚点 | 锚点错了，后面所有地形工程都建在错误位置 |
| 山脉 | 让 `RIDGES` 端点互相咬合，主要山系连成连续屏障 | 单纯加宽会把城挤死；单纯挪关卡救不了地形（已验证） |
| 河流 | `RIVERS` 端点入海或接入山体，消除"可绕源头" | 江能绕，渡口就永远不是必经点 |
| 关隘 | 凿出真正 1 格宽山口，**中心必须是山地 / 丘陵** | 只凿不封 → 旁边能绕；只封不凿 → 切断地图 |
| 渡口 | 落在真实两岸，成对封锁有效 | 单侧渡口没有意义 |
| 规则 | 必要时补 ZOC（控制范围）兜底 | 纯地形方案在个别节点会切断地图 |

**不动的口径**：576×432 栅格、`MAP_VERSION = 3`、`SAVE_VERSION`、59 城、31 处关港小路。
存档兼容优先于布局理想化。

## 1. 当前问题与量化证据

数据来源：`npm run map:gates`、`scripts/diag-gates.ts`、`scripts/_audit-map.ts`、`scripts/_audit-routes.ts`。

### 1.1 硬失败：14 项落位不合格

`npm run map:gates` 当前 **14 项失败**，全部是同一类：

```
潼关、函谷关、武关、散关、壶关、井陉关、阳平关、剑阁、
葭萌关、祁山堡、瓦口关、子午谷、轘辕道、阴平道
→ 中心落在 plain，不是山口
```

**原因**：`carveCorridors()` 把山谷凿成了 `plain`。这是上一轮"凿谷"实验的直接后果 ——
谷确实通了（关卡真的卡在谷上），但把关口本身也凿成了平原，违反"关隘中心必须是山地 / 丘陵"的规格。

这是**最优先要修的**：它让验收门禁直接变红。

### 1.6 陆军连通性：大江大河没有分割地图

未写 `anchor` 的关港按"道路中点"落位，结果偏离史实：

- 潼关落在约 109.36°E（真实约 110.25°E）
- 函谷关、虎牢关、白马津、延津、夏口、赤壁、白帝同样有偏移

## 2. 设计目标

按优先级排序，每条都可量化验收。

| # | 目标 | 验收口径 |
| --- | --- | --- |
| G1 | 关隘中心必须落在山地 / 丘陵 | `map:gates` 0 失败 |
| G2 | 关隘封锁要真的挡住路 | 12 座里 ≥10 座绕行 ≥60 MP |
| G3 | 港口成对封锁要挡住江 | 7 对里 ≥5 对 Δ ≥40 MP |
| G4 | 关港要参与路网 | 31 处里 ≥25 处被最短路使用 ≥1 次 |
| G5 | 地图不能被切断 | 59 城全连通，0 条邻接边不可达 |
| G6 | 大江大河要分割地图 | 不含渡口时，陆路连通分量 ≥3（长江以南 / 以北 / 汉中巴蜀至少分开） |
| G7 | 城池不能贴脸 | 最小城距 ≥12 格，中位 ≤46 格 |
| G8 | 地貌可读 | 山岭占比 4%–12%，山地+丘陵 >12%；截图人工确认 |
| G9 | 不破坏既有口径 | 576×432、`MAP_VERSION=3`、59 城、31 关港、`npm run verify` 全绿 |

> **G6 与 G5 的张力**：G6 要求河是墙，G5 要求城全连通。解法是"河是墙、渡口是门"——
> 连通性由渡口提供，而不是靠河岸的陆地缺口。

## 3. 分阶段实施

每阶段结束都必须 `npm run map:gates && npm test`，不允许带着红门禁进入下一阶段。

### P0 · 基线修复与验收工具（1–2 天）

**红队结论：没有可用的验收工具，后面每一步都是盲改。所以 P0 先造尺子，再修东西。**

#### P0.1 修 `map:gates` 的 14 项失败

**问题**：`carveCorridors()` 把山口凿成 `plain`。

**做法**：

1. `carveCorridors()` 凿谷时把**中心段保留为 `hill`**，只有谷的两端（连接平原的部分）凿成 `plain`。
   - 谷底用 `hill` 不影响通行（2 MP/格），但满足"中心必须是山地/丘陵"。
2. `siteFromCorridor()` 的 `center` 强制落在 `hill` 格上（若中点恰好是 `plain`，向谷内找最近的 `hill`）。
3. 复跑 `map:gates`，确认 14 项清零。

**风险**：谷底从 `plain` 变 `hill`，行军变贵（2 MP/格），可能让关隘封锁效果变化 ——
P0 结束后必须重跑 `diag-gates.ts` 记录新基线。

#### P0.2 修 `stats`：现在测的不是真实地形

**问题**：`carveCorridors()` 直接改 `terrainGrid().cells`，但 `stats` 只在生成时算一次
（`terrainGrid.ts:315`）。所以 `map.spec.ts` 的山岭占比读的是**生成时快照**，
凿谷与封山的增量永远测不到 —— A9 这条验收等于失效。

**做法**：凿谷 / 封山结束后重算 `stats`（或提供 `refreshTerrainStats()`，由 `gateSites()` 调用）。

**验收**：改完后 `stats.mountain + stats.hill` 与逐格统计一致（写一个断言）。

#### P0.3 写"禁用渡口的陆路连通分量"脚本（A7 的唯一实现）

**问题**：`_audit-routes.ts:83` 无条件放行渡口跳跃，没有"不含渡口"模式；
`check-map-edges.ts:15` 检查的是抽象邻接图，不是地形。**两条现有工具都测不出地形上的孤岛。**

**做法**：新增 `scripts/audit-connectivity.ts`：

- 从每座城的门外格出发做陆路 BFS，**不松弛 `ferryHopFrom` 的跳跃边**；
- 输出：连通分量数、每个分量的城池清单、不可达的邻接边；
- 纳入 `npm run map:audit`。

**验收**：先跑出基线（预计武都单独成一个分量），作为 G5/G6 的起点数据。

#### P0.4 武都专项：它现在就是孤岛

**问题**：`wudu → tianshui` / `wudu → hanzhong` / `wudu → miandu` 三条邻接边**全部 ∞**。
祁山堡的 `edges` 只覆盖 `tianshui-hanzhong`（`gates.ts:218`），
而 `carveCorridors()` 只为 `gate.edges[0]` 凿谷（`gateGrid.ts:383`）——
**武都从来没有过谷道**。原计划 P2 的"大巴山↔米仓山↔龙门山咬合"正好压在武都周边，
会让它更孤。

**做法**（二选一，先诊断再定）：

1. 给武都补一条走廊（新增一条 `edges: [['wudu','tianshui']]` 的小路或关隘）——
   但会动 31 处关港的硬编码计数，**需要同步改测试**；
2. 把阴平道的 `anchor` 挪到武都—绵竹连线上（阴平道本就是"武都—江油"的捷径），
   不动数量，只改落位。**优先这条。**

**验收**：`audit-connectivity` 里武都归入主分量，三条邻接边不再 ∞。

#### P0.5 修 `cityBlocks()` 的静默回退

**问题**：`terrainGrid.ts:489` 的 `footprintCost` 只要求"4 个门外格中至少 1 格陆地"，
不保证那格能通到外面；搜索失败后 `terrainGrid.ts:548` 回退到 `nearestLandTile`，
**只避水、不避山，也不校验 3×3**，会静默产出非法城，直到 `map.spec.ts:97` 才报错。
加宽山河后这种情况会变多。

**做法**：把静默回退改为**抛错并打印城池 id 与候选评分**，让问题在生成时就暴露。

**回退**：本阶段改动集中在 `gateGrid.ts` / `terrainGrid.ts` / 新增一个脚本，git 可单独回滚。

### P1 · 地理校准：锚点与城池坐标（1–2 天）

**问题**：7 处关港无锚点或锚点偏移；8 对城池过近。

**做法**：

1. 给全部 12 关隘 + 3 小路 + 16 港口补 `anchor`（真实经纬度）。
   - 潼关 `[110.25, 34.60]`、函谷关 `[110.90, 34.63]`、虎牢关 `[113.20, 34.85]`、武关 `[111.00, 33.72]`（已有）…
   - 港口按真实渡口：孟津 `[112.42, 34.83]`、白马津 `[114.55, 35.30]`、夏口 `[114.28, 30.55]`…
2. 修正 `CITY_COORDS` 里 8 对过近的城，向真实经纬度回正（每次 ≤2 格，避免连锁影响城墙落位）。
3. 每改一处跑 `map:check`（城池 3×3 不压水/山）与 `map:edges`（边距中位、连通）。

**验收**：`map:gates` 仍 0 失败；`map:edges` 通过；最小城距 ≥12。

**风险**：挪城会连锁影响 `cityBlocks()` 评分、AI 邻接、援军路径。**一次只动 1–2 座，逐次验证。**

### P2 · 山脉连成屏障（2–3 天）

**问题**：`RIDGES` 多为细长条带，端点在平原中断开 → 关隘两侧可绕。

**做法**：

1. 对每座关隘，检查"谷的两侧 20 格内是否有可通行走廊"（用 `diag-gates.ts` 的 ASCII 剖面 + `landDetour`）。
2. 有走廊 → 延长或加宽对应 `RIDGES` 折线，让端点咬合到相邻山系。
   - 秦岭东端 ↔ 伏牛山西端（已咬合，但宽度不足）
   - 太行山 ↔ 王屋 / 中条
   - 大巴山 ↔ 米仓山 ↔ 龙门山
3. **只调 `width` / `points`，不加新山脉** —— 理由不是"怕超 12%"（实测山岭 4.8%，
   余量 7.2 个百分点；12 处各加 5 格半宽 × 40 格长 ≈ 2,400 格 ≈ 1 个百分点，翻倍也只有 7%），
   而是**怕压缩城池落位空间**：3×3 城墙不能压山，加宽会把城挤到别处。
4. 每加一处，跑 `map:check`（山岭占比）+ `diag-gates`（该关绕行）+ `audit-connectivity`（连通性）。

**验收**：G2（≥10 座绕行 ≥60）、G8（山岭占比 4–12%，**须在 P0.2 修完 stats 之后才可信**）、
G5（0 条不可达）。

**风险**：加宽会压缩城池落位空间。**必须先跑 `map:check` 再提交。**

### P3 · 河流成为真实分割线（2–3 天）

**问题**：59 城陆路全连通，渡口不是必经点。

**做法**：

1. 检查 `RIVERS` 每条河的端点：是否入海、是否接山。
   - 长江 / 黄河 / 汉水 / 淮河的源头若在内陆平原，延长到山体或海域。
2. 收窄"可涉水段"：`riverHalfWidth` 在非渡口处保持 ≥6 格，消除窄到能绕的段落。
3. **5 处汇流段不得加宽**：江夏、江陵、公安、柴桑、寿春。
   这些城的城心真实坐标本来就贴着江（江夏 `[114.3,30.55]` 距长江 `[114.3,30.6]` 仅 1 行，
   而干流半宽约 3.5 行），目前全靠 `cityBlocks()` 半径 16 的搜索推到岸上；
   再加宽就会挤死，且 `gates.spec.ts:121` 要求滩头非水。
4. **先量化再改**：跑一次"江夏→襄阳"当前步数（`gates.spec.ts:164-166` 要求 <200），
   把断言阈值改为"当前值 × 1.15"，避免加宽后硬红。
5. 跑 `audit-connectivity.ts`（P0.3 新增），目标陆路连通分量 ≥3。

**验收**：G6（陆路连通分量 ≥3）、G3（港口成对封锁 ≥5 对有效）、G4（≥25 处被使用）、
`gates.spec.ts` 江夏→襄阳断言仍绿。

**风险**：**最容易切断地图**。每改一条河必须跑 `audit-connectivity`（不是 `map:edges` ——
后者只查抽象邻接图，测不出地形孤岛）。若某城被河围死，补渡口或回退该段。

### P4 · 关隘与港口的最终落位（1–2 天）

**做法**：

1. 重跑 `carveCorridors()`：确认每条谷都是"山外 → 山口 → 山外"的完整通道。
2. 谷两侧封山范围按 P2 结果重新调参（当前 2–6 格）。
3. 港口按 P3 的河岸重新落位，成对港口用 `pairId` 斜向错开 ≥0.25°。
4. 必要时补 **ZOC**（兜底，预计 ≤2 座关隘）。**必须收窄，否则会自己炸掉地图**：
   - 只封 **lane 两端向外 1 格**，不封整圈 —— 封整圈会封掉关隘自己的 `approach`，
     甚至封掉某城唯一的陆门（A6 直接红）；
   - **不作用于城墙格**；
   - **对已经在范围内的部队豁免**（否则部队进圈后无法移动，永久卡死）；
   - 实现走 `army.ts` 已有的 `extraBlocked`（`army.ts:370` / `396`），
     **不要塞进 `marchGrid` 缓存** —— 那个缓存只按 `unitClass` 分键（`army.ts:233`），
     faction 相关的 ZOC 放进去会串味。

**验收**：G1–G4 全部达标，且 A6（0 条不可达）仍绿。

### P5 · 验收与表现（1 天）

1. `npm run verify`（typecheck + test + map:check + map:gates + map:edges + contrast + build）。
2. 重拍截图：30% 全图、100% 州郡、200% 默认、600% 潼关山道、600% 夏口渡。
3. 人工确认：山道可读、渡口在两岸、关隘图标在山口里。
4. 更新 `docs/全地图规格-v3.md` 的 §1.1 与 §7 验收表。

## 6. 风险与回退

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| **切断地图** | 某城不可达，AI 卡死 | 每改一次跑 `audit-connectivity`（P0.3）；P3 每改一条河单独验证 |
| 山岭占比超标 | `tests/map.spec.ts` 红 | 只加宽不加新山脉；每加一处跑 `map:check`；先修 stats |
| 城池被山河挤死 | 3×3 城墙压水/山，四门全封 | `cityBlocks()` 兜底改为抛错（P0.5）；5 处汇流段禁改（P3） |
| 关港仍然可绕 | G2/G3 不达标 | P4 用**收窄版** ZOC 兜底（≤2 座），不封整圈 |
| **老档部队停在新生山河里** | 读档后部队在不可通行格 | `MAP_VERSION` 固定为 3，`migrate.ts:77` 只在 `mapVersion < MAP_VERSION` 时重吸附 —— **这段逻辑对本次改动不生效**。需新增 `terrainVersion` 字段，读档时对 `army.at` 做一次 `nearestLandTile` 吸附 |
| 测试硬编码 31 | 增删关港会红 | 本轮**不增删**；武都专项优先用"挪阴平道 anchor"而非新增关隘 |
| 性能退化 | 凿谷 + 封山增加冷启动 | 当前冷启动 4.9s（含 vite-node 编译），地形生成 <600ms；P4 后复测 `perf:check` |

**回退策略**：每个阶段一个 commit，`git revert` 单阶段不影响其他阶段。
`geography.ts` 的改动集中在数据段（`RIDGES` / `RIVERS` / `CITY_COORDS`），可单独回滚。

## 7. 不做的事

明确排除，避免范围蔓延：

1. **不改栅格尺寸**（576×432）、不改 `MAP_VERSION`、不改 `SAVE_VERSION`。
2. **不增删城池与关港**（59 城 / 31 关港保持，测试硬编码依赖）。

4. **不引入独立道路图层**：行军仍是逐格走，不在底图画驿道线（规格 §5.3 已定）。
5. **不做完整 ZOC 系统**：只在 P4 对个别无效关隘做局部兜底。

## 9. 审查记录

### 9.1 红队审查（2026-10-30）

**整体判断：需修订后可行。**

最大的漏洞不是地形方案，而是**验收工具不存在或测错对象** —— A7 没有实现、
A9 读的是生成时快照、`map:edges` 只看抽象邻接图不看地形。原计划等于"没有仪表盘就上路"。

| # | 红队结论 | 证据 | 本版修订 |
| --- | --- | --- | --- |
| 1 | **切断地图：会炸** | 武都三条邻接边无任何关隘覆盖（`scenarios.ts:52-53`），`carveCorridors` 只为 `gate.edges[0]` 凿谷（`gateGrid.ts:383`）；P2 的"大巴山↔米仓山咬合"压在武都周边会更糟 | 新增 **P0.4 武都专项**；A7 改为必须新写脚本 |
| 2 | 山岭占比：没问题，但担忧点错位 | 实测山岭 4.8%，上限 12%，余量 7.2 个百分点；12 处加宽约 2,400 格 ≈ 1 个百分点 | P2 第 3 条理由从"怕超 12%"改为"怕压缩城池落位" |
| 3 | **城池被挤死：会炸（局部）** | 江夏城心距长江仅 1 行、干流半宽约 3.5 行；`footprintCost` 只要求 4 门有 1 格陆地（`terrainGrid.ts:489`），兜底 `nearestLandTile` 只避水不避山（`:548`），会静默产出非法城 | P3 新增"5 处汇流段禁改"；新增 **P0.5 兜底改抛错** |
