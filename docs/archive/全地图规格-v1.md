## 1. 阶段 0 · 四个裁决

评估文档要求阶段 0 先钉死四个会决定实现参数的决策。S 档只涉及其中两个，另两个顺延。

| 决策项 | 评估建议 | S 档裁决 | 理由 |
| --- | --- | --- | --- |
| 回合粒度 | 旬（3 回合/月） | **保持月回合** | 旬回合的唯一动因是"行军要跨回合"。S 档没有行军过程，改回合会牵动内政 / 经济 / 月报 / 章节四处，纯亏 |
| 网格类型 | 方形 4 邻 | **方形 4 邻** | 与战棋 `MOVE_COST` / ZOC 同构；将来 M 档可 100% 复用；手机端点选精度最好 |
| 战斗形态 | 裁切战场 | **仍切 12×8 场景** | S 档不碰战斗。裁切是 M 档阶段 3 的事 |
| 旧存档 | 放弃 | **不放弃** | S 档是纯表现层：`City.x/y` 仍存在，存档结构不变，`SAVE_VERSION` 不升 |

**顺延说明**：回合粒度与"旧存档放弃"都是 M 档的前置决策，等部队上地图时再裁决。
本档刻意不提前付出这部分成本。

## 2. 地图规格

| 项 | 取值 | 位置 |
| --- | --- | --- |
| 栅格 | 96 列 × 72 行，每格 12 世界单位（世界 1152 × 864） | `geography.MAP` |
| 经纬窗口 | 99.0–124.5°E，20.5–42.5°N | `geography.LON_RANGE / LAT_RANGE` |
| 投影 | 等距圆柱（经纬度线性映射） | `geography.projectLonLat()` |
| 地形枚举 | 海 / 湖 / 河 / 沼泽 / 平原 / 林地 / 丘陵 / 山地 / 荒漠（9 类） | `terrainGrid.TILE_KINDS` |
| 栅格存储 | `Uint8Array`（6912 字节） | `terrainGrid.terrainGrid()` |
| 城市落位 | 61 城经纬度 → 格 → 最近陆地格吸附 | `geography.CITY_COORDS` |

**为什么投影不做墨卡托校正**：该窗口在中纬度（约 32°N）的横纵比约 1.15，
真实值 1/cos(32°) ≈ 1.18，误差 2.5%，肉眼不可辨。等距圆柱换来的是"改窗口只改两个常量"。

**为什么地形存 `Uint8Array` 而不是对象数组**：评估文档难点 2 的结论。
虽然 S 档地形不进 `structuredClone`（它是静态配表、只缓存不落盘），但先把数据结构定成
`Uint8Array` + 纯函数读取，M 档接通行性 / 寻路时不用重构。

## 3. 地形从哪来：控制点，不是手绘

评估文档把"地图编辑器"列为 P0，理由是 5,000+ 格无法手绘维护。本档没有做编辑器，
而是把维护对象从**格子**换成**控制点**：

| 数据 | 数量 | 形式 |
| --- | --- | --- |
| 海岸线 | 54 个折点 | 经纬度折线，闭合到图外框 |
| 河流 | 7 条 / 约 90 个折点 | 经纬度折线 + 相对宽度 |
| 湖泊 | 5 个 | 中心 + 经纬半径 |
| 山脉 | 20 条 / 约 50 个折点 | 经纬度折线 + 半宽 + 高度 |
| 荒漠 / 林地 / 沼泽 | 4 / 8 / 3 个 | 中心 + 半径 + 形状扰动 |

合计约 250 个数，比 6,912 个格子少两个数量级，而且**改一个折点就能让整条河改道**。
栅格由 `terrainGrid.classify()` 按优先级（海 > 湖 > 河 > 山地 > 荒漠 > 丘陵 > 林地 > 沼泽 > 平原）确定性生成，
不含任何随机流，因此同一份配表永远得到同一张图 —— 这是"读档 100% 复现"的延伸要求。

**编辑 / 检查通道**：`npm run map:check` 打印 ASCII 地图、地形分布与落位校验，
`-- --json` 导出 `reports/map-grid.json`（逐格字符 + 城池落点），可用外部工具查看或比对。

> 这是对评估文档的一处**有意偏离**，理由写在这里而不是藏在代码里：
> 编辑器适合"人工绘制的地图"，本档是"程序化生成的地图"，先做编辑器等于先给一个不存在的
> 工作流造工具。若将来地形要手工微调（比如加关隘、改河床），再补编辑器不迟。

## 4. 城市落位

`CITY_COORDS` 给 61 座城填了对应的现代位置，`cityAnchors()` 依次做三件事：

1. 经纬度 → 格坐标（四舍五入）；
2. 若落在海 / 湖 / 河里，螺旋搜索最近的非水域格；
3. 若该格已被占用，按固定顺序向外找最近空格。

结果（`npm run map:check` 实测）：**61 城全部有落点，0 项落水，0 项重叠**。

`City.x/y` **保留**（schema 要求、旧存档兼容），但地图层不再读它：
`cityWorldPos(city)` 优先取地理落点，缺失时退回 `x/y`。这样旧存档里的城也不会飞。

**已知代价**：真实地理会让中原城池明显变密（洛阳 / 陈留 / 许昌 / 小沛 / 彭城 相距 3–5 格）。
旧版手写坐标是"为可读性摊开"的，新版是"为地理准确压缩"的。取舍是：**准确优先**，
拥挤由标签碰撞隐藏 + 缩放（滚轮 / 双指 / 城池列表跳转）解决。

## 5. 渲染分层

| 层 | 内容 | 实现 |
| --- | --- | --- |
| 海 | 渐变 + 26 条极淡波纹 | 每帧重画（成本可忽略） |
| 陆地 / 地形 | 海岸线闭合路径 + 荒漠/林地/沼泽径向渐变 + 山脊三层描边 + 山峰符号 + 3200 点颗粒 | **离屏缓存**，2× 分辨率，整张只画一次 |
| 水系 | 湖泊椭圆 + 河流（支流先画、干流压上）+ 海岸线 | 与地形同层，进缓存 |
| 战略网格 | 随缩放的 44px 方格 | 每帧 |
| 道路 / 出征线 | 虚线（沿用旧逻辑） | 每帧 |
| 城池 / 标签 / tooltip | 沿用旧逻辑，只把坐标来源换成世界坐标 | 每帧 |

**性能取舍**：地形是静态的，但鼠标悬停会触发重绘。若每帧重画 6,912 格或 20 条山脊，
悬停会明显掉帧；因此把整张地形画到离屏画布，每帧只做一次 `drawImage`。
实测（Chrome，1440×900，61 城）悬停无卡顿。

**画幅**：世界矩形固定，不再像旧版按"61 城包围盒"自适应。
好处是换剧本时海岸线不会跟着缩放；代价是城池只占画幅约 75%，比旧版略小 —— 用缩放补。

## 6. 明确不做什么（S 档边界）

| 项 | 归属 |
| --- | --- |
| 部队实体、行军、ZOC、补给 | M 档（阶段 2） |
| 战场从大地图裁切 | M 档（阶段 3） |
| 设施、迷雾、关隘、水战 | L 档（阶段 5） |
| 地形影响规则（通行性 / 战力修正 / 粮耗） | M 档。本档地形**纯表现**，`isPassable()` 已就位但无人调用 |
| 回合粒度改旬 | M 档阶段 0 再议 |

`terrainGrid.isPassable()` / `worldToTile()` / `tileKindAt()` 是为 M 档预留的接口，
现在只有落位校验与调试工具在用 —— 保持"零规则依赖"是 S 档可回退的前提。

## 8. 下一步（M 档的接口预留）

已经就位、等 M 档接的东西：

1. `terrainGrid.isPassable(col,row)` —— 通行性判定；
2. `terrainGrid.worldToTile / tileCenter` —— 格 ↔ 世界坐标；
3. `terrainGrid.cityAnchors()` —— 城池占据的格（将来是 footprint 的种子）；
4. `TILE_KINDS` 的 9 类地形 —— 可直接映射到 `MOVE_COST` 扩展。

还缺的（M 档阶段 2 再做）：A\* 寻路、部队实体、`General.locationId` + `armyId` 拆分、
战场裁切。这些都不该在 S 档提前做 —— 评估文档的判断是对的：**S 档的价值是验证观感，
不是提前还技术债**。
