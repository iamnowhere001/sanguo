## 0. 结论先行

1. **v1 已完成，不再作为排期依据。** I1–I5 的规则、确定性、经济、战棋、开局长线与工程验收都已交付；当前版本已跑在 576×432 全图战斗上。
2. **第一批工作不是加功能，而是重钉验收口径。** 5 项既有失败测试、全图时代的性能基线、启动烘焙成本都还没有结论；口径不定，“达标”无法证明。
3. **功能缺口只剩三块**：地图表现与资产（P0-4、染色/墨线、高倍率清晰度）、战争深度（AI 选项 C、水战、攻城阶段）、长线留存（E9）。外交缺口次之。
4. **排期按“可玩版本”收口**，每轮结束必须能玩、能验收、能回退；不允许同时开三条战线。
5. **I8 与 I10 含待裁决项**，默认不承诺；先做 I6 / I7，再根据实测决定投入。

## 2. 计划原则

1. **先测量，后改造。** P0-0 的教训是：不做基准就会去优化不存在的瓶颈。每轮先出基线表，再动手。
2. **一个入口，一个动作。** 新能力必须挂进现有循环，不新增平行面板。
3. **自动化只做重复，不做取舍。** 内政、运输可委任；征兵、外交、出征、决战必须玩家决定。
4. **每轮准出都是一版可玩的游戏。** 半成品不上主线，可回退是硬要求。
5. **文档单一真值源。** 规格、专项、排期各只有一份“当前有效”，旧版只保留历史记录（见 §13）。
6. **不复制公式。** 模拟器、AI、UI 预览共用同一纯函数；复制实现视为阻塞项。

## 10. 贯穿轨道

以下事项每轮都做，不单独排期：

1. **数值沙盒与回归**：调参后跑 `sim:battle` / `sim:economy` / `audit:ai`，对比 CSV。
2. **日志与回放**：结算关键分支写 log；固定种子可复现。
3. **归因 UI**：新增规则同步补月报 / 战报解释。
