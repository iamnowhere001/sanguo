### 2. 规则补全（可直接进配表）

#### 2.1 回合内的行动力

GDD 说"次数受金钱/体力/资源约束"，但没给数。**不引入额外行动点系统**——多一层资源就多一层教学成本，用已有的钱和体力做闸门更干净。

```
每条内政指令 = 一笔钱 + 执行武将的体力
```

| 指令 | 金钱 | 执行者体力 | 效果 |
|---|---|---|---|
| 开垦 | 60 | 10 | 农业 +8~12（均值 10） |
| 招商 | 60 | 10 | 商业 +8~12 |
| 出巡 | 50 | 10 | 民忠 +5~10 |
| 治理 | 50 | 10 | 防灾 +5~10 |
| 搜索 | 40 | 10 | 见 §2.4 |
| 征兵 | — | 0 | 每兵 1 粮 + 2 钱，上限 `floor(民忠×5)` |
| 交易 | — | 0 | 1 粮 = 5 钱，双向 |
| 宴请 | 100 | 0 | 目标体力 +40，忠诚 +5 |
| 赏赐 | — | 0 | 送出道具，忠诚 +15 |
| 没收 | — | 0 | 收回道具，忠诚 −30 |

**体力规则**
- 体力 0–100，每月初 +20；`宴请` +40（不超 100）。
- 体力 0 时：可执行内政（只扣钱），但**战棋中不能施计**，且普攻伤害 ×0.85（"力竭"）。
- 这是核心取舍：同一名高智武将，是拿体力去搜索/开垦，还是留着上战场放火攻。

`【裁决】` 体力既管内政又管计策，是全局最紧的资源。**这是本作真正的策略轴**，UI 必须在城池面板和战棋面板都显著展示。

#### 2.2 经济与军粮

##### 2.2.1 军粮消耗（GDD 缺）

```
月耗粮 = ceil(该势力总兵力 / 20)      // 每 20 兵 1 粮
```
- 2000 兵 = 100 粮/月。一城（农业 250、民忠 80，月产 200）能养 4000 兵。
- 粮不足时按缺口比例惩罚：**兵力每月逃亡 `min(20%, 缺口比例×50%)`，同时民忠 −5**。
- 结算顺序：先扣军粮，再算逃亡，再算产出 → 产出不能"预支"给当月军粮。

##### 2.2.2 经济自洽性检查 `【建议改】`

按 GDD 原文（税率 1.0）跑一遍单城月度账：

| 项 | 数值 |
|---|---|
| 月粮产出 | `250×80/100 = 200` |
| 季税（税率 1.0） | `250×80/100×1.0 = 200` → 折月 **67 钱** |
| 养 2000 兵 | −100 粮 |
| 一次内政 | −60 钱 |
| 征 400 兵 | −400 粮、−800 钱 |

**结论：税率 1.0 时，一城一个月只够做 1 次内政，征兵一次要攒 12 个月。经济跑不动。**

三档方案：

| 方案 | 税率 | 内政单价 | 月钱（单城） | 评价 |
|---|---|---|---|---|
| A 严格照 GDD | 1.0 | 60 | 67 | 靠搜索掉钱续命，节奏极慢，情怀向 |
| **B 推荐** | **3.0** | **60** | **200** | 每月 3 次内政，征兵 4 个月攒一次，能滚起来 |
| C | 3.0 + 新增"征收"指令 | 60 | 200+ | 多一个指令，多一层复杂度，不必 |

`【裁决】` 采用 **B**：`季税 = floor(商业 × 民忠/100 × 3.0)`。这是**纯配表数值**，写进 `balance.ts` 一个常量，试玩不对改一个数就行——数据驱动的好处就在这里，不要现在争论。

##### 2.2.3 灾害表（GDD 缺具体值）

```
灾害概率 = clamp((60 − 防灾) / 100, 0, 0.6)     // 防灾 60 以上不触发；防灾 0 时 60%
```
| 灾害 | 概率占比 | 损失 |
|---|---|---|
| 旱灾 | 55% | 粮食 −30%、人口 −5%、农业 −3 |
| 水灾 | 45% | 粮食 −25%、人口 −8%、民忠 −6 |

- 防灾 100 → 概率 0，符合 GDD"基本免灾"。
- 灾害系数 `1 − 损失比例`，代入产出公式当月生效。
- 判定用 `rng`，写进存档的随机流，读档可复现。

#### 2.3 忠诚与叛变（GDD 只写了每月 −1）

```
每月初：所有非君主武将 loyalty −1
loyalty < 30 且与某敌对势力城池相邻 → 每月 10% 概率被"挖角"，成功则转投该势力
loyalty == 0 → 立即转为在野，所在城池守军减半
君主 loyalty 恒为 100，不参与结算
```
- 忠诚上升：赏赐 +15、宴请 +5、战胜 +3、占领城池 +2（参战者）。
- **设计意图**：忠诚是"钱的另一种形态"。玩家要在"给关羽配方天画戟（+15 忠诚但占道具位）"和"留着道具给下一个将"之间选。

#### 2.4 搜索与掉落（GDD 缺权重）

```
单次搜索 = 40 钱 + 10 体力
```

掉落分两层：**先判稀有池，再落普通池**。

1. **稀有池**（每城独立，`onceOnly` 条目搜出后永久移出）
   - 命中率 = `min(25%, 该城稀有剩余条目权重和 × 2%)`
   - 例：江夏剩「铁骑兵符(w=5)」→ 命中率 `min(25%, 10%)` = 10%。搜 10 次期望得 1 张。
   - 稀有池空 → 直接进普通池。
2. **普通池**（每次必得其一）

| 结果 | 权重 | 数量 |
|---|---|---|
| 金钱 | 35 | `100 + rng(0..150)` |
| 粮食 | 30 | `200 + rng(0..300)` |
| 普通武器（武力 +2~5） | 15 | 1 件 |
| 常规兵书（智力 +2~5） | 12 | 1 件 |
| 在野武将 | 8 | 该城 `wildGenerals` 中随机一名，可立即招募（200 钱） |

- 在野武将招募后 `loyalty = 60`。
- 搜索不消耗回合，只消耗钱和体力 → 富城可以一月搜空。

#### 2.5 经验与升级（GDD 缺曲线）

```
升级所需（L→L+1）= floor(80 × L^1.4)
```
L1→2 = 80；L5→6 = 761；L10→11 = 2009；L19→20 = 4935；**1→20 累计 41,560 exp**。

| 来源 | 经验 |
|---|---|
| 普攻命中 | 15 + floor(伤害/10) |
| 击溃一支部队（兵力归零） | 80 |
| 计策成功 | 20 |
| 占领城池 | 200（参战全员） |
| 战斗胜利 | 300（参战全员） |

一场中等战斗单将约 400–700 exp。单将若参战 40 场 ≈ 22,000 exp → **14–15 级**；满级需参战 70 场以上。

这个手感是刻意选的：**满级武将 = 这一局的英雄，不是开局配置**。同时也解释了为什么"极兵/玄兵"要靠兵符而不是靠等级——等级这条路太慢了。

#### 2.6 转职与兵符唯一性

GDD 说"装备铁骑兵符转极兵"，但没说兵符能不能复制。`【裁决】`：

- **每张兵符全局唯一（singleton）**，同一时刻只存在于一名武将的道具栏里。
- 转职**不消耗**兵符，兵符可转移（转移需该武将回城，且目标武将满足属性阈值 + 有空位）。
- 极兵武将若失去兵符 → 掉回原兵种，兵力不变。

**这一条比任何数值调整都重要**：它把"极兵过强"从数值问题变成了**位置问题**——全图只有 1 支极兵、1 支玄兵，你想给谁。

> 补充依据：GDD 第 5 页核心循环图把「④ 扩张」的产出明确写成"占领城池、招降俘虏、**控制兵符/坐骑点位**"。也就是说原设计里，兵符点位本身就是战略目标——这跟"兵符全局唯一"是同一个意思，只是它没在文字章节里写死。我把它落成规则。

##### 2.7.3 计策表

| 计策 | 解锁 | 体力 | 射程 | 效果 | 限制 |
|---|---|---|---|---|---|
| 火攻 | Lv3 | 20 | 2（十字范围 1） | 伤害 `floor(智×3 × (1+智差/200) × 天气)` | 雨天禁用 |
| 水计 | Lv5 | 25 | 2 | 伤害 `floor(智×2.5)`，目标邻水或雨天 ×1.5 | 目标需邻水域或雨天 |
| 混乱 | Lv8 | 30 | 2 | 目标 N 回合无法行动，`N = clamp(1+floor(智差/40), 1, 3)` | — |
| 治疗 | Lv6 | 20 | 1（含自身） | 恢复 `floor(智×2)` 兵力，不超上限 | — |
| 落石 | Lv10 | 25 | 2 | 伤害 `floor(智×3.5)`，十字范围 | 施计者须在山地 |

- 天气系数：晴 1.0 / 雨（火攻禁用，水计 1.5）/ 雾 0.9 且命中 −20%。
- 玄兵加成：Lv10 起体力消耗 ×0.9，Lv20 ×0.8，且 Lv20 解锁全部计策（无视等级门槛）。
- 成功率沿用 GDD：`clamp(50 + (施智 − 目智) + 等级差×2, 10, 95)`。

##### 2.7.4 行动顺序与结算

```
每个战斗回合（1 天）：
1. 回合开始：天气判定（每 5 天重掷一次）、混乱倒计时 −1
2. 行动阶段：按 移动力 → 等级 → 攻方优先 排序，逐单位行动
   单位可选：移动 / 攻击 / 计策 / 待机（每单位每回合 1 次主动作 + 移动）
3. 回合结束：兵力归零单位移除，判定胜负
4. 第 30 天结束：进攻方判负
```

- **击溃主将立即胜**：主将 = 部队列表中第一位（玩家可在大地图编成时指定）。
- 俘虏判定：主将被击溃 → **100% 被俘**；其他武将 → 30%，且施害者武力越高概率越高（`30% + (武力差)×0.5%`，上限 70%）。
- **战败或超时的处理（GDD 流程图原文："否/超时 → 我方失败，残兵退回"）**：进攻方失败，部队退回出发城，**兵力保留 70%**；武将不掉级、不掉兵种，但体力清零。
- 主动撤退按战败处理（同上），不能靠"打不过就跑"零成本试探。

> 差 19–21 倍」口径冲突的源头（见 [数值口径](../03-数据/数值口径.md) §0 第 3 条）。
> 删掉它，后人就不知道那段推导在批评什么。**只读结论，不要照抄。**

这是 GDD 最大的空白。"自由沙盘"如果理解成"像素级自由移动"，纯前端 + 回合制的组合会非常难受（路径寻路、补给、遭遇战全要写）。`【裁决】`

##### 2.8.1 大地图 = 城池节点 + 道路图

```ts
interface MapEdge { a: string; b: string; cost: number }  // cost = 行军天数
```
- 城池是节点，道路是边，**一张无向图**（约 35 城 / 50 条边）。
- 玩家点城池 → 弹出"出征"→ 选目标（只列**道路直连**的城）→ 选武将（≤5）→ 出发。
- 行军耗时 = `ceil(edge.cost / 部队最慢移动力 × 3)` 天，折算成 1–3 回合。行军期间部队在地图上"在路上"，不可操作，可被拦截（P1）。
- 抵达后：**城内有守军 → 进战棋；无守军 → 直接占领**。
- 这保留了 GDD 要的"多路线选择 + 战略纵深"，但实现量是像素地图的 1/5。

##### 2.8.2 战棋地图生成（确定性）

```ts
seed = hash(attackerCityId + defenderCityId + turnNumber)
grid = 12 × 10
```
生成流程：
1. 按防守城的 `terrain` 选**地形模板**（不是纯随机噪声，保证每城有辨识度）：
   - `plain` 城：平原 65% / 森林 20% / 河流 15%
   - `mountain` 城：山地 45% / 平原 35% / 森林 20%
   - `forest` 城：森林 50% / 平原 35% / 山地 15%
   - `water` 城 / `isWaterCity`：水域 30%（贯穿条带）/ 平原 45% / 森林 25%
2. 城池格固定在第 3–4 行、第 5–6 列区域（守方主将出生）。
3. 攻方从对侧边缘入场（按两城在大地图的相对方位决定，北攻 → 从下缘入场）。
4. 用 `rng(seed)` 填充其余格，再做一次"去碎块"平滑（避免单格孤岛）。
5. **同一对城池在同一回合反复打，地图不变**（读档可复现）。

#### 2.9 外交公式（GDD 缺）

> **状态：已被 [内政与外交卷](../02-系统/内政与外交.md) 取代。** 本节只保留最初的公式推导，
> 实际实现（三态关系、关系分区间、AI 求和）以该卷为准。

```
离间成功率 = clamp(40 + (我智 − 目标智) + (100 − 目标忠诚)/2, 5, 90)%
  成功：目标体力 −30，忠诚 −(5 + floor(我智/25))
招揽成功率 = clamp(10 + (我智 − 目标智) + (70 − 目标忠诚) × 1.2, 5, 85)%
  仅当目标忠诚 < 70 时可执行；成功则目标转投，带走其兵力
策反成功率 = clamp(5 + (我智 − 太守智) + (60 − 太守忠诚) × 1.0, 2, 50)%
  成功：整城归降（含城内钱粮），太守忠诚重置为 70
  失败：暴露，双方关系恶化 → 该势力对你所有城池的 AI 侵略性 +30%（持续 6 回合）
```
每次外交消耗 150 钱 + 执行武将 20 体力。

#### 2.10 AI 效用评分（GDD 缺权重）

> **状态：已被 [AI 卷](../02-系统/AI.md) 取代。** 本节是 v0.2 时的初版权重，
> 后续两次改造（战略层多城协同、战术层评分重构）都已推翻其中的具体取值。

**战略层（每月，逐城）**
```
score(开垦) = 3.0 if 城粮 < 3×月耗 else 0.5
score(招商) = 2.5 if 势力金 < 500 else 0.8
score(出巡) = 2.0 if 民忠 < 50 else 0.3
score(治理) = 1.5 if 防灾 < 40 else 0.2
score(搜索) = 2.0 if 该城稀有池未空 else 0.6
→ 按 score 降序执行，受金钱与体力约束
```
**出兵判定**
```
战力比 = 我方可战兵力 / (目标城守军 + 邻城援军 × 0.5)
出兵 if 战力比 > 1.3 且 势力粮 > 6×月耗 且 有可战武将体力 ≥ 30
```
**难度参数**
| 难度 | 资源倍率 | 侵略阈值 | 战棋评估深度 |
|---|---|---|---|
| 易 | 0.85 | 1.6 | 1 层 |
| 中 | 1.00 | 1.3 | 2 层 |
| 难 | 1.20 | 1.1 | 3 层 |

**战术层（战棋）** 用简单打分：`弓兵→找森林/山地；骑兵→找平原冲后排；水兵→守水；玄兵→保持距离放计；步兵→占城`。不做全局搜索，够用。

#### 3.2 核心接口

```ts
// core/actions.ts
type Action =
  | { t: 'SELECT_SCENARIO'; scenarioId: string; rulerId: string }
  | { t: 'DOMESTIC'; cityId: string; cmd: DomesticCmd; generalId: string }
  | { t: 'SEARCH'; cityId: string; generalId: string }
  | { t: 'RECRUIT'; cityId: string; generalId: string; amount: number }
  | { t: 'TRADE'; cityId: string; buyFood: boolean; amount: number }
  | { t: 'CLASS_CHANGE'; generalId: string; tallyItemId: string }
  | { t: 'DIPLOMACY'; kind: 'alienate'|'recruit'|'defect'; targetId: string; agentId: string }
  | { t: 'DEPLOY'; fromCityId: string; toCityId: string; generalIds: string[] }
  | { t: 'BATTLE_MOVE'; unitId: string; to: Coord }
  | { t: 'BATTLE_ATTACK'; unitId: string; targetId: string }
  | { t: 'BATTLE_TACTIC'; unitId: string; tacticId: string; target: Coord }
  | { t: 'END_BATTLE_TURN' }
  | { t: 'END_TURN' };

function reduce(state: GameState, a: Action): { state: GameState; log: LogEntry[] }
```

- 所有 `systems/*` 都是 `(state, params) => Result`，**不持状态、不读全局、不碰 DOM**。
- reducer 只做三件事：校验 → 调 system → 合并结果 + 日志。这样 Vitest 能直接测规则。

#### 3.3 月度流水线（顺序必须写死）

```
1. 玩家阶段（map）             ← 玩家自由操作，可存自动档
2. END_TURN
3. 时间推进：month+1（12→1 时 year+1）
4. 忠诚 −1 → 叛变判定
5. 军粮扣除 → 缺粮逃亡
6. 灾害判定 → 直接扣粮食/人口/民忠（不产生"系数"，避免与产出重复计算）
7. 粮产结算
8. 若 month ∈ {3,6,9,12}：季税结算
9. AI 势力依次行动（固定顺序 = factions 数组顺序）
10. 胜负检查
11. 资源上限校验（粮食溢出归零 + 强警告）→ 自动存档
```

两处对 GDD 的调整，都是为了堵套利漏洞 `【裁决】`：

- **先扣军粮、再产粮**。若按 GDD 的"先结算产出再判定"，玩家可以在月末把粮食交易/征兵清空，下月军粮就扣不到——白养一回合兵。
- **灾害直接扣存量，不走系数**。原设计"粮产 × 灾害系数"与"灾害扣粮食"会重复计算；改为灾害先扣，产出按满额算，因果关系更清晰，玩家也更容易归因（"这个月粮少是因为闹了旱灾"，而不是"粮产公式里有个看不见的系数"）。

#### 3.4 随机数可复现

```ts
// mulberry32，状态存 { seed, cursor }
function next(s: RngState): [number, RngState]  // 纯函数
```
存档只存 `seed + cursor`。读档时快进 `cursor` 次即可完全复现。**不要在 system 里直接 `Math.random()`**，这是可回放与 bug 复现的前提。

#### 3.5 渲染分层（GDD 风险项"大地图性能"）

Canvas 分三层，静态层只在状态变更时重绘：

| 层 | 内容 | 重绘时机 |
|---|---|---|
| L0 静态 | 地形底图、道路、城名 | 换剧本 / 城池易主 |
| L1 动态 | 城池旗帜、部队图标、选中高亮 | 每次 state 变更 |
| L2 交互 | 光标、可达范围、伤害预览 | 每帧（仅鼠标移动时） |

35 城 + 5 单位，三层分离后完全不会卡。

#### 3.6 存档

```ts
interface SaveV1 {
  version: 1;
  createdAt: number;       // 槽位列表用
  scenarioId: string;
  state: GameState;        // 含 rng: {seed, cursor}
  checksum: string;        // 简单 hash，防手改
}
```
- Dexie 表：`saves`（槽位）、`auto`（自动档，3 个滚动位）。
- 自动存档时机：每回合 END_TURN 后、战斗结束后、关键操作（处斩/没收）前。
- 迁移：`migrate.ts` 按 `version` 链式升级，**永远不删旧字段解析器**。
