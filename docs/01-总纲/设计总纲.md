# 设计总纲 · 这是一款什么样的三国游戏

> **本文管什么**：设计意图 —— 这游戏靠什么好玩、抄三国志 11 的哪几条、不抄哪几条、什么坚决不做。
> **本文不管什么**：具体数字（查 [项目基线](../00-基线/项目基线.md)）、具体规则（查 [规则底座](规则底座.md)）、具体系统（查 `02-系统/`）。
>
> 写这份文档的原因：设计意图此前散在 README、现代重制方案、迭代计划三处，**没有一处能一页读完**。
> 新接手的人先读迭代计划，会以为这是个「按 I6–I11 排期交付的工程」，而不是「一款要做成什么样的游戏」。

---

## 1. 一句话

**一款仿《三国志 11》的回合制策略 Web 游戏，但把决策密度从「部队调度」挪回「城内政令 + 一战一题 + 月报归因」。**

这句话里最重要的是**后半句**。前半句是品类，后半句是差异化 —— 也是唯一的生存理由。

---

## 2. 核心循环

游戏有三层节拍，玩家在三个尺度上做决定：

| 尺度 | 玩家在做什么 | 关键约束 |
| --- | --- | --- |
| **月** | 朝议 → 分配政令 → 决定这个月先解决什么 | 每城政令 = 2 + 在城武将/3，上限 4；月度点击目标 ≤ 20 |
| **旬**（1 月 = 3 旬） | 行军 → 围城 → 攻城，逐旬下令 | 每支部队每旬 1 个动作（移动不占动作）；每将每月只能行军一次 |
| **季**（3/6/9/12 月） | 税收入账，看这一季的家底 | 税率 1.2；金钱上限 30000，粮食无单城上限 |
| **局** | 立足 → 争锋 → 定鼎，三幕推进 | 幕有退出条件，不是「占够 40% 城」 |

**为什么是「旬」不是「月」**：月回合 + 59 城 + 合理行军速度，三者不能同时成立。
这是《全地图模式升级评估》里点名的**硬约束** —— 是设计问题，不是实现问题。
选「旬」是唯一能同时满足三者的组合，代价是玩家每月要下 3 次令而不是 1 次。

---

## 3. 三条设计主线

所有设计取舍都可以回到这三条上。它们来自 GDD 优化规划报告（基线 rev.5）。

| 主线 | 目标 | 判据（可以拿来否决一个提案） |
| --- | --- | --- |
| **A · 数值：切断套利，重建取舍** | 农业管「数量」、商业管「质量」 | 任何单一加点路线不超过最优产能的 120% |
| **B · 信息：行动前可预览，结算后可归因** | 月报、上限预警、伤害区间、计策成功率全部前置 | 月度操作点击 ≤ 40（v2 目标 ≤ 20） |
| **C · 工程：确定性优先，内容后置** | 命令 → 纯函数 → 新状态；随机数按系统分流 | 读档 100% 复现 |

**主线 C 是最容易被违反的一条**。任何「先加个随机效果，以后再补确定性」的提案，都会在存档迁移和回归测试上付出十倍代价 —— 项目已经为这个教训付过一次账（`SAVE_VERSION` 从 5 到 6 清库）。

## 4. 四条体验支柱

主线管「怎么做得对」，支柱管「怎么做得**好玩**」。
它们的共同判断是：**系统已经够多了，问题是玩家不知道这个月先听谁的。**

| 支柱 | 要解决的问题 | 判据 |
| --- | --- | --- |
| **一屏一月** | 月度入口是城池列表，不是议程 | 2 城 5 令只需 2 次操作；经典模式 0 泄漏 |
| **一战一题** | 每场战斗的目标都是「把对面打完」 | 现代模式战斗 100% 有主目标；预览 / HUD / 战报三处一致 |
| **一局三幕** | 章节只是三个数字目标，不是叙事单元 | 幕有转折，后期清城量 −50% |
| **一眼一等** | 金色、红色、青色都在抢注意力 | 任何新面板先回答「它属于 T1/T2/T3/T4 哪一层」 |

**这四条不是功能清单，是验收口径**。一个「加了新系统」的版本如果四条支柱一条都没改善，那它就是负功。

## 5. 抄三国志 11 的什么，不抄什么

这是本作最需要说清楚的一节 —— 因为「仿三 11」这四个字，既是最好的卖点，也是最容易走偏的地方。

### 抄的（已验证有效，保留）

| 三 11 的机制 | 本作的落地 | 为什么抄 |
| --- | --- | --- |
| 五维武将（统率 / 武力 / 智力 / 政治 / 魅力） | 338 名武将，数值按五维设定 | 五维是「一个武将能干什么」的最简表达，不需要额外职业系统 |
| 一队三将 | 1 主将 + 2 副将，战场合并为一个单位 | 让「搭配」成为决策：武力最高的当主将，还是智力最高的？ |
| 关隘 / 港口是必经节点 | 47 处关港，1 格宽 4 邻接通行线，线外山水不可通行 | 地理决定战略纵深；没有关的关卡，地图就只是背景图 |
| 3×3 城郭 + 四门 | 每城 9 格，四边中点各一门，四门全堵则守军出不来 | 攻城有「围三阙一」的战术空间，而不是数值对撞 |
| 旬为回合单位 | 1 月 = 3 旬，跨月才做月度结算 | 见 §2 的硬约束 |
| 兵种相性 + 地形适性 | 六兵种相性矩阵、地形强/中/弱 | 让「带什么兵、走哪条路」有意义 |
| 攻城器械 | 冲车 / 井阑 / 投石 / 木兽，各有射程与对门 / 对墙 / 对守军倍率 | 攻城是个多回合的工程，不是一次判定 |
| 国策三选一 | 8 张国策，收益与代价都写明 | 每月一个真实的取舍，而不是纯增益 |

### 不抄的（明确否决，不再讨论）

| 三 11 的机制 | 为什么不抄 |
| --- | --- |
| 内政设施自由摆放 | 决策成本高、UI 复杂度高，收益是「微调最优解」。本作用**营造工程**（每城 2 位、4 类工程、2–3 月自动推进）替代 |
| 单挑 / 舌战 | 独立小游戏，与主循环耦合弱；做了也只是一个可跳过的动画 |
| 结婚 / 义兄弟 / 人际关系网 | 需要长期关系建模，与「一局 3 幕」的节奏冲突 |
| 舰船兵种 + 独立水战规则 | 只做江面地形与补给影响，不做舰船。**已裁决，不再议** |
| 写实 3D / HD-2D 表现 | 程序化地图 + 高可读性是本作的成本优势，换表现等于换项目 |

### 最危险的诱惑（必须记住）

> **全地图会稀释现有优势。**
>
> 本作现在的决策密度在「城内政令 + 一战一题 + 月报归因」。
> 全地图模式的决策密度会转移到「部队调度与补给」。
> 后者做不好，游戏会退化成**走路模拟器** —— 这是绝大多数三国志 11 仿制品的死因。

这条判断写在《全地图模式升级评估 v1》里，当时是用来劝退「L 档（地图即战场 + 设施 + 迷雾）」的。
后来项目确实走了全地图路线，但**用的是 M 档思路**（地图上跑部队），并且靠「一屏一月」把决策密度按回了内政侧。
**这条警告没有过期** —— 每次想加「地图上的新操作」时，先问一句：这是在加决策，还是在加走路？

## 6. 非目标

以下事项**不在本轮范围内**，提出来会被直接否决（除非先改这份文档）：

- 多人联机、账号系统、在线排行
- 写实 3D / HD-2D；地图保持程序化与高可读性
- 地图随机生成、天气系统扩展、部队阵型扩展
- 舰船兵种与独立水战规则
- 美术资源铺量；资产只做「城池 / 关隘部件」最小集
- 完整复刻原版彩蛋；情怀项一律走设置开关

**「非目标」不是「以后再说」**。它是「现在说不」，防止排期被悄悄塞满。
真要改，先改这份文档，再改排期 —— 顺序反了就会变成「先做，再找理由」。
