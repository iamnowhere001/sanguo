## 0. 裁决

用户已定的三条，本档不再讨论：

| # | 决策 | 取值 |
| --- | --- | --- |
| 1 | 战斗节拍 | **逐队每旬手动下令**（三11 同制）。废弃 `BattleState.day` 的"日"回合，战斗与战略共用「旬」 |
| 2 | 范围 | **攻城 + 野战一起合一**。`BattleScreen` / `BattleCanvas` / `GamePhase 'battle'` 全部删除 |
| 3 | 守军 | **实体化为「城守军」部队**：真实 `Army`，占城心与己方门格，可被器械打击、可出城迎战、可被围死 |

本档补充的六条：

| # | 决策 | 取值 | 理由 |
| --- | --- | --- | --- |
| 4 | 一旬行动权 | 每支部队每旬 = **移动（花 MP）+ 1 个动作**；动作过完记 `Army.actedXun = xunTurn` | 现在 `Army` 没有任何行动标记，防重复全靠 `phase==='battle'` 这道全局锁（`reducer.ts:468/481/818`）。锁要拆，就必须先有替代物 |

| 6 | 围城停修 | 任一门被敌军堵住的城，**本月不享受耐久月修** | 中城月修 121 ≈ 40/旬，裸攻 70/旬，净 30 → 27 旬才破。不停修则"围城"永远耗不过"等待" |
| 7 | 旧存档 | `SAVE_VERSION` 6 → 7；v6 起库升级本就清档（`save/db.ts:156`），**战中档直接放弃**，不做 BattleUnit 回写迁移 | 迁移一条已经不存在的状态机，成本高于收益 |
| 8 | 一战一题 | 从"每场战斗一题"改为**每场战役一题**（一次围城 / 一次接战 = 一场战役），Phase 4 回归 | 题目体系（`battle/objectives.ts`）依赖 `day` 与 `units`，是合一里最贵的一块，不能阻塞主链路 |

## 1. 三11 攻城规则的落地映射

### 1.1 城池 = 地图上的可攻击目标

一座城在地图上是一组格子，攻击目标有三类，玩家下令时必须显式选一个：

| 目标 | 格 | 谁打得到 | 打中什么 |
| --- | --- | --- | --- |
| **城门** | `block.gateTiles[side]` | 站在该门 `approaches[side]` 的部队（射程 1） | 城墙耐久，倍率最高 |
| **城墙** | `block.tiles` 非门格 | 射程 ≥ 2 的器械（投石） | 耐久（低于城门），但可在安全距离外持续放血 |
| **城内守军** | 城心 3×3 域 | 井阑（压城头）、投石（抛物）、木兽（火攻），以及耐久 <25% 后的登城步兵 | 守军兵力与气力 |

非城主的部队始终不能踏上城墙格（`cityGrid.wallPassableFor:122`），这条不变。
**耐久归零 = 城破**，此时城墙对攻方开放，攻方进入城心格即完成占领；
**守军兵力归零 = 空城**，可直接接管（沿用 `setup.captureUndefended` 的结算口径）。

### 1.2 器械分工（本档的核心新增）

现状：器械只是"站在城墙格上磨耐久"的倍率（`battle/siege.ts:52`），既没有射程，也不能把城当目标。改为：

| 器械 | 价 | 射程 | 对耐久 | 对守军 | 城头反击 | 特例 |
| --- | --- | --- | --- | --- | --- | --- |
| 无（裸兵） | — | 1（贴门） | ×1 | ×1 | 全额 | 只能磨，慢 |
| 冲车 ram | 60 | 1（贴门） | **×4** | ×0.5 | **全额 ×1.3** | 只有它能"破城门"：城门耐久单独算，破则此门可被步兵直接踏入 |
| 井阑 tower | 90 | 1–2 | ×3 | **×1.2** | 全额 | 唯一能压制城头的：它攻击时守军反击 ×0.5 |
| 投石 catapult | 120 | **2–3** | ×3 | ×0.8 | **无**（射程外） | 唯一能直接打城内守军与友邻敌部队的；误伤相邻格（含己方）20% |
| 木兽 beast | 80 | 1 | ×2 | **×1.5 + 火攻** | 全额 | 命中后城内守军气力 −15、该城 `fortification` −5（下限 0），持续至月结 |

`BALANCE.DURABILITY.siegeWeaponMult`（`balance.ts:132`）与 `siegeWeaponVsTroops`（`:139`）是真值源，
上表新增的射程与反击系数并入同一块 `BALANCE.SIEGE`。

### 1.3 守军的还手

守军不再只在"被复制成战棋单位"时才存在。地图口径下：

- **城头反击**：任何对城门/城墙/城内守军的动作，都会按"抽象守军单位"（兵力 = `garrisonTroopsOf`，
  武力 = 在城最强将，地形 = `city`，减伤吃 `cityDamageMultiplier(城防)`）回敬攻方一记，
  走同一份 `computeDamageValue`。器械的反击减免见 1.2 表。
- **出城迎战**：守军部队实体化后，玩家可以（AI 自动）把城守军拉出城门变成野外部队，
  四门全堵则出不来（沿用 `cityGrid.sortieBlocked:97`）。
- **被围断粮**：四面陆门全被堵 → 每月守军逃散 + 民忠下降（沿用 `army.runSiegeAttrition:1605`），
  并按裁决 6 停止耐久月修。

## 2. 状态模型

### 2.1 `Army` 新增字段（`core/state.ts:340`）

```
role?: 'field' | 'garrison'        // 缺省 field；garrison = 城守军，占城格、不自动吃旬移动力
garrisonCityId?: string            // role==='garrison' 时指向驻守城
actedXun?: number                  // 上次执行动作的 xunTurn；同旬不可再动作
morale?: number                    // 气力 0–100（从 BattleUnit 平移）
stunned?: number                   // 混乱剩余旬数
entrenched?: number                // 据守等级：原地不动累积，受击减伤
maxTroops?: number                 // 出征满编快照：溃散阈值（15%）的分母
autoOrder?: boolean                // 玩家野战部队托管：旬结时自动行军 / 接战 / 攻城
```

`BattleUnit` 的 `hasMoved / hasActed / prevX / prevY / bonusMove / routed` 不再需要：
移动由 `mp` 记账，溃散由 `troops === 0` + 撤退结算表达。
`maxTroops`（溃散阈值）用 `General.troops` 的出征快照，落在 `Army.troops` 上即可。

### 2.2 武将在城 / 在军的互斥语义（最大风险面）

现在"在城"= `status==='active' && locationId===cityId && !armyId`，全仓 **20+ 处手写**这组三元组。
守军实体化后，守将**会**挂 `armyId`（指向本城守军部队），所以必须先把判定收口到一个谓词：

```
// core/state.ts
isCityDefender(g, cityId)  =  g.status==='active'
                           && g.locationId === cityId
                           && !g.armyId
```

Phase 3 守军实体化后，守将**会**挂 `armyId` 指向本城守军部队，届时谓词扩为
`(g, cityId, s)` 并加上 `|| s.armies[g.armyId]?.garrisonCityId === cityId`。
Phase 0 先不收这个参数：没有产生者之前它就是死参数。
（Phase 3 实际未采用这条路线，守军改为派生镜像，谓词保持原样，见 §6.3。）

Phase 0 做纯机械替换（行为不变），顺带修两处已存在的口径漏洞：
`reducer.ts:378`（`ASSIGN_TROOPS_ALL` 漏 `!armyId`，在途将能被一键领兵）与
`diplomacy.ts:200` / `delegate.ts:59`（只比 `locationId`，把在途武将算进守军）。

### 2.2.1 Phase 0 已落地（施工记录）

- 谓词落在 `core/state.ts:979`，替换 **24 处**手写三元组，覆盖 `troops / domestic /
  logistics / abandon / diplomacy / events / ai / aiStrategy / army / reducer /
  battle/setup / battle/delegate`，UI 侧 `MapCanvas` 改走 `cityGenerals`。
- `core/selectors.ts:cityTroops` 原是自己重算一遍驻军，现直接委派 `garrisonTroopsOf`。
- 行为有意变化的四处（其余零变化）：
  1. `ASSIGN_TROOPS_ALL` 不再把城内池兵发给已出征的部队；
  2. `diplomacyTargets` 不再把在途武将列为敌城守将；
  3. `delegate` 的「敌国君主所在，必须亲征」只在君主真在城时触发；
  4. `captureUndefended` 不再中途改写仍在行军的部队归属。
- 撤退折兵比例归一：`army.ts` 原 `0.6`、`gates.ts` 原 `0.7` 均改读
  `BALANCE.RETREAT_KEEP_RATE`（0.7）。**地图部队战败保留率因此从 60% 提到 70%**。
- `damage.ts` 本来就是解耦的（`DamageAttacker/Defender` 是结构接口，全文无 `BattleState`）。
  真正缺的桥是地形：`KIND_TO_TERRAIN` 从 `battle/grid.ts` 搬到 `systems/cityGrid.ts`，
  新增 `mapBattleTerrainAt(col, row, targetCityId)`——`battle/grid.ts` 是 Phase 4 要删的文件。
- 新增 `tests/garrison.spec.ts`（4 项）钉住以上不变量。

## 3. 结算层（新增 `src/systems/combat/`）

| 文件 | 导出 | 职责 |
| --- | --- | --- |
| `unit.ts` | `armyCombatView(s, army)` / `garrisonCombatView(s, cityId)` | 把 `Army` 与城内守军适配成伤害公式需要的形状（地形实时取自 `terrainGrid`，气力/器械/特技取自 Army） |

## 5. 数值重标定（per-日 → per-旬）

`BALANCE.DURABILITY.assaultPerTroop = 0.025` 的语义由"每日"改为"**每次攻城动作**"，数值不动。
校准结果（2,000 兵 / 武力 80，开局耐久按上限 80% 起算）：

| 目标城 | 上限 | 起算 | 裸兵 ×1 | 冲车 ×4 | 投石 ×3 |
| --- | --- | --- | --- | --- | --- |
| 小城（城防 40） | 690 | 552 | 8 旬 | 2 旬 | 3 旬 |
| 中城（城防 60） | 1,010 | 808 | 12 旬 | 3 旬 | 4 旬 |
| 都城（城防 80） | 1,680 | 1,344 | 19 旬 | 5 旬 | 6 旬 |

配合两条：围城停修（裁决 6）、多路合围伤害线性叠加。设计目标：
**不带器械的裸攻应当打不下来，或者打到气力崩溃**——器械与合围才是破城的正解。
野战伤害不变，但 `BATTLE_MAX_DAYS=30` 这条"30 天超时"上限随战棋会话一起删除。

### 6.1 Phase 1 已落地（2026-10-31 施工记录与偏差）

**实际落点**

- 新增 `src/systems/combat/` 四个文件：`action.ts`（行动权）、`unit.ts`（适配层）、
  `capture.ts`（城破易主）、`siege.ts`（攻城内核）；`strike.ts / xun.ts / ai.ts` 属 Phase 2/3，未建。
- `action.ts`：`canAct` / `actBlockReason` / `markActed`，判据 `army.actedXun === s.xunTurn`；
  移动仍只吃 `army.mp`，不占动作。**失败的下令不记账**（结算成功后才调用 `markActed`）。
- `reducer.ts` 的 `ASSAULT` 改为必带 `cityId`，新增可选 `target: 'gate' | 'wall' | 'garrison'`
  （缺省 `gate`）与 `gateSide`；旧 `assaultCity` 整段删除，AI 与玩家走同一把 `siegeStrike`。
- 围城停修：`logistics.runCityRepair` 读 `cityGrid.isSieged`（四门任一被敌军压住即停修）。
- AI：`army.playArmyTurn` 末尾用 `aiSiegePickOf` 选目标、`siegeStrike` 下单；不再 `createBattle`、
  不再写 `phase='battle'`。城破后该纵队直接从地图上移除（武将已入城）。
- 校准实测：中城（城防 60、上限 1,010、起算 80%）2000 兵 / 武力 80 带冲车 = **280/旬，3 旬破城**，
  与 §5 表一致；`tests/siege.map.spec.ts` 14 项钉住射程、破门、两条破城路、围城停修与适配层。
- `tests/army.spec.ts` 的「走到城门外自动开战」用例改写为「围城不自动开战，下令才打、同旬拒二次」；
  全量 560 项中仅剩 R7 的 5 项既有红（不新增红）。

**与规格的偏差（有意）**

1. **木兽气力惩罚未做**：`Army` 还没有 `morale`，`SIEGE.fire.moraleHit` 留到 Phase 2 接上；
   Phase 1 只落地「火攻烧城防」。
2. **火攻城防为永久创伤**：三11 的削弱持续到月结，需要临时状态容器；Phase 1 直接扣
   `city.fortification`（下限 0），靠新 owner 重修城防恢复。
3. **城门耐久只由冲车消耗**：`City.gateHp` 在 `planSiege` 里只有 `ram` 打门才扣；
   井阑 / 投石 / 木兽砸的是城墙耐久。破门后同一座门的伤害 ×`breachedGateMult`（1.5）。
4. **裸兵登城门槛**：`weapon === 'bare'` 时，须「已破门」或「耐久 ≤ 上限 × `stormWallRatio`」
   才能选 `garrison` 目标；否则报「登不了城」。
5. **投石贴门可隔城砸对侧**：射程 2–3 意味着贴着北门打不了北门，但 3×3 城块的对侧门在 2 格外，
   仍可打。因此 AI 的投石压在门口不会彻底空转，Phase 1 不需要「后退一格」的 AI 逻辑。
6. **`retreatCityFor` / `checkGameOver` 仍引用 `battle/resolve.ts`**：`capture.ts` 只抽出了
   城池易主口径，这两个函数随 Phase 4 与 `battle/resolve.ts` 一起迁入；Phase 1 允许单向依赖。
7. **`MapCanvas.battleZoomFor` 未删**：野战仍走战棋会话（Phase 2 才合一），删掉会让野战镜头
   失去跟随。攻城已不产生 `state.battle`，不会再触发放大；该分支留到 Phase 4 统一清。
8. **`gates.ts` 的攻关结算未地图化**：关防仍是轻量即时结算，本轮只把它的伤亡分摊改为复用
   `combat/unit.applyGeneralLoss`，不并入 `siegeStrike`。

### 6.2 Phase 2 已落地（2026-10-31 施工记录与偏差）

**实际落点**

- 新增 `src/systems/combat/strike.ts`：`strikeArmy(s, attackerId, defenderId)`。一道军令 = 本旬一记
  交锋（前向伤害 → 反击 → 溃散判定 → 败方撤退/被俘），伤害走 `computeDamageValue` 与
  `armyCombatView`；夹击按「目标相邻的己方部队数」取 `BALANCE.MODERN.FLANK`；
  胜利方清空 `path / mp / targetCityId`，非水军在江面获胜后移到最近陆地；忠诚按
  `LOYALTY.battleReturn / battleDefeat` 记账。玩家参战写 `s.report`（野战胜利 / 击退敌军 /
  野战失利 / 遭遇战失利）并 `recordBattleResult`；AI 互殴只写日志。
- `reducer.ts` 的 `ATTACK_ARMY` 直接调 `strikeArmy`，成功后返回草稿态，**不再生成 `BattleState`、
  不再切 `phase='battle'`**；同旬第二次下令由 `army.actedXun` 拒绝。
- `army.ts`：删除 `resolveAiSkirmish / armyPowerOf / retreatArmyGenerals`（约 75 行）；
  AI 相邻敌军走同一把 `strikeArmy`，败方按 `loserArmyId` 从 `keep` 移除；玩家侧
  `attackArmy` 改为委托。AI 互殴不再有「战力高者胜」的特判。
- `core/state.ts` 新增 `Army.maxTroops`（出征满编快照）。`army.ts` 建队时写入；
  旧部队 / 测试构造的部队由 `strikeArmy` 首次接战按当时兵力补记。溃散线 =
  `maxTroops × ROUT_TROOPS_RATIO (15%)`。
- `ui/MapScreen.tsx`：`ATTACK_ARMY` 成功后不再清空选中部队，玩家可以连续观察战果；
  按钮提示改为「地图即时交锋，不切战棋；击溃后退往最近己方城」。
- 修复败军处置的一处口径漏洞：被打光的武将不再被当成「零兵预备队」遣回城里，
  主将按开战时的最强将判定被俘，副将溃散；真正未参战的零兵预备队仍回城待命。
- 测试：新增 `tests/field.map.spec.ts`（7 项）钉住交付判据——全程 `phase==='map'` 且无
  `state.battle`、同旬拒二次、失败下令不吃行动权、跨旬消耗至溃散、夹击加成、AI 互殴不写
  玩家战报；`tests/fieldBattle.spec.ts` 的 3 项战棋流程用例改写为地图流程，其余 13 项继续
  覆盖 Phase 4 才删的战棋函数。全量 566 项：561 绿 + 5 项 R7 既有红（不新增红）。

**与规格的偏差（有意）**

1. **气力 / 混乱 / 据守 / 计策 / 突击未挂到 `Army`**：本阶段 `strikeArmy` 只做普攻 + 反击，
   `Army.morale / stunned / entrenched` 与计策、突击一起留到 Phase 3（与守军实体化同一批容器）。
   因此溃散判定先用「出征满编 15%」这条硬线，跨旬累计消耗分胜负；没有气力崩溃这条软线。
2. **`runCombatXun` 未建**：每旬的气力恢复、晕船、围城停修标记仍留在既有旬结
   （`playArmyTurn` 的水战上岸、`logistics.runCityRepair` 的围城停修）；`combat/xun.ts`
   随 Phase 3 一起建，届时接管这两处。
3. **天气固定晴天**：`GameState.weather` 尚不存在（裁决 10 的旬级全局天气是 Phase 3 的容器），
   `strikeArmy` 用 `MAP_WEATHER = 'clear'`，不吃雨 / 雾减伤。
4. **AI 旬级下令未拆 `combat/ai.ts`**：仍复用 `playArmyTurn` 的逐队循环——相邻敌军 →
   `strikeArmy`，射程内有敌门 → `siegeStrike`；选目标只取最近的敌军 / 敌门，不做兵力评估
   与主动撤退。`orderArmiesForFaction` 随 Phase 3 抽出。
5. **溃散分母取 `Army.maxTroops` 而非「本旬起始兵力」**：若按每旬起始兵力算，势均力敌的
   野战每旬各掉约 10%，永远摸不到 15% 线，只能靠一击全歼收场。以出征满编为分母后，
   同等规模的野战会在数旬内自然分出胜负。
6. **玩家不能中途脱离野战**：战棋的 `BATTLE_RETREAT` 没有地图等价物——要么继续下令打，
   要么用行军令走开。`BATTLE_*` 系列动作随 Phase 4 删除。
7. **关港驻军仍不可野战**：与 Phase 1 同口径，`strikeArmy` 直接拒绝「关港驻军不出关野战」。
