## 四、重复逻辑（按合并价值排序）

### 4.1 建议合并

**`inMap` ×3 + `keyOf` ×4 —— 网格坐标工具散落各处**

- `inMap`：`marchCost.ts:119`（导出）、`gateGrid.ts:90`（本地 const，逐字相同）、`terrainGrid.ts:439`（`inBounds`，换对象参数、语义相同）
- `keyOf`（`` `${col},${row}` ``）：`army.ts:91`、`cityGrid.ts:45`、`gateGrid.ts:88`、`terrainGrid.ts:420`（`keyOfTile`）
- 建议：收敛到一个中立的网格工具模块。**关键坑**：marchCost.ts 已 import gateGrid，gateGrid 不能反向 import marchCost，否则循环依赖——这正是各文件本地重写的原因，必须落到双方都不依赖的中立模块（如 `src/data/tables/geography.ts` 或新建 `src/core/grid.ts`）。
- 风险：低（纯函数），但涉及 4 个文件的引用改写，需跑完整 verify。

**`clamp` ×2 —— 两份等价实现**

- `src/systems/formulas.ts:9` 与 `src/render/camera.ts:50`（min/max 写法不同，算法等价）
- 建议：保留 formulas.ts 版本为唯一实现，camera.ts 改为引用。`generalStats.ts:5` 的本地 clamp 带 round 和 5–95 固定区间，**语义不同不合并**（可改为调共享 clamp 后再 round）。
- 风险：低。

**terrainPaint 法向量惯用段 —— 10+ 处重复**

- `` const len = Math.hypot(dx,dy)||1; const nx=-dy/len; const ny=dx/len `` 模式在 `terrainPaint.ts` 的 227、279、426、530、723、777、824、871、915、938、1056、1545 等行反复出现。
- 建议：抽 `normalOf(a, b)` 辅助函数，净省约 40 行。风险：低，纯几何。

### 4.2 不建议合并（看似重复，实为分层设计）

- **确定性 RNG 两套**：`src/core/rng.ts`（mulberry32 + 可序列化游标，游戏逻辑）vs `terrainPaint.ts:100`（LCG 闭包，仅绘图）。合并会**改变地形贴图的确定性输出序列、地图外观随之变化**，且绘图侧不需要游标序列化。建议保留，各加一行注释说明为什么不共用。
- **三套网格搜索**：`army.ts:307 marchField`（Dijkstra，含关防/城墙/占位约束）vs `gateGrid.ts:616 cityLandDistance`（多源 BFS + 缓存）vs `gateGrid.ts:663 landDetour`（限深 BFS + 预分配队列）——权重模型、约束、性能优化各异，强行抽公共 BFS 会参数爆炸。
- **`isMarchable` vs `isPassable`**：前者含兵种与山岭代价，后者仅查水面，粒度不同（且前者已是死代码，删掉后此问题消失）。
- 琐碎项：MapCanvas.tsx 两处相同的「万」格式化（2182/2496 行），价值不大，顺手可抽。
