## 1. 地图规格与旧档迁移

| 项 | v1 | v2 | v3（当前） |
| --- | --- | --- | --- |
| 栅格 | 96×72 | 192×144 | **576×432** |
| 每格世界单位 | 12 | 12 | **12** |
| 世界尺寸 | 1152×864 | 2304×1728 | **6912×5184** |
| `MAP_VERSION` | 1 | 2 | **3** |
| `SAVE_VERSION` | 3 | 4 | **5** |

- 经纬度投影不变（`LON_RANGE` / `LAT_RANGE`），只放大采样密度；59 城仍按真实坐标落位。
- 旧档迁移按版本链逐级放大：v1 → v2 → v3，每一级都把部队坐标乘以对应倍率，
  再吸附到最近的可行陆格；**只放大大地图坐标，不放大战斗内局部坐标**。
- 缺 `mapVersion` 的存档一律视为 v1；`SAVE_VERSION` 小于 5 的档走同一套迁移链。

### 为什么是 576×432

- 城池之间终于能放下"路程"：中原到江陵不再是一屏内的几个点；
- 长江 / 黄河可以画到 10–20 格宽，港口渡线有足够水面；
- 720% 近景时一格约 33px，山道、城门、渡口都能看清；
- 20% 全图仍是完整天下，适合看大势与势力色块。

## 2. 关隘与港口

### 2.1 数量与分布

| 类型 | 数量 | 名单 | 落位 |
| --- | --- | --- | --- |
| 关隘 | 12 | 潼关、函谷关、虎牢关、武关、散关、壶关、井陉关、阳平关、剑阁、葭萌关、祁山堡、瓦口关 | 山脊 / 丘陵的窄口 |
| 港口 | 16 | 孟津渡、河阳渡、白马津、延津、夏口渡、汉阳渡、赤壁渡、乌林渡、寻阳渡、皖口渡、濡须口、采石渡、横江渡、瓜洲渡、京口渡、白帝渡 | 江面 / 湖面，图标落在岸上滩头 |
| 小路 | 3 | 子午谷、轘辕道、阴平道 | 翻山小径，专为绕过对应关隘而设 |

> **城池与关防不重复**：阳平关、濡须口 只作为关防存在，不再单设城池；赤壁剧本共 59 城。
> 关防数值统一在 `BALANCE.GATE`，配表只写档位与归属城，具体数值由档位区间约束。

### 2.2 通行线

- 每处关港有一条 **1 格宽、4 邻接**的通行线（`GateSite.lane`）；
- 关隘的线穿过山脊，两端接山路；港口的线横渡江面，两端是滩头（`approaches`）；
- 小路的线同样穿过山脊，但没有归属、守军与产出，也无法封锁——它只是"另一条能走的山口"；
- **线外的山体与水面不可通行**：关港是穿越山脉 / 江河的唯一缺口；
- 关隘 / 小路的中心必须在山地 / 丘陵；港口中心必须在水面；
- 港口图标（`GateSite.icon`）必须在岸上，且是两端滩头之一——否则船像停在江心；
- 同一条道路上挂多处关防时，用 `anchor`（经纬度锚点）显式指定先后位置
  （如 汉中–梓潼 一线先过阳平关、再过剑阁），不再取道路中点。

### 2.3 归属与通行

| 状态 | 判定 | 结果 |
| --- | --- | --- |
| 己方 | `gateOwnerOf(s, id) === 势力` | 自由通过 |
| 无主 | `ownerId == null` | 可通行；路过的部队会顺手接管 |
| 敌对 | 归属其他势力 | **封锁整条通行线**，必须先攻关 |
| 法理城易主 | 关港未独立攻占 | 归属跟随 `guardCityId` 的城主 |
| 独立攻占 | `GateRuntime.ownerId` 存在 | 以关港自身归属为准，不再跟随法理城 |
| 小路 | `kind: 'trail'` | 不参与归属判定，永远可通行、不可封锁 |

### 2.4 产出、守军与数值档位

- 关港没有内政、不能征兵、不能建造；
- 每月按类型产出少量钱粮，**直接解送给所属势力的法理城**（`gateSupplyCityOf`），
  不进入关防自己的府库；
- 守军按月少量回补，但不能超过关港上限；
- 攻占关港只改变通行权与产出归属，不触发城池易主。

档位区间（`BALANCE.GATE.TIER`，配表逐项落值，`tests/gates.spec.ts` 校验落在区间内）：

| 档位 | 关隘 城防 / 守军 / 金 / 粮 / 行军 | 港口 城防 / 守军 / 金 / 粮 / 行军 |
| --- | --- | --- |
| 1 大型 | 15–18 / 2600–3200 / 38–46 / 100–125 / +3 日 | 8–12 / 1700–2200 / 26–36 / 100–145 / +2 日 |
| 2 中型 | 9–13 / 1700–2300 / 24–32 / 60–90 / +2 日 | 5–7 / 1200–1600 / 18–24 / 80–100 / +2 日 |
| 3 小型 | 6–9 / 1300–1700 / 15–23 / 40–60 / +2 日 | 4–6 / 900–1300 / 14–18 / 55–80 / +2 日 |
| 小路 | 0 / 0 / 0 / 0 / +4–7 日 | — |

潼关、剑阁、濡须口等锁钥按 1 档给到上限；郡界小关按 3 档，
保证"重点关防值得打、普通关防值得绕"。

### 2.5 对岸配对与斜向锚点

港口按**成对渡口**设计：同一处江面的两岸各设一个港口，用 `pairId` 双向关联，
锚点（`anchor`）沿江斜向错开 ≥ 0.25°（`BALANCE.GATE.PAIR_MIN_OFFSET`），
避免两个图标挤在同一格：

| 南岸 / 西岸 | 北岸 / 东岸 | 对应水路 |
| --- | --- | --- |
| 孟津渡 | 河阳渡 | 黄河 |
| 白马津 | 延津 | 黄河 |
| 夏口渡 | 汉阳渡 | 长江 / 汉水交汇 |
| 赤壁渡 | 乌林渡 | 长江 |
| 寻阳渡 | 皖口渡 | 长江 |
| 采石渡 | 横江渡 | 长江 |
| 瓜洲渡 | 京口渡 | 长江 |

配对只影响落位与展示：两港各自独立归属、独立封锁；`GatePanel` 会显示"对岸港口"，
便于判断过江后的退路。

### 2.6 小路绕关（史实梗）

| 小路 | 绕过 | 典故 |
| --- | --- | --- |
| 子午谷 | 散关 | 魏延献子午谷奇谋，直取长安 |
| 轘辕道 | 虎牢关 | 洛阳东南的轘辕关道，可绕虎牢侧翼 |
| 阴平道 | 剑阁 | 邓艾偷渡阴平，绕开剑阁直下江油 |

小路行军日数高于正关（+4–7 日），且无法驻守封锁：
走小路省去攻关，但要付出时间与无掩护的风险。

### 2.7 AI

- 行军路径经过敌对关港时，AI 必须先攻关，不能"绕过去"；
- 路过无主关港会顺手接管，避免留下免费通道（小路除外）；
- 关港守军不足时，AI 会从法理城调兵补防。

## 3. 真渡口判定

港口不是"水边随便一个点"。`gateSites()` 对每个港口做三项检查：

1. 两端滩头（`approaches`）都是可站立的陆地；
2. 两端滩头都能沿陆路走到最近的城池（不被水或山封死）；
3. 两岸之间不存在短陆路绕行——否则这个"渡口"没有存在意义。

不满足条件的候选点会被丢弃或沿江平移；`npm run map:gates` 与
`tests/gates.spec.ts` 都会逐项校验。夏口渡、赤壁渡等长江渡口因此落在真正的两岸滩头上，
而不是江心或湖心。

## 5. 相机与渲染

### 5.1 缩放口径

| 缩放 | 用途 | 说明 |
| --- | --- | --- |
| 20% | 全图 | 使用全图总览缓存，看势力色块与大势 |
| 100% | 州郡视角（默认） | 一格约 33px，能看清城郭、关港、部队 |
| 720% | 近景 | 一格约 240px，山道、岩壁、渡口纹理可见 |

`CAMERA_BASE = 5`，`MIN_ZOOM = 0.2`，`DEFAULT_ZOOM = 1`，`MAX_ZOOM = 7.2`。

### 5.2 地形分块

- 世界 6912×5184，整图缓存即使 0.5× 也要约 72MB，移动端会触发 canvas 上限；
- **两档缓存**（I7 · 7.5 定稿）：
  - 粗档 **384×384 世界单位一块、1.5× 分辨率、LRU 32 块**（约 42MB），`zoom < 3.2` 使用；
  - 细档 **144×144 世界单位一块、3× 分辨率、LRU 16 块**（约 12MB），`zoom ≥ 3.2` 使用。
    整张地图只有 4×3 块，高倍率视野（约 400×310 世界单位）两三块就够，烘一次可长期复用；
- 高倍率时粗档先铺满视野、细档叠在上面：细档未烘完时看到的是"略糊但完整"的地形，不是空洞；
- 补烘节奏：单帧预算粗档 6 块 / 细档 2 块；两次绘制间隔 < 110 ms 视为连续操作，暂停补烘；
  补烘间隔 160 ms（必须大于 110 ms，否则补烘帧会把自己判成"连续操作"，永远烘不出来）；
- 低倍率全图直接使用单独的总览缓存（1/10 分辨率）。

### 5.3 美术要点

- **河流**：宽度微起伏的平滑绢带 + 上下游色差 + 裁剪内的深浅斑 / 碎波 / 岸沫，
  不再使用多层等宽描边；深浅斑用径向渐变，边缘自然淡出，避免"水面网格"与椭圆硬边；
- **山脉**：`Massif` 山体成块，前后错落；丘陵用扁缓山包，沟壑用暗色折线；
- **关隘**：两座山包 + 沿山道的岩壁 + 土路 + 碎石 / 裂纹，关门嵌在山口里；
- **港口**：图标落在岸上滩头，渡线以虚线横渡江面，标签跟随图标；
- **道路**：低倍率显示驿道，高倍率自动淡出，避免像横跨江面的电线。

### 5.4 版图染色与名牌（I7 · 7.2 / 7.6 定稿）

**染色**（`render/territoryPaint.ts`）：

- 铺色 2 px/格、模糊 1.8px；墨线单独 **3 px/格、模糊 1.2px**（近景才不糊），合计约 17MB；
- 势力色先向白色提亮 **28%**，再用 **`color` 混合**（取势力色色相/饱和度、保留宣纸明暗）。
  旧方案 multiply 会把深蓝、深绿压成灰紫，已在 20% / 100% / 720% 三档真机对比后替换；
- 墨线仍用 multiply（宿墨压深纸底，是线不是面）；
- 染色强度 `territoryWash`：20% → 0.71，100% → 0.42，200% → 0.26，≥300% 封底 0.10。

**名牌**（`render/labelLod.ts`）：

| 档位 | 倍率 | 显示 |
| --- | --- | --- |
| 0 | < 0.45（全图） | 仅都城 |
| 1 | 0.45–0.95 | + 大城 |
| 2 | 0.95–2（州郡） | + 中城 / 小城 / 关港名 / 「势力 · 兵力」副行 |
| 3 | ≥ 2（近景） | 全部 |

- 选中 / 悬停的城无论档位都带名牌；名牌仍按 2px 碰撞盒避让；
- 命中框：城池按"离城心至少 18px"外扩（低倍率小城自动变大，仍取最近中心，不误点邻城）；
  关港命中半径 14px，390px 手机可点选。

## 8. 已知取舍

1. **关港通行线是运行时生成的**：配表只写档位、锚点与法理城，`render/gateGrid.ts`
   按地形找山口 / 渡线；新增关港需要维护 `anchor`、`guardCityId` 与配对关系，
   并由 `map:gates` 校验落位。
2. **水战仍是"在江面格上打陆战"**，没有独立的舰船 / 水军兵种；港口提供的是通行与地形，
   不是一套水战规则。
3. **旧战斗存档不迁移局部坐标**，只保证能继续打完；新战斗一律走大地图。
4. **地形分块在高倍率仍有轻微模糊**：细档 3× 放大到 720% 约 1.8 倍（粗档为 2.2 倍），
   属于性能与清晰度的折中；再想更锐需要按设备像素烘焙或改用 WebGL。
5. **粮食无上限后，后期粮草可能大量堆积**；目前只靠运输与出征消耗，没有新的仓储机制。
6. **编队只在出征 / 行军端自动成队**：目前没有独立的"布阵界面"，玩家不能逐场手动改副将。

## 9. 武将五维与队伍编制

### 9.1 五维口径（参考《三国志 11》）

`General` 持有 `leadership`（统率）、`force`（武力）、`intellect`（智力）、
`politics`（政治）、`charm`（魅力），取值 0–100；名将数值写在
`data/tables/generalStats.ts`，补位将领按武力 / 智力折算，保证全员五维完整。

| 属性 | 作用 |
| --- | --- |
| 统率 | 带兵上限的主属性；出征时决定默认主将排序 |
| 武力 | 普攻伤害、单挑、突击 |
| 智力 | 计策成功率与计策减伤 |
| 政治 | 内政 / 外交面板数值（展示与 AI 参考） |
| 魅力 | 登用 / 征兵 / 民忠面板数值（展示与 AI 参考） |

带兵上限公式：

```
带兵上限 = 统率 × 10 + 武力 × 8 + 智力 × 4 + 等级 × 80
```

`tests/formulas.spec.ts` 锁定样例：1 级吕布（统 89 / 武 100 / 智 26）= 1874，
1 级诸葛亮（统 92 / 武 38 / 智 100）= 1704。

### 9.2 队伍编制：1 主将 + 2 副将

- 一支队伍最多 `BALANCE.SQUAD_DEPUTIES_MAX = 2` 名副将（`systems/squads.ts`）；
- **战场上一个队伍只占一个单位**：兵力合并，武力 / 智力取队内最高，
  兵种与移动力跟随主将；
- 战后按**出阵兵力份额**把剩余兵力分回各将，副将不会凭空消失；
- 编队配置是可选参数（`createBattle(..., { squads })` / `sortieArmy(..., squads)`）：
  不传时保持"一将一队"，旧测试与旧档行为不变；
- 出征时未显式配置，则按统率从高到低每 3 人一队自动成队；
- `BattleScreen` 单位卡显示"副将 关羽、张飞"，`RosterDialog` / 城将列表显示完整五维。

单次出征仍最多 5 名武将（`BATTLE_MAX_ATTACKERS`），即最多 2 支满编队伍 + 1 支残编；
守方按兵多者取前 8 将各自成队（`BATTLE_MAX_DEFENDERS`）。
