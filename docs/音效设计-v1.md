# 音效设计 v1

> 适用版本：三国霸业 v0.1 垂直切片
> 真值源：`src/audio/manifest.ts`（参数）、`src/audio/types.ts`（id 枚举）、`src/audio/director.ts`（触发映射）
> 本文与代码冲突时，以代码为准；改参数只改 manifest，不要把数值散回业务层。

## 0. 一句话

游戏需要六类声音：**背景音乐、环境音、UI 交互、角色动作、技能与战斗反馈、进程提示音**。
全部走同一条混音总线，由「玩家操作 → 声音导演 → 引擎」三个环节串起来，规则层不感知音频存在。

当前项目没有任何音频素材，因此 v1 用 **WebAudio 程序化合成** 落地：零资源、零版权风险、首次交互即可发声。合成配方集中在一处，后续换真实录音只需替换配方，上层参数与触发逻辑不动（见 §7）。

## 1. 设计原则

| 原则 | 具体做法 | 反面案例（本作避免） |
| --- | --- | --- |
| **战斗要压过 UI** | 战斗总线 −7～−10 dB，UI 总线 −15～−19 dB | 点一下按钮和砍一刀一样响 |
| **同一事件只发一次声** | 失败提示音只在 `notify()` 发；战报收束音只在弹窗挂载时发 | 一次点击叠三层音 |
| **时机跟着演出走** | 敌军回合的鼓点在 620ms 演出**之前**播，填满空窗 | 等结算完才响，玩家以为卡了 |
| **重复不刺耳** | 每条音效有冷却与复音上限；噪声随机读取起点；音高带随机抖动 | 连点出兵变成机关枪 |
| **可关闭** | 总音量 / 音乐 / 音效三路独立，静音一键，配置落 localStorage | 只能整体静音 |
| **降级不阻塞** | 无 AudioContext 时全部方法空操作，游戏逻辑与存档不受影响 | 音频报错导致进不去游戏 |

## 2. 声音分层与混音总线

```
合成源（振荡器 / 噪声 / 拨弦 / 鼓 / 钟）
        │
        ▼
  sound.gain（manifest 里的相对增益 0–1）
        │
        ▼
  category bus（域增益 × 用户音量）
        │                              ┌── bgm、ambience 先过 musicDuck
        ├──────────────► musicDuck ────┤   （战报/大招时压到 0.32）
        │                              └──
        ▼
   master（总音量 / 静音）
        │
        ▼
   destination
```

域基础增益（`CATEGORY_GAIN`）：

| 域 | 基础增益 | 受哪一路音量控制 | 用途 |
| --- | --- | --- | --- |
| `bgm` | 0.26 | 音乐 | 三条循环曲 |
| `ambience` | 0.16 | 音乐 | 风、战场底噪、雨 |
| `ui` | 0.50 | 音效 | 按钮、选中、警告 |
| `action` | 0.52 | 音效 | 部队选择 / 移动 / 待机 |
| `combat` | 0.68 | 音效 | 普攻、突击、溃散 |
| `tactic` | 0.62 | 音效 | 五种计策与落空 |
| `stinger` | 0.62 | 音效 | 月结、出征、胜负、统一 |

**默认设置下各层实际响度**（master 0.80 / 音乐 0.70 / 音效 0.85）：

| 层 | 代表音效 | 实际响度 |
| --- | --- | --- |
| BGM | `bgm.map` | −16.7 dB |
| 环境音 | `amb.map` | −25.4 dB（只做底噪，不该被“听见”） |
| UI | `ui.click` / `ui.warn` | −18.7 / −15.1 dB |
| 动作 | `unit.move` | −15.1 dB |
| 战斗 | `attack.melee` / `combat.charge` | −9.6 / −7.1 dB |
| 计策 | `tactic.rock` / `tactic.fail` | −8.4 / −13.9 dB |
| 提示音 | `stinger.unify` / `stinger.report` | −7.5 / −12.2 dB |

设计意图：**音乐垫底、环境音几乎不可察觉、战斗明显顶出、UI 克制**。任何新音效都应落在同域现有值的 ±3 dB 内。

## 3. 音效类型与触发时机

### 3.1 背景音乐（BGM）

| id | 曲风 | 何时进入 | 何时退出 |
| --- | --- | --- | --- |
| `bgm.menu` | A 羽调，稀疏拨弦 + 低频持续音，1.15s 一步、42% 休止 | 主菜单 / 剧本选择 | 进入对局 |
| `bgm.map` | 同调性，0.85s 一步、带每 8 拍一记远鼓 | 开局、读档、战斗结束回到大地图、月结 | 进入战棋 |
| `bgm.battle` | D 羽调，0.42s 一步、每 2 拍一鼓，音区更高更硬 | 出征成功建立战斗 | 战斗结算完、回到大地图 |

切换规则：**同一时刻只有一条 BGM**，交叉淡化；新旧同 id 时不重启（`enterScene` 做差异判断）。

### 3.2 环境音

| id | 内容 | 叠放方式 |
| --- | --- | --- |
| `amb.map` | 两段带通噪声，缓慢扫动，模拟原野风 | 与 `bgm.map` 同进同退 |
| `amb.battle` | 风声更急 + 42Hz 低频压迫感 | 与 `bgm.battle` 同进同退 |
| `amb.rain` | 高通噪声双层，雨幕 + 细雨沙沙 | 战棋内 `weather === 'rain'` 时叠上去，晴天淡出 |

`amb.rain` 是**天气叠层**，与 base 环境音各占一个槽位，互不替换：雨天时 `amb.battle` 继续存在，只是再叠一层雨。

### 3.3 UI 交互

| id | 触发场景 | 播放时机 |
| --- | --- | --- |
| `ui.click` | 任意按钮点击（全局事件委托，捕获阶段） | click 事件立即 |
| `ui.confirm` | 主操作按钮（`.primary` / `.danger`）或 `data-audio="confirm"` | 同上 |
| `ui.cancel` | `Esc` 关闭弹窗 / 取消选择；或 `data-audio="cancel"` | keydown 立即 |
| `ui.select` | 大地图点击城池（画布，不走按钮委托） | 选中变化时 |
| `ui.warn` | `store.notify(text, 'warn' \| 'danger')`：无效操作、资源不足、超时 | 提示入队时 |
| `ui.toast` | `store.notify(text, 'info' \| 'good')`：存档成功、一般提示 | 提示入队时 |

`installUiAudio()` 用一次全局 `click` 委托覆盖所有现有与后续按钮，**新增界面不需要写任何音频代码**；需要特殊语义时用 `data-audio="none|confirm|cancel"` 覆盖。

### 3.4 角色动作

| id | 触发 | 说明 |
| --- | --- | --- |
| `unit.select` | 战棋中点选我方待行动部队 | 与 `ui.select`（城池）区分：一个在棋盘上，一个在地图上 |
| `unit.move` | `BATTLE_MOVE` 成功且兵种为步兵 / 弓兵 / 极兵 / 玄兵 | 两步甲片声 |
| `unit.moveCavalry` | 同上，骑兵 | 三蹄 + 沙土 |
| `unit.moveNavy` | 同上，水兵 | 水花与船体 |
| `unit.wait` | `BATTLE_WAIT` 成功 | 一声呼气，主动“放弃行动”的听觉确认 |
| `unit.undo` | `BATTLE_UNDO_MOVE` 成功 | 反向噪声，暗示“退回” |

### 3.5 技能与战斗反馈

| id | 触发 | 播放时机与层次 |
| --- | --- | --- |
| `attack.melee` | `BATTLE_ATTACK` 成功，攻方为步兵 / 水兵 / 极兵 / 玄兵 | 立即；金属碰撞 + 低频身体 |
| `attack.arrow` | 同上，攻方为弓兵 | 立即；破空 170ms，命中在 150ms 处 |
| `attack.cavalry` | 同上，攻方为骑兵 | 立即；双蹄撞 + 马刀 |
| `hit.heavy` | 同一次攻击 `damage ≥ 目标 maxTroops × 25%` | 延迟 **40ms** 叠在攻击音上，只加强不替代 |
| `combat.charge` | `BATTLE_CHARGE` 成功（极兵突击，每战 1 次） | 立即；上扫 + 巨鼓，全场最重的一击 |
| `combat.rout` | `result.routed === true` | 攻击后 **120ms** / 突击后 **180ms**；下行噪声 + 远去鼓 |
| `combat.enemyPhase` | 玩家结束回合、敌军演出开始前 | **立即**，先于 620ms 结算延迟，填满等待空窗 |
| `tactic.fire` | `BATTLE_TACTIC` 成功且 `tacticId === 'fire'` | 立即；低频膨胀 + 7 次随机爆裂 |
| `tactic.water` | 同上，水计 | 立即；水幕下扫 |
| `tactic.rock` | 落石 | 立即；次低频轰鸣，仅次于突击 |
| `tactic.confuse` | 混乱 | 立即；两个相差 31Hz 的钟产生拍频，制造眩晕 |
| `tactic.heal` | 治疗 | 立即；三音上行（C5-E5-G5） |
| `tactic.fail` | `success === false` | 立即；闷响，与命中音形成明确对比 |

**为什么重击用“叠加”而不是“替换”**：兵种音色承载“谁在打”，伤害层承载“打得多重”，两者正交。替换会让弓兵的高伤害听起来像近战。

### 3.6 进程提示音

| id | 触发 | 时机 |
| --- | --- | --- |
| `stinger.turn` | `END_TURN` 成功 | 立即，更鼓三响，标志一个月结束 |
| `stinger.deploy` | `DEPLOY` 成功（出征建战斗） | 立即，战鼓 + 号角起势 |
| `stinger.report` | 月报弹窗挂载 | 挂载后立即 |
| `stinger.victory` | 战报 `result === 'victory'` | 弹窗挂载时 |
| `stinger.defeat` | 战报败北 / 撤退；或结局败北 | 弹窗挂载时 |
| `stinger.unify` | `UNIFY` 成功；或结局一统天下 | 立即 / 结局界面挂载时 |
| `stinger.cityCaptured` | 非战斗途径获得城池（劝降、献城） | 立即；战斗夺城交给战报 |
| `stinger.levelUp` | `CLASS_CHANGE` 成功（转职） | 立即 |
| `stinger.disaster` | 月结有灾害（`pendingMonth.facts.disasters` 非空） | **延迟 0.9s**，等更鼓落定再报 |

## 4. 参数约定

### 4.1 循环轨

| id | 说明 | 增益 | 播放 | 淡入 / 淡出 (ms) |
| --- | --- | --- | --- | --- |
| `bgm.menu` | 主菜单 · 苍茫 | 0.95 | 循环 | 1600 / 1200 |
| `bgm.map` | 大地图 · 经营 | 1.00 | 循环 | 1600 / 1200 |
| `bgm.battle` | 战棋 · 交锋 | 1.00 | 循环 | 900 / 700 |
| `amb.map` | 大地图环境 · 风与原野 | 0.60 | 循环 | 2400 / 1600 |
| `amb.battle` | 战场环境 · 风与远鼓 | 0.55 | 循环 | 1800 / 1200 |
| `amb.rain` | 雨声叠层 | 0.70 | 循环 | 3000 / 2500 |

规律：
- 进战斗要**快**（700–900ms），离开战斗可以**慢**（1200ms），让紧张感自然回落；
- 环境音比 BGM 更慢（1.6–3s），避免“底噪突然出现”；
- 雨是天气叠层，进出都最慢（2.5–3s），像天气渐变而不是开关。

一次性音效**没有淡入淡出**：它们的包络写在配方里（攻击 3–6ms，衰减按材质 50ms–2.4s），由 `exponentialRampToValueAtTime` 保证不会爆音。

冷却与复音的取值逻辑：
- 冷却 ≈ 该音效自身长度 × 0.3–0.6，保证“听得出是两次”而不是糊成一团；
- 复音上限：可连发的（攻击、点击）给 2–3；有语义唯一性的（提示音、计策、突击）给 1，后到的直接丢弃。

## 5. 循环、切换与闪避

**交叉淡化**：切换 BGM 时新轨 0→满、旧轨满→0，时长取各自 `fadeIn` / `fadeOut`，不做硬切。

**差异切换**：`sceneFor(screen, state)` 每次全量给出「该放什么」，`enterScene` 只处理与当前不同的槽位。因此可以在任何时机重复调用，不会重启正在播的曲子。

**天气叠层**：`weather` 槽位独立于 `ambience` 槽位，雨天时两者共存。

**音乐闪避（ducking）**：
- 触发：带 `duck: true` 的音效（重击、突击、溃散、计策、全部提示音）播放时，自动压制 **1100ms**；
- 长时压制：月报 / 战报 / 结局弹窗挂载期间 `setDuckHeld(true)`，关闭时释放；
- 深度 `DUCK_GAIN = 0.32`（约 −10 dB），建立 140ms、释放 900ms —— 快压慢放，避免音乐“抽搐”。

## 6. 与现有逻辑的集成

### 6.1 数据流

```
玩家操作
   │
   ▼
gameStore.dispatch(action)          ← 唯一状态入口，已有约定
   │
   ├─ reduce(before, action) ──► { state, result }   规则层，纯函数，不认识音频
   │
   ├─ cuesForAction({ action, result, phaseBefore, unitsBefore })   ← 纯函数，可单测
   │        │
   │        ▼
   │   audio.playCues([...])        ← 只消费 Action + ActionResult
   │
   └─ syncScene() ──► sceneFor(screen, state) ──► audio.enterScene(scene)
```

关键取舍：**规则层不出声**。`core/`、`systems/` 里没有一行 `audio.` 调用，战斗结算仍然可以在 Node 里跑模拟器和单测。声音完全由 `ActionResult`（`damage` / `routed` / `success`）和状态差异推导。

### 6.2 代码职责

| 文件 | 职责 | 不该做的事 |
| --- | --- | --- |
| `src/audio/types.ts` | id 枚举、`SoundDef` / `AudioSettings` 契约 | 不含参数值 |
| `src/audio/manifest.ts` | 全部参数真值源 + 域增益 | 不含播放逻辑 |
| `src/audio/synth.ts` | 合成原语与 34 条配方 | 不读游戏状态 |
| `src/audio/music.ts` | 生成式循环轨（持续音 / 噪声床 / 拨弦 / 鼓） | 不做混音 |
| `src/audio/engine.ts` | 总线、复音、冷却、交叉淡化、闪避、解锁 | 不判断游戏语义 |
| `src/audio/director.ts` | 事件 → 音效（纯函数）+ 场景推导 | 不碰 AudioContext |
| `src/audio/settings.ts` | 音量收敛与持久化 | — |
| `src/audio/index.ts` | 单例 + 手势解锁 + 全局按钮委托 | — |

### 6.3 三个接入点

1. **`main.tsx`**：`installAudioUnlock()` + `installUiAudio()`，渲染前装好。
2. **`store/gameStore.ts`**：`dispatch` 里 `playCues` + `syncScene`；`notify` 里按语气发提示音；`start/load/quit/go` 里切场景。
3. **界面侧**：只补规则层拿不到的信息 —— 战棋点选（`unit.select`）、地图点城（`ui.select`）、敌军回合鼓点（`combat.enemyPhase`）、战报/结局收束音、`Esc` 取消（`useEscape`）。

### 6.4 自动播放策略

浏览器要求 `AudioContext` 在用户手势里恢复。因此：
- 首次 `pointerdown` / `keydown` 时 `resume()`，成功后摘除监听；
- 未解锁前 `play()` **直接丢弃**（不排队，否则解锁瞬间所有音效齐响）；
- 未解锁前 `enterScene()` 只记录意图，解锁后自动补上；
- 解锁前**不创建** AudioContext，避免控制台策略警告。

### 6.5 降级

`AudioEngine` 每个入口都先判断环境。Node 测试、隐私模式、极老浏览器下全部空操作，游戏逻辑、存档、自动存档不受任何影响（单测 `tests/audio.spec.ts` 专门锁这条）。

## 7. 资源替换路径

v1 全部合成。要换成真实录音（或加配音）：

1. 把 `assets/audio/<id>.ogg` 放进 `public/audio/`；
2. 在 `manifest.ts` 对应 `SoundDef` 上加 `src` 字段；
3. `engine.play()` 里加一条分支：有 `src` 走 `AudioBufferSourceNode`，没有就走 `recipeFor(id)`。

**参数表、触发映射、总线、冷却、复音、闪避全部不用改**。这也是把「配方」与「参数」分成两个文件的原因。

## 9. 已知限制

- **合成音不是配乐**：生成式 BGM 解决“有没有”，不解决“好不好听”。正式版应替换为录制的民乐/管弦素材。
- **无空间化**：所有音效都是干声居中，没有基于棋盘坐标的声像与距离衰减。若要加，`voice` 增加 `pan` 参数即可，总线结构不用动。
- **无随机容器**：同一兵种的攻击音只用音高/滤波随机化，样本量仍然只有一条。
- **iOS Safari**：静音开关拨到静音时 WebAudio 也会静音，这是系统行为，无法绕过。
- **未做无障碍提示音开关**：目前静音是全局的，没有“只关音乐保留提示音”之外更细的粒度（音乐/音效两路已够用）。
- **未接战斗内单位受击语音**：项目暂无角色语音资源。
