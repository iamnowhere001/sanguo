> 状态：**已实施**（2026-10-23）。
> 范围：`src/systems/factionDiplomacy.ts`、`src/systems/abandon.ts`、`src/systems/battle/setup.ts` / `resolve.ts`、`src/core/reducer.ts`、地图与战棋 UI。

## 0. 结论

- **外交**：势力之间现在有战争 / 停战 / 同盟三种状态与 −100~100 的关系分。玩家可以送礼、停战、结盟、宣战；AI 会互相停战、被压制时向玩家求和；停战 / 同盟期内双方不能出兵，攻击候选与 `createBattle` 都会拦截。
- **战前弃城**：守不住的城可以整建制撤往相邻友城，城池交给最强的邻敌，粮草金钱各损失一半。玩家在城池面板操作，AI 在月度阶段自动判断。
- **守方撤退**：战棋内守方也能弃城撤退，按攻方胜利结算，但未溃散守军撤往友城保留 70%；主将需保住 25% 兵力才能突围。无守军城池被占领时，零兵守将也会撤走，不再留在敌城里。

## 1. 外交关系

### 1.1 数据模型

```ts
type RelationState = 'war' | 'truce' | 'alliance';
interface FactionRelation {
  state: RelationState;
  score: number;          // -100..100
  untilTurn?: number;     // 停战 / 同盟到期（含）
  offeredAtTurn?: number; // 上次求和，避免每月骚扰
}
GameState.diplomacy = { relations: Record<'a|b', FactionRelation> }
GameState.pendingDiplomacy = { fromFactionId, kind, turn } | undefined
```

- 关系键按两个 faction id 排序后拼接，保证 `a|b` 与 `b|a` 同一条。
- 新开局 / 旧存档：`ensureDiplomacy` 补齐全员战争。
- 到期未续：`effectiveRelation` 按战争处理，`tickDiplomacy` 在每月 AI 阶段把状态改回 war 并 −5 关系。

### 1.2 玩家行动

| 行动 | 费用 | 效果 | 条件 |
|---|---|---|---|
| 送礼 | 200 金 | 关系 +10 | 任意状态 |
| 停战 | 300 金 | 停战 12 回合，关系 +10 | 当前战争；AI 接受才生效 |
| 结盟 | 500 金 | 同盟 24 回合，关系 +20 | 需先停战、关系 ≥55；AI 接受才生效 |
| 宣战 | 0 | 立即战争，关系 −40；其它势力各 −5 | 当前停战 / 同盟 |

停战被接受的三条任一：

1. 关系 ≥15（两次送礼即可）；
2. AI 总兵力 < 玩家 75%（打不过）；
3. AI 实际接壤的敌对势力 ≥2，且兵力不超过玩家的 1.1 倍（多线压力，但碾压局不谈）。

结盟额外要求双方有共同敌人，或 AI 比玩家弱。被拒绝仍扣使者费用，并 −5 关系。

UI：地图顶栏「外交」打开势力列表，显示关系、剩余回合、态度分、兵力与四个行动。原城池面板的「外交」改名为「敌将」，只处理离间 / 招揽 / 策反，避免两个入口混淆。

### 1.3 AI 外交

- **AI 互相停战**：当双方都不是最强势力、且主动方明显弱于对方时，主动方花 300 金签 12 回合停战。效果是弱国抱团，把压力转向最强势力（通常是玩家或曹操）。
- **向玩家求和**：AI 总兵力 < 玩家 55% 时，每隔 6 回合发一次停战请求，进入 `pendingDiplomacy`。玩家在地图上看到「停战请求」弹窗；接受即停战 12 回合，拒绝 −10 关系。
- **求和月不进攻玩家**：已经递出求和信的势力，本月攻击候选会跳过玩家目标，避免「一边求和一边捅刀」。
- **未回应的求和信 3 个月后作废**，防止 AI 永久等待。
- **攻击过滤**：`planAttackCandidates` 与 `planMassingMove` 跳过停战 / 同盟目标；`createBattle` 再做一次兜底，玩家手动出征也会被拒绝。
- **威胁判断**：`adjacentThreat` 只统计敌对邻国；盟友 / 停战邻居不再触发增援或弃城。
- **侧翼窗口**：`windowBonusFor` 的「多线受敌」只统计与守方敌对的第三方，盟友不算牵制。

### 1.4 关系变化

| 事件 | 变化 |
|---|---|
| 送礼 | +10 |
| 停战达成 | +10 |
| 同盟达成 | +20 |
| 宣战 / 毁约 | −40（其它势力 −5） |
| 停战 / 同盟到期 | −5 |
| 攻占对方城池 | −15 |
| 求和被拒 | −10 |
| 停战被拒 | −5 |

## 2. 战前弃城

### 2.1 规则

`canAbandonCity` 的前置条件：

1. 大地图阶段、己方城池；
2. 不是最后一城（弃最后一城 = 亡国）；
3. 相邻有敌对势力（没有威胁就不需要弃城）；
4. 城里有可撤退的守将（含 0 兵守将）；
5. 相邻友城的空位装得下全部守军（整建制撤退，不做分批）。

执行 `abandonCity`：

- 所有 active 守将移到相邻友城（优先空位最多的）；
- 城池交给**最强的相邻敌对势力**（按该城驻军排序）；没有敌对邻国时才会变成无主（前置条件通常已排除）；
- 城中粮草、金钱各损失 `BALANCE.ABANDON_SCORCH_RATE = 50%`；
- 玩家弃城会记录 `recordCityLost`，并检查游戏结束与章节进度；
- 日志：「X 弃守 Y，N 将退往 Z，W 进驻」。

### 2.2 玩家入口

城池面板底栏新增「弃城撤退」：

- 不满足条件时禁用，tooltip 说明原因（最后一城 / 无相邻敌军 / 友城容不下 / 非己方城池）；
- 满足时弹出确认框，写明撤退目的地、接手的势力、辎重损失比例；
- 确认后立即执行，不发生战斗。

### 2.3 AI 判断

`planAbandonment` 每月评估一次：

```
threat = 最强相邻敌军的驻军
ratio  = easy 3.0 / normal 2.5 / hard 2.2
若 threat > defense × ratio（或 defense = 0），且能找到目的地 → 弃城
```

- 每月最多弃一城；
- 君主在城内也会一起撤走，保存势力核心；
- 弃城发生在增援 / 出兵之前：先保人，再谈反击；
- 如果 AI 刚和威胁方签了停战，`adjacentThreat` 不再计入，自然就不会弃城——外交可以救城。

## 3. 战棋内守方撤退

- 战棋顶栏的「撤退」按钮现在对攻守双方都显示；守方文案为「弃城撤退」。
- 守方点击后，reducer 走 `resolveBattle(s, b, 'victory')`：按攻方胜利结算，城池归攻方，但未溃散守军撤往相邻友城，保留 70%。
- 确认框会显示撤退目的地；没有相邻友城时明确警告「守军将被俘」。
- 主将只有兵力 ≥ 出战兵力 25% 才能突围；残兵主将仍会被俘。
- 已经溃散的守军不撤退。
- 无守军城池被 `captureUndefended` 占领时，城里的零兵守将也会撤往友城；无路才 inactive，不再出现「0 兵守将留在敌城」的脏状态。

## 6. 未做

- **同盟不自动参战**：目前同盟只保证互不攻击，盟友不会在你被进攻时自动对敌宣战，也不会派兵支援。
- **AI 不主动结盟**：AI 之间只签停战，不签同盟；玩家可以主动与 AI 结盟。
- **没有战争疲劳 / 关系自然漂移**：关系只随事件变化，不会因长期和平自然回暖。
- **弃城不能选接手指向**：城池固定交给最强邻敌，玩家不能选择「交给盟友」或「留空城」。
- **守方撤退没有断后战**：撤退即弃城，不能打一场掩护战再走。
