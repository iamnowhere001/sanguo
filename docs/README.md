## 2. 目录结构

```
docs/
├── README.md                  ← 你在这里
├── 00-基线/                   台账：现在是什么（机器校验，不手改生成块）
│   ├── 项目基线.md
│   └── 项目基线.json
├── 01-总纲/                   意图：为什么做、做成什么样
│   ├── 设计总纲.md
│   └── 规则底座.md
├── 02-系统/                   规格：每个系统怎么运作
│   ├── 地图.md
│   ├── 战斗.md
│   ├── 内政与外交.md
│   ├── AI.md
│   └── 音效.md
├── 03-数据/                   数据：数值与配置
│   ├── 数值口径.md
│   ├── 地图配置台.md
│   ├── 地图数据清单.md        ← 生成物（npm run map:doc）
│   └── 地图配置基线.json      ← 生成物
├── 04-计划/                   计划：接下来做什么
│   ├── 路线图.md
│   └── playtest-观测协议.md
└── archive/                   历史：已废止的决策，不作真值源
```

**为什么是这个顺序**：它对应一个人理解游戏的顺序 ——
**先知道现在是什么（00）→ 再知道要做什么（01）→ 然后知道怎么玩（02）→ 查具体数字（03）→ 最后看排期（04）**。
旧结构按「文档写作时间」堆，所以新人打开目录会看到 22 个平级文件，无从下手。

## 4. 文档规矩

这四条不是形式，是**已经被违反过、并因此付出代价**的规矩。

1. **数字只写一处。** 任何文档要写「59 城」「47 关防」「SAVE_VERSION 6」，从 [项目基线](00-基线/项目基线.md) §2 抄。
   查不到就补进基线，**不许另开一份**。
   代价：曾有 4 处文档各抄一份地图尺寸，地图一改就四处飘，`baseline:check` 就是为这个加的。

2. **改了代码就重生成。** 配表 / 版本号 / 缩放档位一变，同一次提交里跑 `npm run baseline:doc`，否则 `verify` 会挡住。

3. **新文档先登记。** 没在本文件 §3 登记「管什么、不管什么」的文档，不算真值源，只能当讨论稿。
   **一主题一真值源** —— 同一件事有两份文档都自称有效，是文档冲突的唯一根源。

4. **被取代的进 archive，并在开头写明「已被谁取代」。**
   不要在原文里改数字让它「看起来还是对的」—— 那会制造第二份真值源。

### 常用命令

```bash
npm run baseline:doc     # 代码 → 项目基线 §2 + JSON
npm run baseline:check   # 校验：代码 vs 基线 vs 文档断言
npm run map:doc          # 代码 → 地图数据清单 + 基线 JSON
npm run verify           # 完整门禁（含以上检查）
```
