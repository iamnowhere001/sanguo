# 《三国霸业》现代重制 · 体验迭代方案 v2.0

> 基线：步步高电子词典《三国霸业》（约 2004 年）+ 当前 Web 复刻版（四剧本 / 61 城 / 174 将 / 12×8 战棋）
> 关系：v1 回答“现代重制应该有哪些系统”；v2 回答“这些系统如何收成一个玩家能感知的循环”。
> 一句话：**v1 把系统做出来，v2 把系统收成一个动作。**

---

## 0. 结论先行

v1 的 E1/E2 已经落地了大半：政令槽、国策、事件、项目制内政、探索、章节、战斗军令、夹击、托管都已存在，工程上也有对应测试。  
但把游戏真正跑起来后，问题不再是“系统不够”，而是：

> **每个系统都在说话，玩家却不知道这个月先听谁的。**

当前版本的体验断点可以归为四句话：

1. **月度入口还是城池列表，不是议程。** 玩家打开游戏，先看到 2–20 座城，而不是“这个月最该处理什么”。
2. **战斗有战术，没有问题。** 地形、天气、兵种、军令、托管都有，但每场战斗的目标几乎都是“把对面打完”，30 天限制很少成为决策。
3. **长局有章节，没有幕。** 章节是三个数字目标，不是“立足—争锋—定鼎”的三幕结构；后期仍然容易变成逐城清理。
4. **界面有风格，没有层级。** 金色、红色、青色都在抢注意力；手机端顶栏溢出、地图挤成一张网，主操作被次要操作淹没。

因此 v2 不再增加新系统，而是用四条支柱把已有系统重新组织：

| 支柱 | 一句话 | 解决的问题 | 状态 |
| --- | --- | --- | --- |
| **一屏一月** | 一个屏幕内看完本月局势，并完成本月治理 | 月度入口分散、逐城点击 | **E5 已落地** |
| **一战一题** | 每场战斗只问一个问题，部署前就能看到 | 战斗目标单一、30 天无感 | **E6 已落地** |
| **一局三幕** | 一局分成立足 / 争锋 / 定鼎三幕 | 长局没有节奏、后期清城 | E7 |
| **一眼一等** | 一眼能读出“现在该看什么、该点什么” | 信息层级、移动端、色彩语义 | E8（E5 已打底） |

**v2 的第一刀选择“朝议”，不是因为它最炫，而是因为它是所有系统的入口。**  
如果玩家不愿意把重复内政交出来，后面加再多战斗目标，也只是在旧循环上再叠一个按钮。

本轮已实现并验证：

- **朝议 / 军师**：三张奏折 + 风险提示 + 四种施政倾向 + 可预览委任 + 一键执行；只动内政政令，不碰征兵、交易、外交、出征。
- **一战一题（E6）**：现代模式每场玩家战斗在部署前显示主目标（破城 / 守城，带期限）与最多一个支线（斩将 / 截粮 / 护粮）；战棋 HUD、战报奖励和部署预览共用同一份确定性题目。
- **地图军师条**：把“本月最紧急的一件事”常驻在地图上方，不用打开弹窗也知道下一步。
- **手机端信息架构**：顶栏“更多”收纳次要操作；地图默认 2.1× 缩放，支持拖拽、滚轮、`+ / − / 全图`。
- **交互语义**：金色 = 前进 / 确认，红色只留给破坏性操作。
- **工程验证**：295 项测试全绿，`typecheck` 与生产构建通过；1440 / 390 两端 Playwright 实测无控制台错误、顶栏无溢出。

## 1. v1 回望：哪些承诺兑现了，哪些变成了新摩擦

### 1.1 已兑现的部分

| v1 承诺 | 当前实现 | 评价 |
| --- | --- | --- |
| 政令槽 | 每城 `min(4, 2 + 在城武将/3)`，月结重置 | 规则成立，但操作仍然逐城 |
| 项目制内政 | 屯田 / 市集 / 城墙 / 兵营，2 个营造位，按月推进 | 有长期投资感，但入口埋在城池面板 |
| 国策 | 每 3 回合三选一，8 张路线牌 | 有 build 身份，但缺少“为什么现在选它”的上下文 |
| 事件 | 蝗灾 / 商队 / 流民 / 名士，2–3 个取舍 | 有故事点，但和月度议程是两条线 |
| 探索 | 1–3 个月派遣、方向选择、线索链 | 搜索从连点变成投资，方向正确 |
| 战斗军令 / 夹击 / 托管 | 3 点军令、夹击增伤、AI 托管与接管 | 战术表达足够，但缺少战斗目标 |
| 章节 | 城池 / 兵力 / 府库三项目标，达成奖励 | 有短期目标，但还不是“幕” |
| 移动端 | 响应式布局、地图缩放、弹窗适配 | E5 修掉了顶栏溢出和地图不可读 |

### 1.2 新摩擦：系统并行，缺少议程

v1 的每个系统都解决了自己的问题，但它们没有回答同一个问题：

> **“现在是第 3 个月，我有 8 道政令、2 座城、1 个邻敌，我到底先做什么？”**

当前玩家需要自己把国策、事件、项目、探索、章节、粮草、忠诚、边境压力拼在一起。  
这不是“策略深度”，而是**信息整合成本**。现代玩家不是不愿意思考，而是不愿意先做一份 Excel。

### 1.3 第二个新摩擦：战斗没有问题

当前战斗的战术层是够的：

- 12×8 地形、ZOC、六兵种相性；
- 火攻 / 水计 / 混乱 / 治疗 / 落石；
- 军令、夹击、伤害区间、威胁范围、移动撤销；
- 30 天撤退、俘虏、守城回血。

但每场战斗的“题目”几乎一样：**把对面打完，或者被对面打完。**  
地形和天气提供的是“怎么打”，没有提供“为什么打、打到什么程度算赢”。  
所以玩家会记住一次漂亮的火攻，却很难记住“这一战我为什么非打不可”。

### 1.4 第三个新摩擦：章节是数字，不是幕

章节目标（城池 / 兵力 / 府库）能给短期方向，但它没有：

- 一个明确的“这一幕结束了”的时刻；
- 一次改变局势的“转折战”；
- 一个让玩家选择“下一幕我要成为什么样的势力”的节点；
- 后期清理残局的快进手段。

结果是：前 10 小时有目标，后 10 小时只剩清城。

### 1.5 第四个新摩擦：有风格，没有层级

视觉上，金色、红色、青色都在表达“重要”：

- 金色既做装饰，又做主要按钮；
- 红色既做势力色，又做危险提示；
- 顶栏主操作和次要操作同权重；
- 手机端 390px 下，顶栏按钮溢出，地图城池重叠。

E5 先修了最影响操作的三件事：**主按钮语义、手机顶栏收纳、地图可读性**。  
E8 会把“层级”做成一套可复用的规则，而不是继续打补丁。

## 2. v2 的设计原则

v1 的五条原则仍然成立：决策 > 操作、透明 > 惊喜、短局 > 长跑、风格 > 高清、经典 > 魔改。  
v2 在此基础上增加四条更具体的执行原则：

1. **一个入口，一个动作。**  
   每个核心循环只保留一个主入口；玩家不需要记住“这件事在哪个面板”。
2. **建议必须可预览、可拒绝、可解释。**  
   军师可以给建议，但不能替玩家承担后果；预览清单必须和执行结果一致。
3. **自动化只做“重复”，不做“取舍”。**  
   内政政令可以委任；征兵、交易、外交、出征、决战必须由玩家决定。
4. **每场战斗必须有题目，每局必须有幕。**  
   没有题目的战斗是消耗，没有幕的长局是疲劳。

## 3. 支柱一：一屏一月

### 3.1 定义

> 在一个屏幕内，玩家能完成“看局势 → 选倾向 → 预览 → 执行”的月度治理闭环。

“一个屏幕”不是字面意义上所有信息都塞进 390×844，而是：

- **首屏**能看到本月最紧急的一件事、政令余量、府库、可出征方向；
- **一次点击**能进入完整朝议；
- **一次确认**能完成全部内政委任；
- 需要手动微调时，能一键跳到对应城池，而不是重新找入口。

### 3.2 三层信息结构

| 层级 | 位置 | 回答的问题 | 内容 |
| --- | --- | --- | --- |
| **T1 军师条** | 地图上方，常驻 | 这个月最该先做什么？ | 一条主建议 + 政令 / 可出征 / 府库 |
| **T2 朝议** | 顶栏按钮 / `G` | 为什么？还有哪些风险？ | 三张奏折 + 风险 chips + 施政倾向 + 委任预览 |
| **T3 城池面板** | 点击城池 | 具体到这座城怎么调？ | 原有内政、营造、探索、征兵、交易 |

T1 不替代 T2，T2 不替代 T3。  
军师条负责“叫醒玩家”，朝议负责“做决定”，城池面板负责“手动修正”。

### 3.3 朝议的规则边界

朝议只做一件事：**把本月剩余的内政政令，按玩家选择的倾向排成一份可预览的清单。**

它明确不做：

- 不自动征兵；
- 不自动交易；
- 不自动外交；
- 不自动出征；
- 不自动使用搜索 / 探索；
- 不碰经典模式。

原因很简单：这些是“战争决策”，不是“重复操作”。  
一旦自动征兵，玩家就不需要判断“这个月是补兵还是补粮”；一旦自动出征，游戏就变成了看报表。

### 3.4 四种施政倾向

| 倾向 | 定位 | 权重方向 | 适合 |
| --- | --- | --- | --- |
| **均衡** | 农商并重 | 商业略高，开垦 / 出巡 / 治理轮换 | 不确定走哪条路 |
| **农本** | 仓廪为先 | 开垦、出巡 | 粮草吃紧、长期种田 |
| **备战** | 训练与军粮 | 演武、开垦 | 边境承压、准备出征 |
| **安民** | 忠诚与城防 | 出巡、治理 | 新占城、灾害后、叛乱风险 |

倾向不是“难度选项”，而是**同一局势下的不同解法**。  
同一个 2 城开局，农本第一道是开垦，备战第一道是演武；玩家能立刻看出差别。

### 3.5 委任算法（已实现）

`src/systems/council.ts` 是纯函数层，预览和执行共用同一份结果：

1. 按风险给城池排序：断粮 > 低忠诚 > 低城防 > 边境压力。
2. 每城按剩余政令逐条挑选；每条命令的分数 =
   - 倾向权重；
   - `+ 属性收益 × 1.6`；
   - `+ 情境加成`（粮草 < 2 月、民忠 < 45、城防 < 45、邻敌 > 1.2 倍等）；
   - `− 同城同命令重复次数 × 9`（避免一个月四次开垦的“复读”）。
3. 每城保留 **80 金**应急，避免一键花光征兵 / 交易的钱。
4. 只使用剩余政令、可用武将体力、未达上限的属性；任何一条不满足就跳过。
5. 预览清单就是执行清单；执行时逐条调用 `doDomestic(..., silent)`，最后只写一条汇总日志。

### 3.6 为什么是 80 金

80 金不是精确平衡值，而是一个**行为护栏**：

- 它足够让玩家在委任后还能做一次紧急征兵或交易；
- 它又足够低，不会让委任变成“什么都不花”；
- 它按城计算，避免小城被大城吸干。

后续如果加入“委任预算”滑块，80 金可以变成默认值，而不是硬编码。

### 3.7 手机端

- 朝议在 390px 下变为全屏 sheet，统计区固定可见，奏折横向滑动；
- 顶栏只保留“朝议 + 结束回合”，其余收进“更多”；
- 地图默认 2.1× 缩放，支持拖拽、滚轮、`+ / − / 全图`；
- 地图图例在手机端隐藏，避免和城池标签争空间。

## 4. 支柱二：一战一题

> 状态：E6 已落地。范围收口为破城 / 守城、斩将、截粮 / 护粮三类；护送与关隘顺延。

### 4.1 定义

每场战斗在部署前，必须让玩家看到一个明确的问题：

- “这一战，我能不能在 8 天内破城？”
- “我能不能保住粮道？”
- “我能不能在敌军援军到达前斩将？”
- “我能不能守住这个渡口 5 天？”

这个问题不是背景文字，而是**改变部署和战术选择的规则**。

### 4.2 五类战斗题目

| 题目 | 攻方目标 | 守方目标 | 设计作用 |
| --- | --- | --- | --- |
| **破城** | 在 N 天内占领城池 | 坚守 N 天 | 让 30 天限制真正进入决策 |
| **斩将** | 击溃指定敌将 | 保护主将撤退 | 让“集火”有明确回报 |
| **守关** | 占领并守住关隘 / 渡口 | 夺回关隘 | 让地形点成为胜负手 |
| **截粮** | 占领粮仓 / 摧毁辎重 | 护送粮队 | 让机动和埋伏有价值 |
| **护送** | 护送指定单位到出口 | 拦截护送队 | 让“保护”成为独立玩法 |

### 4.3 题目如何生成

题目不是随机抽卡，而是从战役上下文推导：

- 攻方 / 守方身份；
- 城池规模与城防；
- 双方主将特性（骑兵、水军、军师）；
- 地形与天气；
- 当前章节幕（立足期偏“守”，争锋期偏“斩将 / 截粮”，定鼎期偏“破城”）；
- 是否历史剧本关键城（赤壁、官渡、夷陵等可手写专属题目）。

同一局内用固定种子，保证读档后题目一致。

### 4.4 展示与反馈

- **部署界面**：主目标 + 支线目标 + 奖励 + 失败代价，一屏可见；
- **战斗 HUD**：主目标常驻，进度用“天数 / 点位 / 目标单位”表达；
- **结算**：主目标成功 / 失败、支线完成、额外奖励，写进战报；
- **托管**：AI 的战术评分必须带目标权重；托管不能只顾杀敌而丢掉目标点；
- **失败**：主目标失败不一定直接战败，但会改变战后结果（例如撤军、损兵、敌将逃脱）。

### 4.5 设计约束

- 不增加第二种“游戏结束条件”；主目标与现有胜负兼容。
- 支线目标永远可选，不阻塞主线。
- 不引入新货币；奖励用金、粮、经验、道具、声望。
- 每场只给一个主目标，最多一个支线；多了就变成清单。
- 经典模式不启用战斗题目，保留原版“打完 / 撤退”。

### 4.6 验收

- 100% 的玩家战斗有可见主目标；
- 70% 玩家战后能复述“这一战我要做什么”；
- 30% 的战斗因目标不同而改变部署（不只换奖励文字）；
- 典型战斗 6–12 回合；
- 1.8:1 攻城胜率保持 50–60%。

### 4.7 E6 落地记录

**范围**：现代模式、玩家参战的战斗，100% 有一个主目标；最多一个支线。经典模式保持原版，不生成题目。

| 层级 | 已实现 |
| --- | --- |
| 数据模型 | `BattleObjective`：`capture` / `hold` / `decapitate` / `supply`，含期限、目标单位 / 点位、奖励、可选标记 |
| 生成 | `planBattleObjectives` 纯函数；按攻守身份、兵力比、城防、城池规模计算期限；固定种子 + `battleSerial`，不消耗战斗随机流 |
| 主目标 | 攻方「破城」：第 N 天前占领；守方「守城」：坚守至第 N 天。仍以原胜负为准，不增加第二种游戏结束条件 |
| 支线 | 「斩将」集火指定敌将；「截粮 / 护粮」争夺 12×8 战场右侧粮仓点 |
| 部署预览 | 出征弹窗顶部显示主目标、支线、达成奖励；与 `createBattle` 共用同一生成函数，预览 = 实战 |
| 战棋 HUD | 顶部常驻主目标 / 支线，显示天数、目标单位兵力或粮仓状态；粮仓点位在战场 Canvas 标记，悬停可读 |
| 结算 | 战报新增「战令 / 支线 / 战利」；达成发金、粮、经验；失败只失去额外战利，不扣兵、不改变胜负 |
| 托管 | `objectiveTargetPriority` 提升斩将目标攻击权重；`objectiveMoveScore` 引导 AI 向粮仓 / 斩将目标靠拢 |
| 存档 | 新战斗题目随 `BattleState` 入档；旧战斗存档迁移时按当前上下文补题；经典模式不补 |
| 测试 | 新增 18 项：生成确定性、预览一致、主目标期限成功 / 失败、守城、斩将、截粮、移动标记、迁移、托管权重、经典模式 |

**经验**：把主目标做成「现有胜负 + 期限 / 奖励」而不是新胜负条件，才能在不破坏 30 天撤退和指挥官溃散规则的前提下，让部署真正因题目改变。

**下一刀**：E7 把章节改造成三幕；E8 再统一战斗 HUD 与部署弹窗在移动端的信息层级。

## 5. 支柱三：一局三幕

> 状态：E7。先把现有章节系统改造成三幕，不另起一套。

### 5.1 三幕结构

| 幕 | 月份 | 玩家问题 | 核心系统 | 退出条件 |
| --- | --- | --- | --- | --- |
| **第一幕 · 立足** | 1–12 | 我能不能活下来，并找到第一个立足点？ | 朝议、项目、探索、第一场守城 | 控制 2–4 城，或完成一次关键防守 |
| **第二幕 · 争锋** | 13–36 | 我要和谁结盟、先打谁？ | 国策、外交、斩将 / 截粮战、转折战 | 控制 40% 城池，或击败一个强敌 |
| **第三幕 · 定鼎** | 37+ | 我能不能在天下大局中收尾？ | 破城战、劝降、大势已定快进 | 统一，或达成割据结局 |

### 5.2 幕间节点

每一幕结束时，给玩家一次“幕间朝议”：

- 三张**幕间选择**（不是普通国策）：例如“休养生息 / 整军经武 / 远交近攻”；
- 一个明确的**转折战**：历史城、关键敌将、粮道节点；
- 一次**势力身份确认**：种田、贸易、军事、外交，给下一幕一个 build 方向；
- 一份**幕报**：这一幕做了什么、失去什么、下一幕的建议。

### 5.3 后期清城

第三幕提供两种快进，但都不是“自动推图”：

1. **大势已定**：当城池 / 兵力差距超过阈值，弱势力可主动劝降，直接接管；
2. **委任出征**：只对“兵力比 ≥ 3:1 且无援军”的城开放，结果可预览，玩家确认后结算。

强敌、关键城、历史城仍然必须手动打。  
自动化的边界依然是：**只做重复，不做取舍。**

### 5.4 验收

- 60–70% 的玩家能完成第一幕；
- 20–40 分钟的会话内，至少经历一次“幕内目标达成”；
- 第二局开局率 ≥ 30%；
- 后期单城清理时间下降 50%，但关键战仍然手动。

## 7. E5 已落地记录：朝议 / 军师

### 7.1 问题

本轮开始前的实测：

- 2 城开局，玩家要先看城池列表，再逐城打开面板，判断“开垦还是招商”；
- 每月 5–8 道政令，每道都要选城、选将、选命令；
- 粮草、忠诚、边境压力分散在不同面板，玩家很难在 30 秒内形成“本月议程”；
- 手机端顶栏按钮溢出，地图 61 城重叠，主操作被“存档 / 武将 / 主菜单”淹没。

### 7.2 方案

| 层 | 实现 |
| --- | --- |
| **军师条** | 地图上方常驻，显示最紧急奏折、政令余量、可出征城数、府库 |
| **朝议弹窗** | 五项统计 + 三张奏折 + 风险 chips + 四种倾向 + 委任预览 + 执行 / 取消 |
| **委任规则** | 只用剩余政令；每城保留 80 金；跳过体力 / 属性 / 金钱不足的命令 |
| **执行** | `AUTO_GOVERN` 动作，预览与执行共用纯函数；只写一条汇总日志；失败命令返回 warnings |
| **经典模式** | 顶栏隐藏朝议；reducer 拒绝；不改变原版规则 |
| **快捷键** | `G` 打开朝议；帮助面板同步 |
| **手机端** | 朝议全屏 sheet；奏折横向滑动；顶栏“更多”收纳次要操作 |
| **地图** | 手机默认 2.1×；拖拽平移；滚轮缩放；`+ / − / 全图`；选中城跟随 |
| **语义** | 金色主按钮；红色只做危险 / 破坏性操作 |

### 7.3 玩家看到什么

以 208 赤壁 / 刘备开局为例：

- 2 座城，8 道政令；
- 均衡倾向生成 5 道政令，预计消耗 360 金；
- 每道政令显示：城名、执行武将、命令、收益、理由、金币；
- 底部显示“预计消耗 / 执行后约余”；
- 执行后只出现一条汇总日志：“朝议（均衡）：2 城 5 道政令已下达，耗 360 金”。

玩家仍然可以：

- 关闭朝议，手动逐城下令；
- 换一个倾向看不同清单；
- 点击奏折 / 城池名跳到对应城；
- 只执行一部分（当前版本通过手动下令实现；后续可加勾选）。

### 7.5 测试证据

`tests/council.spec.ts` 覆盖：

1. 同一局势、同一倾向结果确定，且不修改原状态；
2. 受本月政令上限约束，并保留 80 金应急；
3. 农本先开垦、备战先演武；
4. 金钱低于应急金时不自动花掉最后一点钱；
5. 全势力委任覆盖所有己方城池，且不超过各城政令余量；
6. 经典模式不提供委任；
7. 奏折固定为粮草 / 军备 / 人才三张，统计值有限；
8. 每张奏折都有明确语气与下一步动作；
9. `AUTO_GOVERN` 按预览执行全部政令，只写一条汇总日志；
10. 政令已用尽时拒绝执行，状态引用不变；
11. 经典模式拒绝朝议；
12. 预览收益与实际执行一致，包含属性上限截断与同城连令。

全量结果：

- **E5 落地时 32 个测试文件 / 277 项测试全绿**（合并 E6 后全量为 33 个文件 / 295 项）；
- `npm run typecheck` 通过；
- `npm run build` 通过；
- Playwright 1440 / 390 实测：无控制台错误、顶栏无溢出、朝议统计可见、地图 210% → 245%、拖拽生效。

### 7.6 本轮刻意没做

- **没有自动征兵 / 交易 / 外交 / 出征**：这些是决策，不是重复操作。
- **没有做“勾选部分政令”**：先验证“一键委任”是否被接受，再决定是否加细粒度控制。
- **没有做委任预算滑块**：80 金是行为护栏，不是最终平衡值。
- **没有做战斗目标**：E6 单独做，避免朝议和战斗同时改动导致归因困难。
- **没有做真实玩家埋点**：当前只有开发模式点击统计；E5 的 adoption 指标需要下一轮 playtest 验证。

## 8. E5–E9 路线图

> v2 的阶段编号接在 v1 的 E1–E4 之后。E5、E6 已交付；E7–E9 按“先长局、再表现、最后长线”的顺序推进。

| 阶段 | 周期 | 支柱 | 交付 | 验收 |
| --- | --- | --- | --- | --- |
| **E5 朝议** | 已交付 | 一屏一月 | 军师条、朝议、四倾向、委任预览、手机顶栏 / 地图 | 2 城 5 令 2 次操作；经典模式 0 泄漏 |
| **E6 一战一题** | 已交付（MVP） | 一战一题 | 破城 / 守城、斩将、截粮 / 护粮、部署预览、战斗 HUD、目标奖励、托管目标权重 | 现代玩家战斗 100% 有主目标；经典模式 0 泄漏；预览 / HUD / 战报一致 |
| **E7 一局三幕** | 3 周 | 一局三幕 | 三幕章节、幕间选择、转折战、幕报、大势已定 / 委任出征 | 一幕完成率 60–70%；后期清城时间 −50% |
| **E8 一眼一等** | 2 周 | 一眼一等 | 四档响应式、颜色语义审计、信息层级、战棋移动端、键盘路径 | 390/768/1024/1440 无溢出；首屏有主 CTA |
| **E9 长线** | 3 周 | 一局三幕 + 长线 | 图鉴、成就、挑战 modifier、NG+、战报分享 | 第二局开局率 ≥30%；图鉴完成度分布合理 |

### 8.1 E6 已交付的最小可行版本

不做五类全上，先做三类最能改变部署的（已按下列顺序完成）：

1. **破城 / 守城**：把 30 天限制变成主目标；
2. **斩将**：让集火和护卫有明确回报；
3. **截粮 / 守点**：让机动和地形点成为胜负手。

实现顺序：

1. `BattleObjective` 数据模型 + 从战役上下文生成（纯函数 + 固定种子）；
2. 部署界面显示主目标 / 支线 / 奖励；
3. 战斗 HUD 显示进度；
4. 结算与战报归因；
5. 托管评分加入目标权重；
6. 测试：生成确定性、目标达成 / 失败、托管不丢目标、经典模式无目标。

### 8.2 E7 的关键判断

三幕不是“再加三个章节”，而是**把现有章节改造成有开始、转折、结束的叙事单元**。  
如果 E7 做完，玩家仍然只记得“我占了 40% 城”，那就说明幕间选择只是换皮，需要回炉。

### 8.3 E8 的关键判断

E8 不是“再美化一次”，而是**建立一套信息层级规则**：

- 任何新面板必须先回答“它属于 T1/T2/T3/T4 哪一层”；
- 任何新按钮必须先回答“它是前进、危险、还是次要”；
- 任何移动端布局必须先回答“主 CTA 是否在首屏”。

## 10. Playtest 方案

### 10.1 样本

- 5 名新玩家（没玩过原版，玩过至少一款策略游戏）；
- 3 名老玩家（玩过原版或同类三国策略）；
- 每人 45 分钟，208 赤壁 / 刘备开局；
- 观察 + 出声思考 + 事后访谈。

### 10.2 任务

1. 说出“这个月最该做什么”，并解释依据；
2. 打开朝议，选一个倾向，预览并执行；
3. 结束回合，进入下一月；
4. 打一场战斗，战后复述“这一战的目标是什么”；
5. 说出“下一局想试什么不同路线”。

### 10.3 记录

- 首次打开朝议的时间；
- 朝议使用率 / 手动补令率；
- 每月点击；
- 战斗目标复述准确率；
- 战斗部署是否因目标改变；
- 卡住的位置与原因；
- 对“军师建议”的信任度（1–5）。

### 10.4 判定

- 如果玩家能在 30 秒内说出本月议程，E5 成立；
- 如果玩家主动使用朝议、且之后仍会手动微调，E5 健康；
- 如果玩家把朝议当成“唯一正确解”，E6 之前先调低自动化边界；
- 如果玩家战后说不出目标，E6 不算完成。

## 11. 风险与不做清单

| 风险 | 表现 | 对策 |
| --- | --- | --- |
| 过度自动化 | 玩家变成看报表 | 只委任内政；保留 80 金；征兵 / 外交 / 出征必须手动 |
| 军师误导 | 建议和玩家判断冲突 | 每张奏折给理由；预览可拒绝；不隐藏代价 |
| 朝议变墙 | 手机端一屏塞满文字 | 三张奏折 + 风险 chips + 横向滑动；详情跳城池 |
| 战斗目标变清单 | 每战五六个目标 | 一主一支；目标必须改变部署，不只改奖励 |
| 三幕变换皮 | 幕间只是多一个弹窗 | 幕间必须有转折战与身份选择；否则回炉 |
| 移动端补丁化 | 每个面板单独适配 | E8 建立四档布局与层级规则 |
| 经典模式被侵蚀 | 现代机制泄漏 | reducer 层拒绝 + 测试 + UI 隐藏 |
| 范围蔓延 | 系统越加越多 | 每个新系统必须回答“它让哪个月的决策更有趣” |

**不做**：抽卡、体力、日常、强制在线、写实 3D、全程配音、即时战斗、自动推图、付费数值、经典模式规则改动。

## 12. 一句话总结

> v1 让《三国霸业》重新拥有现代策略游戏的骨架；  
> v2 要把这副骨架收成一个动作：**打开游戏，先听军师说一句，再做三个决定，然后打一场有题目的仗。**
>
> 像素可以更精致，操作可以更顺手，但“用一座城撬动天下”的逆袭感，必须原样保留。
