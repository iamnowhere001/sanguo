# 后勤与城池耐久 v1

> 起因：四条来自实机的反馈 —— 城池守将太少、兵力绑死在将领身上、城池没有「被打穿」的概念、调将可以一城接一城瞬间投送。
> 本文记录这四项的设计裁决与落地位置，数值真值源仍在 `src/data/tables/balance.ts`。
> 计数口径：本文写作时为 61 城；阳平关 / 濡须口 转为关防后为 59 城，机制与数值不变。

## 1 · 守将铺满：338 名武将

**问题**：主表 174 人分摊到 59 城，平均不到 2 人；208 赤壁的曹操二十多座城，名将集中在几个大城，边缘小城常年 0 将 —— 内政、征兵、守城全部停摆。

**裁决**：人物表分两层。

| 层 | 文件 | 内容 |
| --- | --- | --- |
| 名将主表 | `data/tables/generals.ts` | 174 人，剧情锚点与主力，208 默认驻城 |
| 补位表 | `data/tables/generalsExtra.ts` | 164 人，按势力分组，默认 `inactive` |

建局时 `createGame` 调 `fillGarrisons`：按「缺将数从多到少」把本势力的补位将领摊进各城，直到每城达到 `BALANCE.GARRISON.MIN_GENERALS_PER_CITY`（=2）。

实测（四个剧本，59 座有主城池）：

| 剧本 | 登场武将 | 均 | 不足 2 将的城 |
| --- | --- | --- | --- |
| 189 董卓弄权 | 132 | 2.2 | 0 |
| 200 曹操崛起 | 134 | 2.2 | 0 |
| 208 赤壁 | 148 | 2.4 | 0 |
| 220 三国鼎立 | 124 | 2.0 | 0 |

**防呆**：`EXTRA_GENERALS` 与主表 id 冲突会被对象展开静默吞掉（主表条目直接消失），
因此在建表时就抛错；补位表内部的重复 id 同样在模块加载时抛错。

## 2 · 兵力属于城池

**问题**：`General.troops` 既是「驻军」又是「出征部队」，兵力无法集中、无法运输，征兵也被单将带兵上限卡死。

**裁决**：新增 `City.troops` = **未分配兵力池**。

```
城池总驻军 = City.troops（池） + Σ 在城武将 troops（已分配）
```

| 场景 | 行为 |
| --- | --- |
| 征兵 | 先补给执行武将，超出其带兵上限的部分进池；受城池驻军上限约束 |
| 批量征兵 | 按带兵缺口分给全城，余量进池 |
| 分配 | `ASSIGN_TROOPS`（单将，正数领兵 / 负数交回）、`ASSIGN_TROOPS_ALL`（全城） |
| 出征 | `createBattle` 先按武力从高到低从池里补满参战武将，再判「无兵可战」 |
| 守城 | 同上：目标城的池兵会由守将带上城墙 |
| 月粮 | 池兵同样吃粮，断粮时同样逃亡（堵住「把钱粮换成池兵」绕过后勤） |
| 无将城池 | 池兵随城溃散 —— 兵无将则散，不给「有兵无将」的城当刷兵容器 |

唯一真值源：`src/systems/troops.ts`（`troopCapOf` / `poolOf` / `topUpFromPool` / `projectedTroops` / `withdrawTroops`）。
`projectedTroops` 是「若现在分配，各将会带多少兵」的纯计算版，AI 评估与出征预览共用，保证**预览 = 实战**。

## 3 · 城际运输

`TRANSPORT { fromCityId, toCityId, gold, food, troops }`

| 约束 | 值 |
| --- | --- |
| 范围 | 相邻己方城池（与调将同一套邻接约束，不允许中转站） |
| 政令 | 现代模式 1 点（出发城），经典模式 0 |
| 单次兵力上限 | `BALANCE.GARRISON.transportMaxTroops` = 6000 |
| 目标驻军 | 不得使目标城超过规模上限 |
| 兵力来源 | 先扣池，不足部分由守将按兵力从小到大分兵 |

到达后兵力先进目标城池，再按带兵余量自动分给守将，剩余留在池里。

## 4 · 城池耐久

**问题**：原本只有「守军全灭」一条陷城路径，城墙只是个减伤数字，守方缩在城里硬顶时缺少明确出口。

**裁决**：`City.durability`，上限由纯函数给出：

```
上限 = base[规模] + 城防 × 6 + 城墙工程 260
      capital 1200 / large 900 / medium 650 / small 450
```

| 规则 | 值 / 位置 |
| --- | --- |
| 攻城磨损 | 攻方部队**站在城池格上**，每日 `troops × 0.12 × (1 + 武力/200)`（`battle/siege.ts`） |
| 城破判定 | `battleOutcome`：`cityDurability <= 0` → 攻方胜；与「驻守兵力为 0」并列 |
| 月结修复 | 有主城池每月回补上限的 12%（`logistics.runCityRepair`） |
| 城池易主 | 耐久回落到上限的 30% |
| 展示 | 城池面板「城墙耐久」进度条 + 属性条；战棋 HUD 城墙条 + 攻城提示 |

**为什么不是「攻方入城即胜」**：守方 8 个出生位里只有 4 个在城池格上，清掉城内守军后攻方才能站住，
此时城外残兵仍可反扑 —— 攻城变成一个「占住城内、顶着反扑磨墙」的独立阶段，而不是瞬间结算。

## 5 · 每月行军一次

**问题**：`doMoveGeneral` 只校验「相邻」，玩家可以 A→B→C→D 在同一回合内连续调将，
等于绕过整条补给线把部队瞬间投送到地图另一端。

**裁决**：`General.marchTurn` 记录最近一次行军回合，`marchTurn >= turn` 即本月不能再动。

- 调将、出征都计入（`createBattle` 成功后写 `marchTurn`）；
- AI 的 `applyStrategicMove` 走同一条约束；
- UI 在武将行显示「本月已行军」并隐藏调往下拉。

`BALANCE.GARRISON.movesPerTurn = 1` 保留为可调项。

## 6 · 存档兼容

| 字段 | 旧档处理（`save/migrate.ts`） |
| --- | --- |
| `City.troops` | 缺省 0（旧档兵力都在将领身上） |
| `City.durability` | 按当前上限的 80% 补齐 |
| `BattleState.cityDurability(Max)` | 按目标城当前耐久补齐；缺失时不参与攻城磨损 |
| `General.marchTurn` | 缺省视为未行军 |
