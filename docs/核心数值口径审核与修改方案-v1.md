# 核心数值口径审核与修改方案 · v1

> **状态：已归档（2026-10-30）。现行版本见 [核心数值口径审核与修改方案-v2.md](./核心数值口径审核与修改方案-v2.md)。**
> 归档原因：本版对移动单位（格/点）、城距统计、攻城耐久基线与守方回血的判断存在事实与推导错误，
> 且未覆盖操作体验、水路航行与 `MapEdge.cost` 口径冲突。v2 已逐条复核并替代本版，本文仅作历史留档。
>
> 审核对象为 [核心数值总表-v2.html](../核心数值总表-v2.html)；
> 数值真值源仍是 `src/data/tables/`，本文只审「口径」与「与《三国志11·威力加强版》的对齐度」，不新立数值。

## 0. 结论

1. 引擎本身已是旬回合制（`src/systems/economy.ts:44`「一回合 = 一旬（10 天），3 旬为一月」）；**问题出在总表把引擎内部的「天」当成对外单位**，不是引擎错。
2. v1 草案的最大错误：把「天」改叫「移动点」却保留 1:1 数值。**1 点就是 1 格**，改名等于没改，还把「平原 1 点」变成了病句（一格耗一格）。本版改为直接以 **「格 / 旬」** 为单位。
3. 与三11 相比缺三样核心机制：**兵种适性（S/A/B/C）、部队气力（士气）、武将特技**；兵器部队整体缺失。
4. 一个模型级偏差：**兵力被写成武将属性**（`src/data/schema.ts:38`），三11 里兵在都市/部队。
5. 一个未在 v1 发现的量级问题：**攻城磨损 0.12 / 兵 / 日 会让 2,000 兵约 6 天打穿都城**（耐久约 1,940），30 回合的战斗上限根本用不上。这不是单位问题，是数值失衡。
6. 一个未在 v1 发现的口径问题：**行军层所有兵种速度相同**（`src/systems/army.ts:937` 的 `speed` 只含烽燧加成），三11 是骑兵快于枪兵。

## 1. 审核基准（三11 核心模式）

| 维度 | 三11 口径 | 本项目现状 |
|---|---|---|
| 时间 | 1 年 = 36 旬，1 月 = 3 旬；所有命令以旬为单位 | 引擎已是旬制，总表仍暴露「天」 |
| 行军单位 | 每旬一个移动力预算，单位为格；地形按倍率吃格 | 内部按「天」计费，1 天 = 1 格 |
| 行军速度 | 按兵种分档（骑兵快、步兵慢） | 全兵种统一 10 格/旬，仅烽燧加成 |
| 部队 | 主将 + 最多 2 副将；兵力归部队 | 武将自带 `troops`，副将未进表 |
| 兵种 | 枪 / 戟 / 弩 / 骑 / 兵器 / 水军 6 类 | 步兵 / 骑兵 / 弓兵 / 水兵 / 极兵 / 玄兵 |
| 兵种适性 | 每将每兵种 S/A/B/C，决定攻防与战法成功率 | 无适性；用 6×6 相性矩阵 |
| 士气 | 部队「气力」0–100，影响攻击，归零溃败 | 无；只有「训练度」 |
| 特技 | 每将 1 条特技 | 无；只有城池专属技能 |

| 攻击距离 | 近战 1 格；弩兵 2 格；井阑/投石 2–3 格 | 弓兵 2–3 格，其余 1 格 |
| 战斗发生地 | 大地图无缝，不切场景 | M 档：行军 + 场景战棋（需标注为设计分叉） |
| 内政 | 设施建设，逐旬进度 | 命令直加数值 + 4 种大地图设施 |

## 3. 修改方案

### 3.1 方案 A′（推荐）：单位定为「格 / 旬」，并按兵种分档

**规则**：所有移动量以「格」计，所有预算以「旬」计；表中禁止出现「天」，也禁止用「点」代替「格」。

1. **新增 §0「时间与移动单位规范」**：
   `1 旬 = 10 格预算`；`1 月 = 3 旬`；`1 季 = 9 旬`；`1 年 = 36 旬`。所有数值列强制带单位。
2. **地形消耗**（进入该格所需预算，数值不变，只换单位）：

   | 地形 | 消耗 |
   |---|---|
   | 平原 | 1 格 |
   | 林地 / 丘陵 / 荒漠 | 2 格 |
   | 沼泽 | 3 格 |
   | 山岭 / 海 / 湖 / 江河 | 不可通行 |

3. **每旬预算按兵种分档**（解决 B9；引擎现为统一 10 格）：

   | 兵种 | 每旬格数 | 相邻城（中位 55 格） |
   |---|---|---|
   | 步兵 / 弓兵 | 10 | ≈5.5 旬 |
   | 水兵（陆行） | 10 | ≈5.5 旬 |
   | 骑兵 | 14 | ≈3.9 旬 |
   | 极兵 | 16 | ≈3.4 旬 |
   | 玄兵 | 8 | ≈6.9 旬 |

   若判断战役节奏过慢，将基线整体抬到 15 格/旬（步兵相邻城 ≈3.7 旬），属全局改速，见 §7 X7。

4. **关隘**：关口本身 1 格；**排队费 +2 格**（大关 +3 格），标注为「耗时不是路程」。敌对时封锁通行线，必须破关。
5. **渡口**：陆军不能沿江面步行，**跳江传送费 = 2 + ⌈江面宽/4⌉ 格（现表算出 5–7 格 ≈ 半旬）**，且强制进入水战。必须写明这是传送费，不是航程。
6. **小路**：绕行费 +4–7 格（≈0.4–0.7 旬），不可驻守、不封锁。总表现值「4–6」与 `balance.ts:91` 的 `[4,7]` 不一致，以代码为准。
7. **战斗**：单场上限写「3 旬（30 回合）」，脚注「1 回合 = 1 天，仅内部结算」；守方回血改「每旬 3%」；攻城磨损见 3.3。
8. **项目 / 体力**：项目写 9 旬 / 6 旬；体力写「每旬 +7（7/7/6，月合计 20）」，与原值等值。
9. **经济分层**：每旬扣军粮 / 每月产粮 / 每 9 旬收税，三行分别标层级，禁止同格混写。

### 3.3 攻城时长的重新推导（A9 的解法）

目标是「2,000 兵打都城需 2–3 旬」，与 30 回合上限、月修 12% 自洽：

- 都城耐久 ≈ 1,940（含城墙工程），2–3 旬 = 20–30 天
- 需要日均 65–97，折合每兵每日 **0.032–0.048**
- 取 **0.04**：2,000 兵 / 武力 80 → 112/日 → 17 天（≈1.7 旬）；3,000 兵 → 11 天
- 小城 690 耐久：1,000 兵 → 8.6 天，符合「小城可速下」

若不想改公式，替代方案是把耐久整体 ×10（都城 ≈19,400），但玩家看到的耐久会变成五位数，读感差。建议改磨损。

### 3.4 方案 B（保守，零代码）

引擎继续用「天」做内部预算，只在总表与 UI 文案折算成「格/旬」：
- 「尚余 X 日路程」→「尚余 X 格（约 Y 旬）」；
- 每张表加脚注「本表以格/旬计，引擎内部按天结算」。
优点：无回归风险；缺点：两套口径长期并存。

### 3.5 方案 C（不建议现在做）

大地图无缝战斗 + 6 兵种 + 适性/气力/特技/兵器。属玩法级重写，会推翻 M 档与 338 将配表，拆到独立迭代（见 §4）。

## 6. 验收标准

1. 全文检索「天」：只允许出现在 §04 脚注「1 回合 = 1 天」。
2. 全文检索「点」：不允许作为移动单位出现；移动单位统一为「格」。
3. 每个数值列带单位，且能回答「这是一旬内的，还是一月的」。
4. 1 月 = 3 旬、1 年 = 36 旬可在表内自洽验算；相邻城行军旬数可用「格距 ÷ 每旬格数」手算验证。
5. 渡口规则一句话可判定：过江 = 跳江 5–7 格 + 强制水战。
6. 攻城时长可验证：2,000 兵打都城应为 2–3 旬（1,940 耐久 ÷ 112/日 ≈ 17 天）。
7. 相性/地形/训练叠乘有显式上限（建议 2.0×），表内写明。
8. 统计口径唯一：登场 / 全名册 / 在野 三档各自标注。
9. 测试全绿，`npm run verify`（typecheck → test → map:check → map:gates → contrast:check → build）通过后再合并。
