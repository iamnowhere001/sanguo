# 战斗 AI 行为诊断与改造方案 v1

> 状态：**选项 A + B 已实施**（2026-10-23）。选项 C 未做，列在 §8。
> 目标：让战棋 AI 从「站着挨打」变成「会压上、会集火、会走位、会反应」。
> 范围：`src/systems/battle/` 战棋层为主；大地图 AI（`src/systems/ai.ts`）的被动点列在附录 B，另行处理。
> 证据：`npm run audit:ai` → `reports/ai-audit.csv`（40 个种子 × 6 组对照，双方各 800 兵）。

---

## 0. 结论

**改造前的结论：AI 的第一问题不是「打不过」，是「不打」。**

- AI 作为进攻方，对**完全静止**的守军：40/40 场，30 天 **零出手**，100% 超时撤退。
- 默认档停在距敌 5 格处，此后再也不动；切到「托管激进档」也只推进到距敌 3 格，仍然零出手。近战攻击距离是 1 格。
- 三个设计选择叠加成一个稳定均衡点：
  1. 威胁按「全体敌军满额集火」一次性计入；
  2. 接近收益是线性的（每格 −6）；
  3. 评分器发现「当前格就是最优」时直接返回 `null`。
- 结果：站在威胁圈外一格，分数永远高于「进去挨一下但能打到人」。AI 不是不会评估，是**评估函数把进攻评成了亏本买卖**。
- 次要但同样显眼的问题：敌方 AI **从不花军令点**、计策只按表顺序放、治疗只在「没人可打」时用、没有侧级集火、玩家永远先手。

**改造后（同一审计口径）**：首日接战第 **2** 天，30 天超时率 **0%**，接战后零输出天数 **0**；AI 对 AI 平均 **8.45** 天、双方每天都有输出；攻方每场花 **2.3** 点军令、守方 **3.08** 点，计策 **3.75 / 11.32** 次。详见 §7。

## 1. 改造前的决策流程（基线）

> 本节行号对应改造前的 `ai.ts`，用于说明根因；改造后的代码位置见附录 A。

### 1.1 时序

```
玩家结束回合 (BATTLE_END_TURN, reducer.ts:426)
  └─ runAiTurn: beginSideTurn → 循环 planSideAction 直到无人可动 (ai.ts:266-279)
       └─ 每次只产出一个原子动作，落到战场后重新评估
  └─ battleOutcome 判定
  └─ advanceBattleDay: 天数 +1、守方回血、重置行动、side = playerSide (turn.ts:61-95)
  └─ beginSideTurn(playerSide) (reducer.ts:452)
```

**玩家每天先手**（`turn.ts:93` 强制把行动权交回玩家），AI 永远只能对玩家当天的动作做反应。这是「被动感」的结构性来源之一：AI 没有先手权，也没有「抢先手」的机制。

### 1.2 单个单位的决策树（`planSideAction`, ai.ts:199-236）

| 优先级 | 条件 | 动作 | 代码 |
|---|---|---|---|
| 1 | 当前格能打到敌人 | 极兵**无条件**突击 → 计策（表顺序、成功率 ≥55%）→ 普攻（评分选目标） | ai.ts:208-221 |
| 2 | 打不到，且有友军 <55% 兵力 | 治疗（`heal`，射程 1） | ai.ts:224-227 |
| 3 | 打不到，且本日未移动 | 战术落点（评分） | ai.ts:230-233 |
| 4 | 其它 | 待机 | ai.ts:235 |

行动顺序：射程降序 → 武力降序（ai.ts:189-197）。射程远的先动，本意是「先手计策/射击」，但没有侧级协同。

### 1.3 落点评分（`bestTacticalStep`, ai.ts:77-119）

```
score = 120 × 可攻击
      − 6 × 到最近敌人的曼哈顿距离
      + 30 × (地形修正 − 1)
      − 威胁 × 权重
      + 8 × 城池格
      + 目标加分（粮仓/斩将，objectives.ts:315-336）

威胁 = Σ 每个敌人的预计伤害 × (已行动 ? 0.35 : 1)
敌人筛选：曼哈顿距离 ≤ 移动力 + 最大射程（ai.ts:64-74）
权重：easy 0.2 / normal 0.55 / hard 1.0；残血时再额外扣 threat × 0.4（ai.ts:87, 112）
```

「已行动」折减只在玩家回合结束后生效：AI 行动时玩家单位通常已 `hasActed=true`，威胁 ×0.35。**但折减后仍然压过接近收益**，见下。

## 2. 为什么它会冻结：一次可复现的算术

以审计脚本第 100 号种子为例：曹操军 3 名步兵 vs 守军 5 名步兵，双方各 800 兵，平原。

| 项 | 数值 |
|---|---|
| 步兵一击伤害（800 vs 800，平原，无夹击） | ≈ 92 |
| 5 名守军全部落在前进落点的「移动 3 + 射程 1」威胁圈内 | 威胁 ≈ 460 |
| normal 权重 0.55 | 扣分 ≈ **253** |
| 玩家已行动折减 0.35 后再乘 0.55 | 扣分 ≈ **89** |
| 从距敌 5 格推进到 2 格（3 格）的接近收益 | +**18** |

- 89 仍然是 18 的 **5 倍**。即便按「玩家已行动」打折，进圈依然血亏。
- 威胁按**每个敌人的可达范围阶跃累加**：进入某个敌人的打击圈，就一次性计入它的全额伤害；接近收益却是线性的（每格 6 分）。两者相交处必然产生一个「站在打击圈外一格」的稳定均衡。
- `best.x === unit.x && best.y === unit.y` 时直接返回 `null`（ai.ts:117-118），于是「当前格最优」= 永久待机，连「稍微往前挪一点」都不会做。
- `marchCautious` 只改变「什么时候开始评估威胁」：默认档始终评估，激进档在距离 ≤2 时才评估。所以激进档只是把均衡点从 5 格推到 3 格，并没有解除冻结。逐日轨迹：

```
默认档：第1天 移3 待3，距离 6→5；第2天起 移0 攻0，距离 5→5（直到第30天）
激进档：第1天 距离 6→3；第2天 距离 3→3；第3天起 移0 攻0（直到第30天）
```

这不是「谨慎」，是评分函数的一个**吸收态**：一旦落进去，任何单步动作都降低分数。

> 附注：`AI_PROFILE_PILOT` 是战斗界面「AI 托管」按钮实际使用的档位（`BattleScreen.tsx:480` → `planPilotAction`），不是纯测试对照组。也就是说，玩家点托管时同样会看到「推进到 3 格后停住」的冻结；审计里的「激进档」就是托管的手感基线。这次改造因此同时修好了托管。

## 3. 五项能力缺口

| 能力 | 现状 | 直接证据 | 目标行为 |
|---|---|---|---|
| **兵力部署** | 出生点固定，无兵种分层；近战/弓兵/玄兵混站，聚团吃火攻溅射（`tactics.ts:190-200` 火焰波及相邻） | `setup.ts:167-176` 按索引填格子，无阵型逻辑 | 前排近战、后排弓/玄；守方占城/林/山；单位间距 ≥1 防空袭溅射 |
| **主动出击** | 攻方不接战（100% 超时）；守方只在被贴脸后还手，不主动出击；不会在玩家露出破绽时压上；不抢粮仓（粮仓最多 +34、斩将最多 +19，打不过「可攻击 +120」） | 场景 A/C；`objectives.ts:326-332` | 攻方 3 天内接战；守方在玩家暴露后排/残兵时出击；粮仓被夺后最近单位反抢 |
| **预判局势** | 威胁只看当前站位；用「最大移动力 + 射程」的曼哈顿菱形，忽略地形、ZOC、阻挡；按全体敌军求和，不看我方能否先手击杀威胁源；无「下回合会不会被打死」判断 | `ai.ts:64-74` | 用真实可达格 + ZOC + 射程建威胁图；按「交换比」而非绝对伤害决策；识别「一回合能打残我方」的危险单位并优先处理 |
| **合理走位** | 评分只靠近「最近敌人」，不靠近目标（城池/主将/粮仓）；无夹击意识（相邻友军 +8/15/20%，`combat.ts:26-39`）；弓兵会贴脸；无撤退/风筝；无防溅射间距 | `ai.ts:98-111` | 弓兵保持 2–3 格；近战占目标相邻格触发夹击；残血后撤；不聚团 |
| **及时反应** | 单步重规划是优点（每个动作后重新评估），但触发面太窄：只有「已经能打」才响应；治疗只在无敌人可打时；主将濒危只有玩家托管有 handoff（`autopilot.ts:59-93`），敌方 AI 没有；粮仓被夺无反应；**从不花军令** | `ai.ts:208-227`；`grep useBattleCommand` 仅玩家侧 | 被集火日固守/治疗/后撤；主将濒危优先保命；粮仓被夺即反抢；进攻前鼓舞、追击时急袭 |

### 3.1 两个容易被忽略的放大器

1. **军令点完全闲置**：`setup.ts:227-230` 给玩家参战的战斗发 3 点军令，`useBattleCommand` 本身支持任意 `side`（`turn.ts:22-58`），但 `runSideTurn` 从不调用。敌方每场白扔 3 点（鼓舞 +20% 伤害 / 固守 −30% 承伤 / 急袭 +2 移动）。
2. **计策选择与收益脱钩**：`aiPickTactic` 按 `availableTactics` 的表顺序取第一个成功率 ≥55% 的敌方目标计策（`ai.ts:33-41`），顺序是 火 → 落石 → 水 → 混乱。于是：
   - 能一发普攻打死，却先放火攻；
   - 混乱（1–3 天无法行动）永远排在火攻之后，哪怕目标正是敌方主将；
   - 治疗只在「当前格打不到任何人」时才考虑，接战中永远不奶。

## 4. 期望达成的行为表现（可验收）

### 4.1 叙事标准

- **进攻方**：开战 1–2 天内成建制压上，近战在前、弓兵在后；不会在 5 格外列队等 30 天。遇到威胁圈时，选择「能换掉对方一个单位」的入口，而不是原地不动。
- **防守方**：不是死守城墙，而是用一格缓冲消耗；当玩家把弓兵或残兵暴露在 2–3 格内，骑兵/极兵会出来咬一口再退回城；玩家主将低于 30% 时全侧集火。
- **预判**：会抢占「下回合能打到、本回合打不到我」的位置；对「一回合能打残我方」的单位优先混乱/集火/拉开。
- **走位**：弓兵保持 2–3 格；近战站目标相邻格吃夹击；不聚团吃火攻；残血后撤而不是送。
- **反应**：玩家击杀 AI 一个单位后，同一回合内会重新分配目标并补位，而不是继续打原目标；粮仓被占后最近单位立刻反抢；主将濒危时固守/治疗/撤。
- **军令**：总攻前鼓舞；被 3 人以上围殴当日固守；抢粮/追击时急袭。每场至少花掉 2/3 点。
- **计策**：先算期望收益再放，不按表顺序；能击杀就不放控制；治疗在接战中也会用；混乱优先给最高威胁单位。
- **难度分层**：easy 允许犯错（随机目标、不放计策、不集火）；normal 会集火但不深算；hard 会预判、卡位、用军令。差距来自「决策质量」，不是资源倍率。

### 4.2 硬指标（改造后用 `npm run audit:ai` 回归）

| 编号 | 指标 | 改造前 | 目标 | 改造后 |
|---|---|---|---|---|
| B1 | 攻方首次接战天数（对静止守军） | 永不 | ≤ 3 天 | **2 天** ✅ |
| B2 | 攻方 30 天超时率 | 100% | ≤ 5% | **0%** ✅ |
| B3 | 接战后「零输出天数」 | 30 天/场 | ≤ 1 天/场 | **0** ✅ |
| B4 | AI 对 AI（默认档）平均战斗天数 | 30（双方都不打） | 8–14 天，且双方均有输出 | **8.45 天**，双方每天有输出 ✅ |
| B5 | 可击溃目标当回合击杀率 | 未统计（无侧级分配） | ≥ 80% | 单测覆盖：30 兵目标当回合击溃 ✅ |
| B6 | 军令点使用 | 0 / 3 | ≥ 2 / 3 | 攻 **2.3** / 守 **3.08** ✅ |
| B7 | 计策使用（智力达标单位） | 仅贴脸、按表顺序 | ≥ 1 次/场，且为最高期望收益 | 攻 **3.75** / 守 **11.32** 次 ✅ |

## 5. 改造方案：三个选项

> A、B 已实施；以下保留原始方案描述，便于对照落地情况。C 未做。

### 选项 A：最小闭环（已实施）

**只改 `ai.ts` 的评分与 threat 模型，约 120 行。**

1. `estimateThreat` 改为真实可达：用 `reachableTiles` 的 BFS 距离 + 攻击射程，而不是曼哈顿菱形；伤害按目标剩余兵力截断，最多计 3 个敌人（同一格同时被 5 人打是极端情况）。
2. 评分从「绝对扣分」改成「交换比」：`预期造成伤害 − 预期承受伤害 × 风险系数`。能先手击溃威胁源时，风险系数下调。
3. 加「推进意图」项：到目标（城池 / 主将 / 粮仓）的距离，攻方权重显著高于「最近敌人」。
4. 删除「当前格最优就返回 null」的硬停：不能攻击且未达目标时，强制选择一个「缩短目标距离」的次优落点；只有完全无路可走才待机。
5. 加可接受风险阈值：预计承伤 < 当前兵力 35%（或能先手击杀威胁源）时允许进圈。

**验收**：B1 ≤ 3 天、B2 ≤ 5%、B3 ≤ 1 天。风险低，不动伤害公式与平衡表。

### 选项 B：战术协同（已实施）

**A + 新增 `src/systems/battle/focus.ts`，改 `ai.ts` 的目标与计策选择，约 300 行。**

1. **侧级集火**：每回合先扫「可击溃清单」，按 可击溃 > 主将/斩将目标 > 高威胁 > 残血 分配攻击者，按击杀所需配人，避免伤害摊薄；击杀后剩余单位改打次优目标。
2. **角色化走位**：弓兵维持 2–3 格射界；近战占目标相邻格触发夹击；骑兵/极兵绕侧；玄兵后排；用 `flankMultiplier` 反推「站哪里能吃到 +8/15/20%」。
3. **计策期望值**：`命中率 × 收益 − 机会成本`，伤害/控制/治疗同台比较；混乱优先给「下回合能击溃我方」的敌人；治疗在接战中可用。
4. **军令自动化**：敌方 AI 也用 `useBattleCommand`——总攻前鼓舞、被围殴日固守、抢粮/追击急袭；每场至少 2 点，留 1 点机动。
5. **极兵突击**：只在「能击溃」或「目标为主将/高威胁」时使用，不再见面就交。

**验收**：B1–B9 全绿；AI 对 AI 平均战斗 8–14 天；三档难度胜率曲线不塌。中等风险，需要重跑 `sim:battle` 观察攻方胜率。

### 选项 C：完整行为系统（未做）

**B + 新增 `threat.ts` / `deployment.ts` + 难度旋钮 + 决策日志，约 500 行。**

1. **威胁热图**：每回合为 96 格计算「下回合可能承伤」（真实可达 + ZOC + 射程 + 已行动折减），走位、撤退、固守共用一张图。
2. **开战部署**：按兵种分层出生（前排近战、后排弓/玄），守方优先城/林/山；单位间距 ≥1 防火焰溅射。
3. **反应预案**：主将濒危、粮仓被夺、单位被集火、敌方后排暴露，各自触发对应规则（保命/反抢/固守/突袭）。
4. **难度旋钮**：`riskTolerance` / `focusDiscipline` / `predictionDepth` / `commandUsage` 写进 `difficulty.ts`，替代现在的 `tacticAi` + `focusCommander` 两个布尔。
5. **决策日志**：debug 开关下记录「为什么选这个格/这个目标」，便于调参与回归。

**验收**：全套指标 + 三档难度对照。风险中高：AI 变强会抬高攻方胜率，可能需要回调 `DEFENDER_REGEN_RATE` / 城防系数；必须重跑 `sim:battle` 并做难度校准。

### 5.1 不建议顺手做的事

- **改回合顺序**（让攻方先手）：能立刻改善「永远后手」，但会同时改变所有战斗的胜率与平衡，应作为独立议题，不和 AI 改造混在一个提交里。
- **直接调高 `AI.attackRatio` 或资源倍率**：那是让 AI「更敢出兵」，不是让战棋 AI「会打」，会掩盖问题而不是解决。

- 有可击溃目标时，同侧不再攻击其它目标（集火溢出）；
- 两个单位不会对 10 兵目标各打一次；
- 智力达标且能击杀时，选普攻/伤害计策而非混乱；
- 一场战斗敌方军令消耗 ≥ 2；
- 同种子重放，动作序列完全一致（确定性）。

### 7.2 关键行为变化

- **威胁模型**：改用 `reachableTiles` 的 BFS 可达 + 射程 + ZOC，逐个敌人叠加并按当前兵力截断；不再用「最大移动力 + 射程」的曼哈顿菱形。
- **评分**：统一以伤害为单位，`攻击收益 − 承伤 × 风险`；攻方接战前风险 ×0.55，且只允许「不增加目标距离」的落点，彻底移除「圈外站桩」的吸收态。
- **集火**：侧级焦点目标按 可击杀 > 主将/斩将 > 高威胁 > 残血 排序，焦点目标 +70；击杀后剩余单位自动改打次优目标。
- **走位**：弓兵保持 2–3 格；近战贴目标相邻格；夹击铺垫 +20 + 8/helper；残血更保守。
- **计策**：`命中率 × 效果 − 机会成本`；击杀不再重复加主将分；能普攻击杀时不放控制。
- **军令**：每天最多 1 条、至少留 1 点；打不过固守、打得过鼓舞、够不着急袭；双方独立记账。
- **突击**：普攻能解决就省下，留给「突击能杀 / 主将 / 弓玄」。

### 7.3 回归结果与风险

- `npm run typecheck` 通过。
- `npm test`：34 个测试文件、302 条；5 条既有失败（`i4.spec` 大势已定、`modern.spec` 章节/存档迁移），与本次改动无关，`src` 改动前即失败。
- `npm run audit:ai`：B1–B8 达标，B9 守方达标、攻方受攻城地形限制，B10 未做。
- **平衡影响**：镜像 AI 的攻方胜率从旧「激进档」15% 升到 53%，平均战斗 10.9 → 8.45 天。AI 变强是预期结果，但攻方胜率已接近五五开；建议下一轮用 `npm run sim:battle` 重跑数值沙盒，确认 1.8:1 攻城胜率仍在目标区间。
