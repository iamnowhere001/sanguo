# 三国霸业

一款以《三国演义》为背景的回合制策略 Web 游戏：576×360 全地图、3×3 城郭与四门、47 处关隘 / 港口 / 小路、部队逐格调度、武将五维养成、一队三将编制、外交策反，以及直接在大地图上展开的回合制战斗。

当前处于**可玩垂直切片**阶段：开局 → 经营 → 出征 → 大地图列阵 → 占城 → 月报 → 存档全链路已打通；测试规模与门禁状态见 [项目基线 v1](docs/项目基线-v1.md) §5（数字只在那里维护）。

## 设计主线

依据 [GDD 优化规划报告](sanguo-gdd-optimization/sanguo-gdd-optimization.html)（基线 GDD rev.5），本作按三条主线推进：

| 主线 | 目标 |
| --- | --- |
| A · 数值：切断套利，重建取舍 | 农业管“数量”、商业管“质量”；任何单一加点路线不超过最优产能的 120% |
| B · 信息：行动前可预览，结算后可归因 | 月报、上限预警、伤害区间、计策成功率全部前置；月度操作点击 ≤ 40（v2 目标 ≤ 20） |
| C · 工程：确定性优先，内容后置 | 命令 → 纯函数 → 新状态；随机数按系统分流；读档 100% 复现 |

优化建议按三层落地：**A 澄清**（补全规则表，必须做）、**B 校准**（只改参数，建议做）、**C 可选**（新机制，默认关闭）。

## 技术栈

- **React 19** + **TypeScript 7**（严格模式，原生编译器）
- **Vite 8**（Rolldown 内核）开发与构建
- **Vitest 5** 单元测试
- **Canvas 2D** 绘制大地图与战场
- **势力版图场**：多源 Dijkstra 按真实行军代价扩张，低分辨率铺色 + 模糊成墨迹边界
- **Web Audio API** 程序化音效与生成式 BGM（无音频素材）
- **IndexedDB** 存档，**zod** 配表校验

## 快速开始

需要 **Node.js 22.12+ 或 24+**（Vitest 5 与 Vite 8 的最低要求，见 `package.json` 的 `engines`）。

```bash
npm install
npm run dev
```

浏览器打开终端提示的本地地址即可。

大地图配置台是独立入口：访问 `http://localhost:5173/map-studio.html`，数据结构与操作见 [大地图数值配置 v1](docs/大地图数值配置-v1.md)。改完可用 `npm run map:apply` 把点位与数值回写进 `src/data/tables/`。

## 目录结构

```
src/
├── core/            # 状态模型、reducer、随机数、公共 selector/result
├── data/
│   ├── schema.ts    # zod 配表校验
│   └── tables/      # 数值、城池、武将、道具、计策、兵种、剧本
```

## 架构约定

1. **唯一状态入口**：所有玩家操作都经过 `core/reducer.ts` 的 `reduce()`。
2. **draft 模式**：`reduce()` 先 `structuredClone`，各 system 直接修改草稿；成功才替换原状态，失败保持原引用。
3. **数值真值源**：平衡数值集中在 `src/data/tables/balance.ts`。改数值优先只改这里，不要把常量散落回系统层。
4. **战棋模块边界**：
   - `grid` 只负责坐标、地形、移动/攻击范围；
   - `combat` 负责伤害与普攻/突击；
   - `tactics` 负责计策；
   - `ai` 只做决策并调用上面三者；
   - `resolve` 负责战后结算与游戏结束判定。
5. **存档兼容**：新增字段时，在 `src/save/migrate.ts` 补默认值，并增加迁移测试。

## 数值与配表

- 所有数值标注来源：`【GDD】` 原文明确、`【优化】` 优化报告校准值、`【推导】` 由前两者推出。
- 调整顺序固定为：`balance.ts` 常量 → `formulas.ts` / `battle/damage.ts` 纯函数 → 单测断言 → 接 UI。
- 配表由 zod 校验 id 唯一、引用存在、数值范围与枚举合法。

## 存档

- 自动存档槽位：`auto`
- 手动存档：多个槽位，存于浏览器 IndexedDB
- 存档版本号为 `SAVE_VERSION`（`src/save/db.ts`，当前 6）；旧版本按 `migrations` 链升级，缺失迁移会明确报错；v6 起升级会清空旧存档库。
- 大地图版本号为 `MAP_VERSION`（`src/data/tables/geography.ts`，当前 4）：v1 = 96×72、v2 = 192×144、v3 = 576×432、v4 = 576×360（南缘裁剪，比例尺不变）。
- 存档记录 `runSeed`、回合、各随机流游标与 `presets`；战棋中存档会保留 `battle` 状态与战斗随机流，读档后直接续战。
- 新增武将属于配表内容扩充，只对**新开局**生效；旧存档沿用存档内的人物表，不会自动补入新武将。

## 已知限制

- **`npm run verify` 现在能跑通**（2026-10-31 复核）：`map:gates` 退出 0，只剩 4 处关隘的绕行距离未达 tier 阈值——剑阁 Δ36 < 70、葭萌关 Δ0 < 45、瓦口关 Δ0 < 30、阴平道 Δ0 < 30。这是**地形内容债**（封锁后仍能近路绕过），不是工程回归；逐座判据见 [关隘有效性体检 v1](docs/关隘有效性体检-v1.md)，处置选项见 [项目基线 v1](docs/项目基线-v1.md) §4。
- 陆路连通性基线在 2026-10-30 修正了水面判定（旧版把 `cells[]` 的数字下标当 `TileKind` 字符串喂给 `isWaterKind`，永远为假）：**10 个连通分量、主分量 173,999 格、58 城在主分量、武都孤岛**；此前文档里「59 城一个连通分量」的结论不可信。
